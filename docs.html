Introduction. #

Cyber is a safe, fast, and concurrent programming language.

The areas of focus for the language include:

  • Static typing with primitives, references, structs, options, enums, choices, traits, and generic types.
  • Memory safety. Favors structured and flat memory use through borrowing and reference counting. (No garbage collector.)
  • Value ownership and deinitializers.
  • Metaprogramming with templates, inline evaluation, and compiler hooks.
  • Concurrency. Threads that run in parallel, futures and await to wait for them, fibers and scope blocks for structured concurrency, and generators.
  • Interpreted by a bytecode virtual machine. A CLI runs scripts, and libcyber embeds the VM in a host application.
  • Embedding controls that let a host restrict a script: raw pointers, the modules it can load, its memory, its stack and its run time.
  • Introspection. Much of the internals such as the builtin types and runtime is written in Cyber and can be inspected from the source code or the API docs.

These docs provide a reference manual for the language. It can be read in order or browsed from the navigation. Features that are marked Planned have not been completed at the time of writing.

Statements. #

A statement ends with the new line character:

a := 123

Any token inside delimited parentheses, brackets, or braces, can be wrapped to the next line:

sum := add(1, 2, 3, 4,
    100, 200, 300, 400)

colors := {'red', 'blue', 'green',
    'purple', 'orange', 'yellow'}

A statement can wrap to the next line if the last token before the new line is an operator or keyword.

gameover := health <= 0 or
    player.collides_with(spikes)

if year > 2020 and year <= 2030 and
    month > 0 and month <= 11:
    print('Valid')

Comments. #

A single line comment starts with two hyphens and ends at the end of the line.

-- This is a comment.

a := 123   -- This is a comment on the same line as a statement.

# does not start a comment. A # followed by a space or the end of the line is a parse error that says to use --.

^topic

Blocks. #

Some statements can start a new block with a colon. The first statement in a new block must be indented further. Indentation can be spaces or tabs but not both.

-- This `if` statement begins a new block.
if true:
    a := 234

Subsequent statements in the block must follow the same indentation. The block ends when a statement recedes from this indentation:

items := {10, 20, 30}
for items |it|:
    if it == 20:
        print(it)

    -- This is the first statement outside of the `if` block.
    print(it)

A block with a single statement can be written in a single line:

-- A single line block.
if true: print(123)

if true: print(123)
    -- Indentation error. The `if` block already ended.
    print(234)

Since blocks require at least one statement, pass can be used as a placeholder statement:

fn foo():
    pass

Local variables. #

:= declares a variable with the type inferred from the initializer.

a := 123

Variables can be assigned afterwards using the = operator:

a = 234

Several variables are declared or assigned at once with commas. Every value on the right is evaluated, from left to right, before the first one is stored, so a swap needs no temporary:

a, b := 0, 1
for 0..10:
    a, b = b, a + b
print(a)     --> 55

x, y := 'left', 'right'
x, y = y, x
pt.x, pt.y = pt.y, pt.x
xs[0], xs[1] = xs[1], xs[0]

Each side has the same number of items: '2 places take 2 values, found 3.' The places of = are variables, fields and elements, the names of := are new variables. A value that can not be copied (NoCopy, such as Array) moves, as in a single assignment. A literal takes the type of its place (i, j = 0, 1 for i32 variables). Compound assignments (+=) take one variable. A function returns one value, so q, r := divmod(7, 2) is an error: the right side has one value.

A function body, including the main block, can hold at most 256 locals. Parameters and the hidden temporaries the compiler creates count towards that limit. A function signature can have at most 255 parameters and a struct at most 255 fields. A single branch (the body of a loop, an if or a switch case) can span at most 32767 bytecode slots, roughly 8000 simple statements; a plain if body without else can span 65535. Exceeding a limit is a compile error. Move part of a long body into another function.

var declaration. #

When a local variable is declared with var, a type specifier is required. The initializer must satisfy the type constraint:

-- Correct.
var a float = 123.0

-- CompileError. Expected `float`, got `str`.
var b float = 'hello'

Sometimes, the var declaration can be simpler and more readable than an equivalent := declaration:

var action ?str = switch color:
    case .green => 'go'
    case .red => 'stop'
    else => none

Variable scopes. #

Local variables exist until the end of their scope. Each block has their own variable scope.

Variables declared in the current scope will take precedence over any parent variables with the same name. This is also known as variable shadowing:

fn foo():
    a := 234

    if true:
        -- New `a` declared.
        a := 345

        print(a) 
        --> 345

    print(a)
    --> 234
^topic

global variables. #

Global variables live until the end of the program and can be accessed from any context (unless they have a private modifier). Globals are considered unsafe.

Global variables are declared with global and require a type specifier:

global a int = 123

fn foo():
    print(a)    --> 123

A global can not have a borrow type (&T, ?&T, a borrow container such as OpaqueFunc[F]), since it would outlive the local it borrows. Use an owned type such as ^T.

The initializer of a global variable can use the global variables that are initialized before it:

global a int = 123

global b int = a + 1

Using a global that is initialized later, or the global itself, is a compile error:

global b int = a + 1
--> error: The initializer of `b` accesses the global `a`. `a` is initialized after `b`.

global a int = 123

Global variables are initialized before the main block runs, in a fixed order. The globals of a module are initialized in the order that they are declared. The following would invoke load_a before load_b:

global a int = load_a()
global b int = load_b()

A module is initialized after the modules that it imports with use, so a function of an imported module sees the globals of its module initialized. At the end of the program, modules are deinitialized in the reverse order.

The same rule holds for the functions that an initializer calls. They can read and write the globals that are initialized before it. Reaching a global that is initialized later, or the global that is being initialized, is a compile error:

global a int = load_a()
--> error: The initializer of `a` can reach `load_a`, which accesses the global `b`. `b` is initialized after `a`.
global b int = 123

fn load_a() -> int:
    return b + 1

Declare b before a to fix the error.

The check follows the functions that are called by name, including operators, @init and @deinit. It does not know the target of a call through a function value or a trait. When an initializer can reach such a call, every function that is used as a value (a lambda, a function assigned to a variable or passed as an argument, a generator) and every method that implements a trait counts as reachable. The check does not look at conditions either, so an access that never runs at initialization is still an error.

Circular references between initializers are not possible. One of the two globals is initialized first, and its initializer can not use the other:

global a int = b
--> error: The initializer of `a` accesses the global `b`. `b` is initialized after `a`.

global b int = a

An #[extern] global can not be used in a global initializer.

Arithmetic operators. #

The following arithmetic operators are supported for numeric data types. Some types such as math.Vec and math.Mat also overload these operators.

1 + 2     --> 3   (Addition)
100 - 10  --> 90  (Subtraction)
3 * 4     --> 12  (Multiplication)
20 / 5    --> 4   (Division)
2 ** 4    --> 16  (Power)
12 % 5    --> 2   (Modulus remainder)
-(10)     --> -10 (Negative)

An integer and a float can be mixed. The integer converts to the type of the float, whichever side it is on, and the result is a float. An f32 with a float gives a float the same way:

i := 7
f := 2.5
print(i * f)      --> 17.5
print(f * i)      --> 17.5
print(i + 0.5)    --> 7.5
print(i / 2)      --> 3    (Both are integers: integer division.)
print(i / 2.0)    --> 3.5

The result does not convert back to an integer. i += f and var n int = i * f report 'Expected type int, got float.' Write int(i * f). The bitwise operators take integers only, so i && f is an error. An operand that is not a number is an error on either side: f + 'abc' reports 'Expected float, found str.'

Comparison operators. #

The following comparison operators are supported and evaluate to a Boolean value.

The == equals operator returns true if the two values are equal. Primitive values compare with their underlying bytes. The comparison recurses for composite types. For the str type, the underlying bytes are compared for equality. For references types, the comparison checks that the two references point to the same value.

1 == 1          --> true
1 == 2          --> false
1 == true       --> false

a := 'abc'
a == 'abc'      --> true

la := []int{1, 2, 3}
lb := la
la == lb             --> true
la == []int{1, 2, 3} --> false

The not equals operator returns true if the two values are not equal.

1 != 1          --> false
1 != 2          --> true

Number types have additional comparison operators.

a > b           --> `true` if a is greater than b
a >= b          --> `true` if a is greater than or equal to b
a < b           --> `true` if a is less than b
a <= b          --> `true` if a is less than or equal to b

A comparison converts its operands like an arithmetic operator does. An integer converts to the type of a float on the other side, and an integer of a narrower type converts to the wider one. A signed integer on the left does not convert to a raw integer on the right, since that would read a negative value as a large one: i8 < r64 is a type error. symbol and error values are not numbers and do not convert:

i := 7
print(i < 7.5)    --> true
print(i == 7.0)   --> true
print(7.0 == i)   --> true
^topic

Logic operators. #

The logical operators and, or, and not are supported.

The unary operators not and ! perform negation on the boolean value:

not false     --> true
not true      --> false
!false        --> true
!true         --> false

not binds weaker than a comparison and tighter than and and or, as in Python. ! binds as tightly as the other prefix operators:

not a == b      -- not (a == b)
not a and b     -- (not a) and b
!a == b         -- (!a) == b
^topic

Bitwise operators. #

The following bitwise operators are supported for Int and Raw number values.

-- and: any underlying bits that are set in both integers are set in the new integer.
a && b

-- or: any underlying bits that are set in either integer a or integer b are set in the new integer.
a || b

-- exclusive or: any underlying bits that are set in either integer a or integer b but not both are set in the new integer.
a ~ b

-- logical right shift: a's bits are shifted b bits to the least significant end. 
a >> b

-- arithmetic right shift: like `>>` but the sign bit fills the vacated bits. `(-8).asr(1)` is `-4`, `-8 >> 1` is a large positive integer.
-- A shift amount past the sign bit leaves only the sign: `-1` for a negative integer, otherwise `0`.
a.asr(b)

-- logical left shift: a's bits are shifted b bits to the most significant end. This does not perform sign-extension on the 32-bit integer.
a << b

-- not: a's integer bits are flipped.
~a

When the place of a ~ expression expects a wider integer type, the operand is converted to that type before its bits are flipped: var z r32 = ~r16(5) is 0xfffffffa. Assign the result to a variable first to flip the bits in the width of the operand: n := ~r16(5) is 0xfffa. A float target converts the result: float(~5) is -6.0.

Integers. #

int (an alias for i64) is the default integer type. It's encoded as 64-bit two's complement and represents integers in the range -(263) to 263-1.

Integer types are named according to how many bits they occupy: i8, i16, i32, i64

Raw integer types do not encode a sign bit. They include: r8 (byte, r16, r32, r64. byte is an alias for r8.

While integer types are typically used for counting, raw integer types are intended to represent masks and raw memory.

Without a target type, a numeric literal will default to the int type:

a := 123

Other integer notations include:

a := 0xFF     -- Hexidecimal.
a = 0o17      -- Octal.
a = 0b1010    -- Binary.

An underscore can separate digits to make a long literal easier to read. It is optional and does not change the value. It must have a digit on both sides:

const PARAM_CAP r32 = 100_000
mask := 0xff_ff_00_00
bits := 0b1111_0000
ratio := 1_000.000_5

A decimal literal must fit in the target integer type. Without a target type that is int (64-bit signed), so 9223372036854775808 is a compile error instead of wrapping around. Hexadecimal, octal and binary literals, and decimals with a u suffix, are 64-bit patterns:

a := 0xFFFFFFFFFFFFFFFF      -- -1
a = 18446744073709551615u    -- -1
var b r64 = 18446744073709551615

When the target is a float or f32, a hexadecimal, octal or binary literal converts by its unsigned 64-bit value: var f float = 0x10 is 16.0 and var g float = 0xFFFFFFFFFFFFFFFF is 18446744073709551615.0. Without a float target the literal is an int first, so float(0xFFFFFFFFFFFFFFFF) is -1.0.

A raw integer converts to a float by its unsigned value at every width, and a float converts to a raw integer the same way. The fraction is dropped. A negative value, a NaN or a value that does not fit the raw type panics:

var mask r64 = 0xFFFFFFFFFFFFFFFF
print(float(mask))                -- 18446744073709552000.0
print(r64(9223372036854775808.0)) -- 0x8000000000000000
print(byte(255.9))                -- 0xff
f := -1.0
print(r64(f))                     --> panic: Lossy conversion to `r64`.

String literals evaluate as their UTF-8 codepoint if the target integer type is big enough:

-- Success.
var a int = '🐶'

-- error: Expected `byte`, found `str`.
var b byte = '🐶'

-- Success.
var b byte = 'a'

Strings and other values can be converted to a int using the type as a function:

a := '123'
b := int(a)

int(s) gives 0 for a string that is not a number. To check the string, use int.parse, which returns !int and gives error.InvalidCharacter or error.Overflow:

n := int.parse('42') !else 0

Integer types can perform arithmetic, bitwise, and comparison operations.

Integer overflow. #

+, -, *, **, unary - and / of a signed integer (int, i32, i16, i8) panic with 'Integer overflow.' when the result does not fit in its type. A wrong value never passes on silently. int.min / -1 overflows too, and x % -1 is always 0. A constant expression that overflows is a compile error with the same message:

n := int.max
print(n + 1)           --> panic: Integer overflow.
print(i8(100) + i8(28)) --> panic: Integer overflow.
const k = int.max + 1  -- error: Integer overflow.

When a result may not fit, ask for it with checked_add, checked_sub and checked_mul, which return none instead. Where wrapping is the intent, as in a hash, a checksum or a random number generator, write wrapping_add, wrapping_sub and wrapping_mul:

-- The nth Fibonacci number, or `none` when it does not fit in an `int` (from `fib(93)` on).
fn fib(n int) -> ?int:
    a, b := 1, 0
    for 0..n:
        a, b = b, a.checked_add(b) ?else return none
    return b

print(int.max.wrapping_add(1) == int.min)  --> true

The raw integer types (byte, r16, r32, r64) hold bits for masks and memory: their arithmetic wraps at their width. Shifts and bitwise operators never overflow.

^topic

Floats. #

float (an alias for f64) is the default floating point type. It's encoded as 64-bit IEEE 754.

Floating point types include: f32, f64

A float can represent integers between -(253-1) and (253-1). However, integers outside this range are not guaranteed to have a unique representation.

Decimal and scientific notations always produce a float value:

a := 2.34567
b := 123.0e4

An integer literal can evaluate to a target float type:

var a float = 123

Strings and other values can be converted to a float using the type as a function:

a := '12.3'
b := float(a)

float(s) also gives 0 for a string that is not a number. float.parse (and f32.parse) returns !float and gives error.InvalidCharacter instead. It reads '1.5', '-2', '1e3', 'inf' and 'nan', and does not allow spaces around the number:

x := float.parse('1.5') !else 0.0

A float always converts to text that reads back as a float. print, str(x), string interpolation and x.fmt() use the shortest digits that give the same value, in plain decimals without an exponent. A finite value without a fraction gets .0, so the output tells a float from an int. Infinity and NaN print as inf, -inf and nan. f32 follows the same rule:

print(3.0)              --> 3.0
print(1.5)              --> 1.5
print(-0.0)             --> -0.0
print(1e21)             --> 1000000000000000000000.0
print(1e-7)             --> 0.0000001
print(1.0 / 0)          --> inf
print('%{float(7)}')    --> 7.0
print([]float{3, 5.5})  --> {3.0, 5.5}
print(3)                --> 3

json.stringify and toon.encode follow their own formats and write 3.0 as 3.

Float types can perform arithmetic and comparison operations.

^topic

Strings. #

The str type represents a sequence of UTF-8 code points. Each code point is stored internally as 1-4 bytes.

Strings are not validated by default. When indexing for code points, an invalid codepoint will be returned as the replacement character (0xFFFD).

Strings are immutable, so an operation on a string returns a new string.

Some string operations are SIMD accelerated.

^topic

Raw string literal. #

A raw string doesn't allow any escape sequences or string interpolation.

Backticks are used to delimit a single line literal:

fruit := `apple`
s := `abc🦊xyz🐶`

Since raw strings interprets the sequence of characters as is, the backtick character can not be escaped:

-- ParseError.
s := `abc`xyz`

Triple backticks are used to delimit a multi-line literal. It also allows single backticks:

s := ```abc`xyz```
greet := ```Hello
World```
^topic

String literal. #

A string literal allows escape sequences and string interpolation.

Single or double quotes are used to delimit a single line literal:

fruit := 'apple'
fruit = 'Miso\'s apple'
fruit = "Miso's apple"
sentence := '%{fruit} is tasty.'

Triple single or double quotes are used to delimit a multi-line literal:

title := 'last'
doc := '''A single quote ' doesn't need to be escaped.'''
s := """line a
line "b"
line %{title}
"""

A single line literal can not contain a line break. Write \n for one, or use a multi-line literal.

A string literal can hold at most 65535 bytes. Each literal piece of an interpolated string counts on its own. A longer literal is a compile error; split the text into several literals and join them at runtime.

Strings from bytes. #

str(bytes) copies a []byte or PtrSpan[byte] into a string without checking the encoding. str.from_utf8(bytes) checks that the bytes are valid UTF-8 and returns error.Unicode otherwise, so it is the one to use for bytes that come from outside the program:

data := os.read_file_bytes('notes.txt')!
text := str.from_utf8(data) !else ''
if str.is_utf8(data.span()):
    print('valid')
^topic

String indexing. #

The index operator returns the byte from a given index:

a := 'abcxyz'
print(a[1])         --> 0x62
print(a[1] == 'b')  --> true

Since indexing operates at the byte level, it should not be relied upon for iterating runes or rune indexing. However, if the string is known to only contain ASCII runes (each rune occupies one byte), indexing will return the expected rune.

str.rune_at returns the rune from a given byte index:

a := '🐶abcxyz'
print(a.rune_at(0)) --> 0x1f436

If the index does not begin a sequence of valid UTF-8 bytes, the replacement character (0xFFFD, 65533) is returned:

a := '🐶abcxyz'
print(a.rune_at(1)) --> 0xfffd

str.seek will return the n'th rune:

a := '🐶abcxyz'
print(a.seek(2))    --> 0x62 ('b')

Slicing also operates on byte indexes and returns a view of the string at the given start and end (exclusive) indexes:

a := 'abcxyz'
b := a[0..3]
print(a[0..3])  --> abc
print(a[..3])   --> abc
print(a[1..])   --> bcxyz

Lines and padding. #

lines splits a string at \n and \r\n and drops the line breaks. A line break at the end does not start another line, and an empty string has no lines:

'a\r\nb\n\nc\n'.lines()   --> {'a', 'b', '', 'c'}
''.lines().len()          --> 0

pad_left and pad_right add spaces, or a given one-rune fill, until the string has width runes. A longer string is returned as it is:

'ab'.pad_left(4)         --> '  ab'
'7'.pad_left(3, '0')     --> '007'
'ab'.pad_right(4, '.')   --> 'ab..'

A fill that is not one rune panics with 'Invalid argument.'. Width counts runes, not display columns: a wide character such as 한 counts as one.

^topic

String interpolation. #

String templates wrap expressions in %{} which converts them to strings using the builtin to_print_string:

name := 'Rex'
points := 123
title := 'Scoreboard: %{name} %{points}'

String templates can not contain nested string templates: '%{'L%{n}'.len()}' is an error. Assign the inner template to a variable first. The expression inside %{} is code, so it can not contain a backslash escape such as \": write a string there with the other quote, "%{f('b')}".

to_print_string renders a struct as a record literal with its type name, a choice as its case with the payload, and a slice or vector as its elements. A string nested in one of those keeps its quotes:

type Point:
    x int
    y int
type Shape enum:
    case circle int
    case empty
print(Point{x=1, y=2})              --> Point{x=1, y=2}
print(Shape.circle(5))              --> Shape.circle(5)
print(Shape.empty)                  --> Shape.empty
print([]str{'a', 'b'})              --> {'a', 'b'}
print('%{[]Point{Point{x=1, y=2}}}') --> {Point{x=1, y=2}}

A reference prints its type name (^Point) and a Ptr prints its address.

Map and Array can not be passed by value, so pass a borrow. A borrowed Map renders its entries, a borrowed Array or ArrayStore its elements, and any other borrow the value it borrows:

m := Map[str, int]{a=1}
a := Array[int]{1, 2}
print(&m)                           --> {'a': 1}
print(&a)                           --> {1, 2}
print('%{&Point{x=1, y=2}}')        --> Point{x=1, y=2}

dump and dump_str render the same values over several lines for inspection. Each struct field or sequence element takes its own line, slices and vectors carry their type name, and scalars render like print:

dump([]Point{Point{x=1, y=2}})
--> []Point{
-->   Point{
-->     x: 1
-->     y: 2
-->   }
--> }
dump(&m)
--> Map[str, int]{
-->   'a': 1
--> }

String formatting. #

Formatting replaces {} placeholders with values converted to strings:

print('First: {}, Last: {}'.fmt({'John', 'Doe'}))

Alternatively, a custom placeholder can be specified:

print('if (%PH) {\n\t%PH}'.fmt('%PH', {cond, body}))

Values that can be formatted into a string typically have a fmt method:

x := 123
print(x.fmt(.hex))  --> 7b

Symbols. #

A symbol literal is written symbol. followed by an identifier, like an error value is written error.Name. Each symbol has a global unique ID.

currency := symbol.usd
print(currency == symbol.usd)   --> true
print(currency)                 --> symbol.usd
print(currency.name())          --> usd
print(int(currency))            -->

A symbol does not need a declaration. The same name is the same value everywhere in the program.

Earlier versions wrote a symbol literal as @usd. That is a compile error that names the replacement: 'Undeclared @usd. A symbol literal is written symbol.usd.'

^topic

References. #

A reference type is denoted as ^T where T is the type of the value that the reference points to. References are safe to use because the memory that they point to are automatically managed.

Separating values and references provides more control over how data is laid out in memory. For example, some types may benefit from compacted members to leverage cache locality and reduce object indirection.

The lift operator ^ lifts a value onto the heap and returns a reference to the new value:

i := 123
ref := ^i

The .* operator dereferences a ^T and returns the value that it points to:

print(ref.*)      --> 123

If a value was intended to be initialized on the heap, it's usually constructed with the lift operator ^. This avoids a copy of the underlying value:

pos := ^Vec2{x=4, y=5}
^topic

Optionals. #

An Option is a value type that provides null safety by forcing the inner value to be unwrapped before it can be used.

Option types either hold a none value or wraps some value.

A type prefixed with ? is the idiomatic way to declare an option type. The following str optional types are equivalent:

Option[str]
?str
^topic

Wrap value. #

A value is automatically wrapped into the inferred optional's some case:

var a ?str = 'abc'
print(a)    --> abc

An optional borrow ?&T is a borrow container: like &T it can not be lifted with ^, it is returned with a scope parameter and a scope return type, and a generator can not take it as a parameter. A result !&T is the same.

The option type's constructor can also wrap a value:

a := ?str('abc')
print(a)    --> abc

The type after ? ends before the call or the initializer, also when it is a result type: ?!int(int.parse(s)) calls ?!int, and []?int{1, none} and []!int{int.parse(s)} are slices. The argument is wrapped one level only: ?!int(1) is a compile error, since an int is not a !int. At the start of an expression ! is logic not, so !int(x) is not int(x).

^topic

Wrap none. #

none is automatically initialized to the inferred optional's none case:

var a ?str = none
print(a)    --> none

The option type's constructor can also wrap none:

a := ?str(none)
print(a)    --> none

Unwrap or panic. #

The .? operator unwraps an optional. The current thread panics if the expression evaluates to the none case at runtime:

var opt ?int = 123

-- Success.
v := opt.?

opt = none

-- panic: Option is empty.
v = opt.?

Unwrap or default. #

The ?else operator either returns the unwrapped value or a default value when the optional is none:

var opt ?int = none
var v = opt ?else 123
print(v)     --> 123

An ?else block executes a block of statements for the none case:

value := opt ?else:
    return error.Missing

A block of one return, break or continue can follow on the same line without ::

value := opt ?else return none
for items |item|:
    size := item.size ?else continue

if unwrap. #

The if statement can be amended to unwrap an optional value with the capture |_| clause:

var opt ?str = 'abc'
if opt |value|:
    print(value)    --> abc

When the payload is a NoCopy type, the capture takes it out of the option. An option that is read from a variable is moved then, so the variable can not be used after the statement (if make() |v|: and while it.next() |v|: take the payload of a new value; while o |v|: with a variable o from outside the loop is an error, see moving). An option in a member (if s.opt |v|:) is not moved: 'Cannot copy ?Foo, type member implements NoCopy.'

The capture unwraps the whole condition. An operand of and or or is a bool, so if ok and s.index('=') |i|: is a compile error. Put the unwrap in an if of its own:

if ok:
    if s.index('=') |i|:
        print(i)

Vectors. #

A vector type is a static data structure that holds contiguous elements of the same type. It's denoted as [N]T where N is the size of the vector and T is the element type.

Vectors are constructed with the initializer expression:

a := [3]int{1, 2, 3}

The number of elements can be inferred with the generic type [_]T:

a := [_]int{1, 2, 3}

An initializer literal can infer the target vector type:

var a [3]int = {1, 2, 3}

Vectors can be indexed:

a[2] = 300
print(a[2])    --> 300
^topic

Partial vectors. #

Sometimes a vector prefers to be incrementally initialized where the uninitialized elements are unowned. The partial vector type denoted as [..N]T keeps track of how many elements in the vector are initialized at runtime so that it can be properly deinitialized:

elems := [..4]Stateful{}
print(elems.len())   --> 0

-- No `Stateful` element is deinitialized.

Elements must be incrementally appended to the PartialVector. Indexing an element that hasn't been initialized results in a thread panic:

elems << Stateful()
elems << Stateful()

elems[3] = Stateful()
--> panic: Out of bounds.
^topic

Slices. #

A Slice type is a dynamic data structure that holds contiguous elements of the same type. It's denoted as []T where T is the element type. Slices grow or shrink when inserting or removing elements.

Slices are constructed with the initializer expression:

arr := []int{1, 2, 3}

The intializer literal can infer the target slice type:

var a []int = {1, 2, 3}

Without a target type, a list literal is a []T where T is the type of the first element. The other elements are not converted to it: {1, 'a'} and {1.5, 2} are compile errors, write []int{1, 'a'} or []float{1.5, 2}. An empty {} needs a target type:

names := {'a.py', 'b.py'}    -- []str
for {1, 2, 3} |n|:
    print(n)

A list literal uses braces. ['a', 'b'] is not a list literal: [n]T is a vector type.

A slice copies its elements (two copies of a slice share the buffer until one of them is resized), so the element type can not be a NoCopy type such as Array[T]. Use an Array for those, which moves its elements:

xs := []Array[int]{}
--> error: A slice `[]Array[int]` copies its elements, so the element type `Array[int]` can not be `NoCopy`. Use `Array[Array[int]]`, which moves them.

ys := Array[Array[int]]{}
ys.append(Array[int]{1, 2})

The first element of the slice starts at index 0.

print(arr[0])    --> 1
^topic

Sub-slices. #

Slices can be sliced into smaller sub-slices. Sub-slices share the same underlying element buffer as the original slice which enables read/write access to the same elements:

arr := []int{1, 2, 3, 4, 5}
print(arr[0..0])    --> {}
print(arr[0..3])    --> {1, 2, 3}
print(arr[3..])     --> {4, 5}
print(arr[..3])     --> {1, 2, 3}
print(arr[..])      --> {1, 2, 3, 4, 5}
print(arr[1..=2])   --> {2, 3}

The start, the end, or both can be omitted. A missing start is 0 and a missing end is the length. A range without a start or an end is only a slice index. Anywhere else (r := ..3, for ..3 |i|, case ..5) it is a compile error.

a[i..=j] includes the end: it is a[i..j+1]. A decreasing range (..>, ..>=) can not be a slice index.

A range outside a slice index or a for loop is a Range{start, end} value with an exclusive end. 0..=3 is Range{start=0, end=4}. A decreasing range is only allowed in a for loop.

A sub-slice will clone the underlying buffer upon any resize operation such as append, insert, remove, etc. Once cloned, the slice will no longer point to the same elements as the original slice:

arr := []int{1, 2, 3}
slice := arr[0..1]
slice[0] = 100
print('%{arr[0]} %{slice[0]')   --> 100 100

slice += 4
slice[0] = 101
print('%{arr[0]} %{slice[0]')   --> 100 101
^topic

Slice operations. #

Here are some common slice operations:

arr := []int{234}

-- Append a value in place.
arr += 123

-- Another way to append in place.
arr.append(123)

-- Inserting a value at an index in place.
arr.insert(1, 345)

-- Get the length.
print(arr.len())  --> 4

-- Sort the slice in place. Without a function, `sort` uses `<` of the element type.
arr.sort(|a, b| a < b)
arr.sort()

-- Reverse the slice in place.
arr.reverse()

-- Iterating a slice.
for arr |it|:
    print(it)

-- Remove an element at a specific index in place.
arr.remove(1)

append, insert, remove, clear, size_down, size_up and += change the slice in place and return nothing. appended, inserted, removed and + return a new slice and leave the receiver as it was:

arr := []int{1, 2, 3}
rest := arr.removed(0)
print(arr.len())   --> 3
print(rest.len())  --> 2
more := arr + 4
print(arr.len())   --> 3
print(more.len())  --> 4

Assigning the result of an in-place method (arr = arr.append(1), rest := arr.remove(0)) is a compile error that names the method to use. So is dropping the result of a method that returns a new slice (arr.appended(1) as a statement, _ = arr.removed(0)), because it changes nothing.

When the receiver is a variable and this is its last use (the only use of the name in the statement, and no later statement of the block names it), appended, inserted, removed and + take its buffer instead of copying it, like move followed by the in-place method. The result is the same; the variable can not be used after that anyway. ys := xs.appended(4) as the last use of xs then costs no copy. When another value shares the buffer, the result gets its own copy as before. The body of #for does not take the buffer. A statement that assigns the result to the receiver (xs = xs.appended(v), with no other use of xs in it) takes the buffer too, also in a loop body, so building a list this way does not copy it for each element. So does a member of a variable or of the &&T receiver of a method (self.xs = self.xs.appended(v)), when the variable is not borrowed and the arguments do not name it.

Copies of a slice share its buffer until one of them resizes: an in-place resize of a slice whose buffer another value also holds (ys := xs, a sub-slice) first copies the buffer, so the other value keeps its elements and its length. Writing an element (xs[0] = v, sort, reverse) does not copy: every value that shares the buffer sees it.

xs := []int{1, 2}
ys := xs
xs.append(3)
print(ys.len())   --> 2
xs[0] = 9
print(ys[0])      --> 1

The last print shows 1 because append already gave xs its own buffer. Without the append, ys[0] would be 9.

A slice that holds its buffer alone resizes in place without copying. A loop of append or += takes amortized constant time per element, while a loop of xs = xs + v copies the slice every time.

^topic

Changing a global slice in place. #

A global can not be borrowed exclusively: a function could reach the global by its name while it also holds a && borrow of it. The in-place methods still work on a global Slice or Array, on a field of a global, and on the target of a pointer, by take-and-restore: the arguments are evaluated first, then the call moves the value out of the global into a hidden local, the global holds an empty list while the method runs, and the value moves back right after the call.

global log []str = {}

fn note(s str):
    log.append(s)       -- in place, no copy of the list
    log += '!'

note('a')
print(log.len())        --> 2
print(log.pop().?)      --> !
  • The value is not copied, so a loop that grows a global list stays fast.
  • An argument is evaluated before the value moves out, so it reads the global as it was: g.append(g.len()), g.append(g[0]) and g.append(next()) with a next that reads g all work. An argument that leaves the call (g += f()! when f returns an error) leaves the global as it was.
  • An argument that borrows the same global can not be evaluated first: g.append(g.span()) is the compile error 'The method takes g out while it runs, so this argument can not read g. Read it into a local first.' Another field of the same global is fine: st.xs.append(st.ys.span()).
  • Code that runs inside the method and reads the global by its name sees the empty list. The methods of Slice and Array do not, but a @deinit of an element type that reads the global would.
  • Only a type with an empty value ([]T, Array[T]) can be taken. An exclusive borrow of a global of another type is a compile error.

A ^[]T reference does not turn into the && borrow of an in-place method by itself, since other references may share the list. Call the method on the target: rows.*.append('a'). rows.append('a') is a compile error that names this form.

An index or a length that is out of range panics. This holds for Array, Slice, spans and Buffer: remove and insert need a valid index, the start and the end of a slice expression can not be negative, and a negative or too large length ([]int(n, 0), size_up) panics with Invalid allocation length. str.repeat panics with InvalidArgument when the result would be longer than 4 GiB.

An Array changes in place. pop removes the last element and returns it, or none when the array is empty:

a := Array[str]{'x', 'y'}
print(a.pop().?)       --> y
print(a.len())         --> 1

[]T has the same pop:

xs := []int{1, 2}
print(xs.pop().?)      --> 2
print(xs.len())        --> 1
^topic

Maps. #

A Map type is a dynamic data structure that stores key value pairs in a lookup table governed by hashing functions (key hash and equality functions). Map provides default hashing functions while HashMap requires custom hash functions. The default functions accept these key types: str, integers (Int and Raw of any width), float, f32, bool, symbol, error, enums, Object and references (^T, hashed by address). Another key type is a compile error.

Maps are constructed with the initializer expression:

map := Map[str, int]{a=123, b=234}

The initializer literal can infer the target map type:

var map Map[str, int] = {a=123, b=234}

A key is written key=value, not key: value. A name as a key is a string ({a=1} has the key 'a'). A key in parentheses is an expression:

k := 'name'
map := Map[str, int]{(k)=1, (k + '2')=2, 'my key'=3}
ids := Map[int, str]{1='one', (1 + 1)='two'}

A map literal needs a target type. {a=1} alone is a compile error.

map := Map[int, int]{}

map[123] = 234

print(map[123])     --> 234

print(map.keys())   --> {123}
print(map.values()) --> {234}

map.remove(123)

-- Iterating a map.
for map |entry|:
    print('%{entry.key} -> %{entry.value}')

Structs. #

A struct type contains typed fields.

Struct types are declared with type followed by an optional struct keyword, The following two declarations are equivalent:

type Vec2 struct:
    x float
    y float

type Vec2:
    x float
    y float

Field names are unique in a type. Declaring a second field with the same name is a compile error.

^topic

Initialize struct. #

Structs are constructed from an initializer expression:

v := Vec2{x=30, y=40}
print(v.x)      --> 30.0

An initializer literal can infer the target struct type:

var v Vec2 = {x=30, y=40}

Every entry of a struct initializer is a name = value pair. An entry without a field name is a compile error:

v := Vec2{x=30, 40}
--> error: Expected key value pair.

Structs by default are copyable (unless a child member is not):

v := Vec2{x=30, y=40}
w := v
v.x = 100
print(w.x)     --> 30.0
print(v.x)     --> 100.0
^topic

Default field values. #

Struct initialization requires all fields to be specified, unless a default value was declared. Default field values must be const expressions :

type Vec2:
    x float = 0
    y float = 0

v := Vec2{}
print(v.x)       --> 0.0
print(v.y)       --> 0.0

The names in a default value are looked up where the type is declared: in its module, including private declarations, and among its template parameters (v T = T(3)). The locals of the code that writes the initializer are not visible to it, so a local K does not change the default x int = K.

A default value is owned like a value written in the initializer: a default that reads a global or another place copies it, and one that reads a NoCopy value from a place is the compile error 'Cannot copy Array[int], type implements NoCopy.' at the default.

meta.has_field_default(T, name) tells whether a field has a default value, and meta.field_default(T, name) evaluates it.

Unlike a struct, a cstruct can default to their zero values.

^topic

Field visibility. #

Fields have public visibility by default. However, when a field is declared with a - prefix, the field can only be accessed within the same module (although metaprogramming can get around this constraint):

type Info:
    a       int
    -b      int
    -secret str

The module is the file that declares the type. From another module, reading, assigning or initializing a private field (Info{a=1, b=2}), also through a borrow or pointer, is a compile error: Can not access the private field binInfo. A type that other modules need to initialize gives its private fields a default value. A persist_main session (the REPL) counts as one module.

^topic

Circular references. #

Field declarations may have circular type references if the struct can be initialized:

type Node:
    val  int
    next ?^Node

n := Node{val=123, next=none}

In the above example, next has an optional ?^Node reference type so it can be initialized to none when creating a new Node instance.

The following Node type reports an error because it can not be initialized:

type Node:
    val  int
    next Node     --> CompileError. Circular reference.
^topic

Type embedding. #

Type embedding facilitates type composition by using the namespace of a child field's type:

type Base:
    a int

fn (&Base) double() -> int:
    return self.a * 2

type Container:
    b use Base

c := Container{b = Base{a=123}}
print(c.a)
--> 123
print(c.double())
--> 246

Note that embedding a type does not declare extra fields or methods in the containing type. It simply augments the type's using namespace by binding the embedding field.

If there is a member name conflict, the containing type's member has a higher precedence:

type Container:
    a int
    b use Base

c := Container{a=999, b = Base{a=123}}
print(c.a)
--> 999
print(c.double())
--> 246

Since the embedding field is named, it can be used just like any other field:

print(c.b.a)
--> 123
^topic

Methods. #

Methods are functions that are invoked with a parent value (receiver).

They are declared by specifying the receiver's type before the function name and the other parameters. Inside a method body, self references the receiver's members as well as invoking other methods:

type Node:
    value int
    next  ?^Node

fn (&Node) inc(n int):
    self.value += n
    self.inc_one()

fn (&Node) inc_one():
    self.value += 1

var n = Node{value=123, next=none}
n.inc(321)    --> 445

A method is declared in the module that declares the type. A type that a module imports does not take one, and neither does a name that is not a type:

use m 'm.cy'
use V = m.V

fn (&V) twice() -> float:
    --> CompileError: Can not declare `twice` for `V`: `V` belongs to another module. A method or a member of a type is declared in the module that declares the type.
    return self.x * 2

The same holds for a function, a constant and a function template of a type (fn V :: make(), const V :: K = 1). In a persist_main session the evals are one module, so a later eval declares a method for a type of an earlier one. See REPL.

The receiver type can be passed by value, reference, borrow, or pointer:

-- Pass by value.
fn (Node) inc(n int)

-- Pass by borrow.
fn (&Node) inc(n int)

-- Pass by exclusive borrow.
fn (&&Node) inc(n int)

-- Pass by reference.
fn (^Node) inc(n int)

-- Pass by pointer.
fn (Ptr[Node]) inc(n int)

It's recommended to use a borrow for the receiver unless there is a good reason not to.

Choosing a receiver. #

Start with a shared borrow &T. Change the receiver to an exclusive borrow &&T when the method does something that can invalidate another borrow of the value. The rules behind this are in Exclusive borrows.

A &T receiver can:

  • Read every field.
  • Assign a field that is not managed (int, float, bool, a struct of those), and an element of a slice field (self.items[0] = x).
  • Call the methods that take &T.

A &&T receiver is needed to:

  • Append to a field or resize it (self.items += x, self.items.append(x), self.items.clear()).
  • Assign a managed field: a str, a slice, a Map, a struct that holds one of them, or a field of such a struct (self.tag.label = 'z').
  • Call a method that takes &&T.
type Tag:
    label str

type Counter:
    n     int
    name  str
    items []int
    tag   Tag

fn (&Counter) count() -> int:
    return self.items.len() + self.n

fn (&Counter) inc():
    self.n += 1               -- `n` is not managed.
    print(self.count())       -- A `&Counter` method.

fn (&&Counter) add(x int):
    self.items += x           -- Appends.
    self.name = 'added'       -- Replaces a `str`.
    self.tag = Tag{label='new'}
    self.inc()                -- A `&&Counter` receiver can call a `&Counter` method.

c := Counter{n=0, name='c', items={}, tag=Tag{label='t'}}
c.inc()         --> 1
c.add(5)        --> 3

A &T receiver that does one of these things is a compile error. Each error has its own message:

fn (&Counter) push(x int):
    self.items += x
    --> error: Cannot borrow exclusively through a shared borrow. Declare the borrow as `&&T`.

fn (&Counter) rename(name str):
    self.name = name
    --> error: Cannot replace a managed value through a shared borrow. Declare the borrow as `&&T`.

fn (&Counter) add_one():
    self.add(1)
    --> error: Expected argument `&>Counter`, found `&Counter`, when calling `fn add(&>Counter, int) -> void`.

The first is 'Cannot borrow exclusively through a shared borrow. Declare the borrow as &&T.' and the second is 'Cannot replace a managed value through a shared borrow. Declare the borrow as &&T.' In the third message, &>Counter is the exclusive borrow &&Counter.

A call of a &&T method needs exclusive access to the value. No other borrow of the value can be in use:

c := Counter{n=0, name='c', items={1}, tag=Tag{label='t'}}
first := &c.items[0]
c.add(2)
--> error: Expected exclusive access. There is another active borrow to `c`.
print(first.*)

A method that implements a trait method takes &T. A &&T method does not implement a trait method. See Receivers of trait methods.

type Vec2:
    x float
    y float

fn (&Vec2) `+`(o Vec2) -> Vec2:
    return {

        y = self.y + o.y,

    return {x=-self.x, y=-self.y}

c := -a

An operator method only applies when its type is on the left. When the left operand is a number or another type, declare a module-level operator function that takes both operands. a op b first looks for a method op of the type of a. If there is none, it looks for a module-level function op in the module that declares the type of a, then in the module that declares the type of b:

fn `*`(s float, v Vec2) -> Vec2:
    return {x=s * v.x, y=s * v.y}

d := 2.0 * a
e := 2 * a      -- The literal takes the type of the parameter.

A number literal on either side takes the type of the parameter (c * 2 with fn *(c Cents, f float)). A left operand of a type from another module, such as str, finds a function in the module of the right type. This works for the arithmetic and bitwise operators (+ - * / % ** && || ~ << >>). A module-level operator function takes two parameters, and one of them must be a type declared in the same module. A module can not add an operator to two types that it does not own, since a op b would never find it. Comparison operators (< <= > >=) are only methods of the left operand type.

Special operators have their own name. This example overloads the index operator and the set index operator:

type MyCollection:
    arr []int

fn (&MyCollection) @index(idx int) -> int:
    return self.arr[idx * 2]

fn (&MyCollection) @set_index(idx int, value int):
    self.arr[idx * 2] = val 

a := MyCollection{arr={1, 2, 3, 4}}
print(a[1])
--> 3

Enums. #

An enum type is an exhaustive type where all possible values are defined by case members.

type Fruit enum:
    case apple
    case orange
    case banana
    case kiwi

fruit := Fruit.kiwi
print(fruit)       --> Fruit.kiwi
print(int(fruit))  --> 3

The memory representation of an enum defaults to int. Each case has an increasing value starting from 0.

Case names are unique in an enum. Declaring a second case with the same name is a compile error. The same holds for the cases of a choice and of a C union.

A dot literal can infer a target enum type:

fruit := Fruit.kiwi
fruit = .orange
print(fruit == Fruit.orange)   --> true
^topic

Enum switch. #

switch case can match enum cases:

fn binary_search(arr []int, needle int, compare CompareFn) -> ?int:
    low := 0
    high := len
    while low < high:
        mid := low + (high - low) / 2
        switch compare(needle, mid):
            case .eq: return mid
            case .gt: low = mid + 1
            case .lt: high = mid
    return none

Choices. #

A choice type is an exhaustive type where only one defined case can be active. Each case member may contain a payload of an arbitrary type. An enum declaration becomes a choice declaration if one of the cases has a payload type specifier:

type Shape enum:
    case rectangle Rectangle
    case circle    Circle
    case triangle  Triangle
    case line      float
    case point 

type Circle(radius float)
type Rectangle(width, height float)
type Triangle(base, height float)
^topic

Initialize choice. #

A choice can be initialized with the case payload as an argument:

rect := Rectangle{width=10, height=20}
s := Shape.rectangle(rect)

-- Alternatively.
s = Shape.rectangle({width=10, height=20})

s = Shape.line(20)

A choice without a payload is initialized like an enum case:

s = Shape.point
^topic

Choice switch. #

switch case can match choice cases and capture the payload:

switch s:
    case .rectangle |r|:
        print('%{r.width} %{r.height}')
    case .circle |c|:
        print(c.radius)
    case .triangle |t|:
        print('%{t.base} %{t.height}')
    case .line |len|:
        print(len)
    case .point:
        print('a point')
    else:
        print('Unsupported.')

Only a case of a choice has a payload to capture. A capture clause in a switch on another type is a compile error:

switch 1:
    case 1 |a|:
        pass
    else:
        pass
--> error: Only a case of a choice can capture a payload.
^topic

Compare choices. #

== compares the active cases first. Two values of the same case compare their payloads with ==, and a case without a payload is equal to itself:

Shape.line(20) == Shape.line(20)   --> true
Shape.line(20) == Shape.line(30)   --> false
Shape.line(20) == Shape.point      --> false
Shape.point == Shape.point         --> true

A payload compares by the rules of its type, so a slice payload compares by reference (see Comparison operators). An optional choice can be compared with none.

Unwrap choice. #

A choice can be unwrapped with the .! operator. This will either return the payload or signals a thread panic if the expected case is not active:

s := Shape.line(20)
print(s.!line)     --> 20

Traits. #

A trait is a generic type that defines a common interface for implementing types:

type Shape trait:
    fn area() -> float

Types can be declared to implement a trait with the with keyword:

type Circle:
    with Shape
    radius float

fn (&Circle) area() -> float:
    return 3.14 * self.radius**2

type Rectangle:
    with Shape
    width  float
    height float

fn (&Rectangle) area() -> float:
    return self.width * self.height

A type that intends to implement a trait but does not satisfy the trait's interface results in a compile error. The implementing method must have the same number of parameters, the same parameter types and the same return type as the trait method. Implicit conversions such as int to float do not count, so fn (&Circle) scale(k int) does not implement fn scale(k float).

A trait method without a body is a required method. A trait method with a body is a default method.

^topic

Receivers of trait methods. #

A trait method is declared without a receiver. It is called through a shared view of the value (^Dyn[Shape], &Dyn[Shape], self of a default method), and other borrows of the value can be in use at that time. So the method that implements it takes a shared borrow &T.

A method with an exclusive receiver &&T does not implement a trait method:

type Grow trait:
    fn push(x int)

type Box:
    with Grow
    --> CompileError: `Box` does not implement `fn push(Grow, int) -> void` from `Grow`. The method `push` takes an exclusive borrow `&&Box`, but a trait method takes a shared borrow `&Box`. Keep what `push` changes behind a reference `^T`, or call `push` on `Box` without the trait.
    xs []int

fn (&&Box) push(x int):
    self.xs += x

There are two ways out. Call the &&T method on the type itself and keep it out of the trait. Or keep the value that the method changes behind a reference. The exclusive borrow rule does not hold behind a ^T, so the method can take &T:

type Items:
    xs []int

type Box:
    with Grow
    items ^Items

fn (&Box) push(x int):
    self.items.xs += x

var g ^Dyn[Grow] = ^Box{items=^Items{xs={}}}
g.push(1)

The compiler does not check a borrow that points into a value behind a ^T. Do not keep such a borrow over a call that can resize the value.

When a type has both a &T and a &&T method with the signature of the trait method, the &T method implements the trait.

A method that takes the receiver by value, as ^T or as sink T implements the trait for a template constraint (fn size_of[T Sized](x T)), but the type can not be used as a Dyn value and does not get the default methods of the trait: 'Unit can not be used as Dyn[Sized]. The method size takes the receiver as Unit, but a call through Dyn passes a shared borrow &Unit. Declare the method as fn (&Unit) size(...).'

^topic

Dynamic dispatch. #

Since traits are a generic type, they need to be wrapped in a Dyn container to be materialized into a dynamic dispatch value. Implementing types become assignable to a Dyn reference type:

var s ^Dyn[Shape] = ^Circle{radius=2}
print(s.area())       --> 12.56

s = ^Rectangle{width=4, height=5}
print(s.area())       --> 20.0
^topic

Default methods. #

A trait method with a body is a default method. An implementing type that does not declare the method gets it:

type Shape trait:
    fn area() -> float
    fn name() -> str

    fn describe() -> str:
        return '%{self.name()} with area %{self.area()}'

type Circle:
    with Shape
    radius float

fn (&Circle) area() -> float:
    return 3.14 * self.radius**2

fn (&Circle) name() -> str:
    return 'circle'

c := Circle{radius=2}
print(c.describe())       --> circle with area 12.56

var s ^Dyn[Shape] = ^Circle{radius=1}
print(s.describe())       --> circle with area 3.14

The default method can be called on the implementing type and through a Dyn value.

A type overrides a default method when it declares a method with the same name and the same signature:

type Square:
    with Shape
    width float

fn (&Square) area() -> float:
    return self.width * self.width

fn (&Square) name() -> str:
    return 'square'

fn (&Square) describe() -> str:
    return 'a square of %{self.width}'

print(Square{width=2}.describe())       --> a square of 2.0

A method of the type with the same name and the same parameter types takes the place of the default method. If its return type is not the one from the trait, the type does not implement the trait: 'Square does not implement fn describe(Shape) -> str from Shape.' A method with the same name and other parameter types is another overload, and the type still gets the default method. A trait can have overloads too, with a default for some or for all of them, and a default method can call another overload on self. A field or a function without a receiver that has the same name keeps the default methods of that name out.

Inside a default method, self is the receiver seen through the trait. Its type is the shared borrow &Dyn[Shape]. It can call the other methods of the trait, required or default, and it can be passed to a function that takes a &Dyn[Shape]. A call on self is a dynamic dispatch, so it reaches the method of the implementing type, including an override of another default method.

self knows nothing else about the implementing type. A field access is a compile error:

type Shape trait:
    fn describe() -> str:
        return 'radius %{self.radius}'
        --> CompileError: Field `radius` does not exist in `&Dyn[Shape]`. A default method of a trait can not access the fields of the implementing type, only the methods of the trait.

To use a value of the type, declare a required method that returns it and call that method.

The other rules:

  • A trait method is declared without a receiver, and a default method always takes the receiver as a shared borrow. There is no default method with an exclusive receiver &&T, and a &&T method does not implement a trait method. See Receivers of trait methods.
  • A default method of a generic trait can use the template parameters of the trait. A template type gets default methods like any other type.
  • The body is compiled for each type that gets the default method. A default method that every implementing type overrides is not checked.
  • When two traits of a type have a default method with the same name and the same parameter types, the type must declare the method itself. Otherwise: 'Both gets the default method side from both Left and Right. Declare side for Both to say what it does.' The declared method implements both traits when its signature matches both.
  • A default method of one trait does not implement a required method of another trait: 'Both has the method side only as a default method of Left. Declare side for Both to implement Right.'
  • A default method can not be a generator ('A default method of a trait can not be a generator.') and can not have a template parameter ('A default method of a trait can not have a template parameter.').

Type templates. #

Type declarations can include template parameters. Unlike function parameters, template parameters accept types rather than values of types by default. The type provided is constrained by a generic type specifier. The Any generic type allows any type:

type MyContainer[T Any]:
    id    int
    value T

fn (&MyContainer[]) get() -> T:
    return self.value

When the type template is expanded, a variant of the type is generated:

a := MyContainer[str]{id=123, value='abc'}
print(a.get())     --> abc

Expanding the template with the same parameters returns the same generated type. In other words, the generated type is always memoized from the input parameters.

^topic

const template parameter. #

Template parameters can accept const values other than types with the const modifier:

type MyArray[T Any, const N int]

A const parameter can be an integer (int, byte, i32, ...), a bool, an enum, an EvalStr, or a function symbol (fnsym). Any other parameter type is a compile error. The value is a compile-time constant inside the template body, so it can drive #if and be expanded to a runtime value:

type Lvl enum:
    case low
    case high

type Tag[const S EvalStr, const L Lvl]:
    v int

fn (&Tag[]) name() -> str:
    #if L == .high:
        return S + '!'
    #else:
        return S

t := Tag['warn', .high]{v=1}
print(t.name())               --> warn!
print(type.name(Tag['warn', .high]))   --> Tag['warn', Lvl.high]

Instances are memoized by value: Tag['a', .low] and Tag['a', .low] are the same type, Tag['a', .low] and Tag['b', .low] are different types.

Branching. #

^topic

if statement. #

The if and else statements branch execution depending on conditions. The else clause can contain a condition which is only evaluated if the previous if/else conditional evaluated to false:

a := 10
if a == 10:
    print('a is 10')
else a == 20:
    print('a is 20')
else:
    print('neither 10 nor 20')

An else with a condition is written else cond:. else if cond: and elif cond: are compile errors that say so.

^topic

if expression. #

An if expression evaluates to a value depending on the condition. Unlike the if statement, the if expression can not contain else conditions:

x := 123
b := if (x) 1 else 0
^topic

and expression. #

and evaluates to true if both operands are true. Otherwise, it evaluates to false. If the left operand is false, the evaluation of the right operand is skipped:

true and true    --> true
true and false   --> false
false and true   --> false
false and false  --> false

a := 10
if a > 5 and a < 15:
    print('a is between 5 and 15')
^topic

or expression. #

or evaluates to true if at least one of the operands is true. Otherwise, it evaluates to false. If the left operand is true, the evaluation of the right operand is skipped:

true or true     --> true
true or false    --> true
false or true    --> true
false or false   --> false

a := 10
if a == 20 or a == 10: 
    print('a is 10 or 20')

for range. #

for loops can iterate over a range that starts at an int (inclusive) to a target int (exclusive):

for 0..4:
    performAction()

The loop's counter variable can be captured:

for 0..100 |i|:
    print(i)   --> 0, 1, 2, ... , 99

When ..= is used, the target int is inclusive:

for 0..=100 |i|:
    print(i)   --> 0, 1, 2, ... , 100

To decrement the counter instead, use either ..> or ..>=:

for 100..>=0 |i|:
    print(i)   --> 100, 99, 98, ... , 0
^topic

for each. #

The for clause can iterate over any type that implements the Iterable trait. An Iterable contains an iterator() method which returns a value that implements the Iterator trait. The for loop continually invokes the iterator's next() method until none is returned.

A Slice can be iterated. The element value returned from an iterator's next() can be captured in the |_| clause:

arr := {1, 2, 3, 4, 5}

for arr |n|:
    print(n)

The values come first and the name goes in |_|. for n |{1, 2}|: is a parse error that says so.

Iterating a Map yields MapEntry values:

map := Map[str, int]{a=123, b=234}

for map |entry|:
    print(entry.key)
    print(entry.value)

A counting index can be captured before the each variable. The count starts at 0 for the first value:

arr := {1, 2, 3, 4, 5}
for arr |i, val|:
    print('index %{i}, value %{val}')

The each variable receives a copy of the element. & before the name iterates by borrow instead. The variable is a borrow (&T) of the element and nothing is copied:

arr := Array[str]{'a', 'bc'}
for arr |&val|:
    print(val.len())

for arr |i, &val|:
    print('index %{i}, length %{val.len()}')

Iteration by borrow is required when the element type can not be copied. Array and Slice support it. A type supports it by declaring next_borrow(idx &int) -> scope ?&T next to next. The iterable is borrowed during the loop, so it can not be modified in the loop body.

An iterator can fail. When next returns !?T, an error ends the loop and runs the else block after the body, with the error in its optional |err| capture. The block is required: the error is handled where the loop is written. An iterator that ends without an error skips it:

p := os.cmd({'tail', '-n', '20', 'app.log'}).start()!
for p.lines() |line|:
    print(line)
else |err|:
    print('stopped: %{err}')

Leaving out the else block is a compile error that names the type of next, and an else block after a loop whose next returns ?T is a compile error too. continue in the else block is a compile error: the iterator failed and is not asked again. The block may reach its end, break, or return.

A borrow of an iterable is iterated like the iterable. for a.* |x|: is the same loop:

fn total(a &[]int) -> int:
    s := 0
    for a |x|:
        s += x
    return s

b := {1, 2, 3}
print(total(&b))    --> 6

switch matching. #

The switch statement matches on a control expression and branches to a case from a matching condition. Multiple cases can be grouped together with a comma separator:

val := 1000
switch val:
    case 100:
        print('val is 100')
    case 200, 300:
        print('combined case')
    else:
        print('val is %{val}')

An else fallback case is branched to when no other cases were matched. A switch statement requires an else case unless the type is exhaustive.

        print('at or between 0 and 100')

    else:
        print('val is %{val}')

case fallthrough. #

When a case is declared without a body, it will fallthough to the next case:

val := 1000
switch val:
    case 100
    case 200

Function declaration. #

Functions must be declared with a name:

use math

fn dist(x0, y0, x1, y1 float) -> float:
    dx := x0 - x1
    dy := y0 - y1
    return math.sqrt(dx**2 + dy**2)

Functions can not reference outside local variables unless it's a lambda:

a := 1

fn foo():
    print(a)    --> error: Undeclared variable `a`.

A return without a value returns from a function that returns void (or has no return type) or !void, where it is the success. In a function, method or lambda with any other return type it is a compile error: 'Expected a return value of type int. A return without a value is for a function that returns void or !void.' It does not return none from a function that returns ?T: write return none. In a generator it ends the generator.

fn log(x int):
    if x < 0:
        return          -- OK
    print(x)

fn half(x int) -> int:
    if x == 0:
        return          --> CompileError: Expected a return value of type `int`.
    return x / 2

Functions can only return one value. To return several, declare a tuple type and return that:

type Pair(a int, b int)

fn f() -> Pair:
    return {1, 2}

p := f()
print(p.a + p.b)    --> 3

A return type that lists several types, -> (int, int), and return 1, 2 are parse errors that say so.

Function overloading. #

Functions can be overloaded by their type signature:

fn foo() -> int:
    return 2 + 2

fn foo(n int) -> int:
    return 10 + n

fn foo(n, m int) -> int:
    return n * m

print(foo())         --> 4
print(foo(2))        --> 12
print(foo(20, 5))    --> 100

A call picks the overload whose parameter types match the arguments without implicit conversions, regardless of declaration order. An integer literal matches int parameters first. If no overload matches exactly, the first declared overload that accepts the arguments with implicit conversions (such as int to float) is used:

fn show(x float) -> str:
    return 'float'
fn show(n int) -> str:
    return 'int'

n := 3
print(show(n))       --> int
print(show(2.5))     --> float
print(show(4))       --> int

An argument that takes its type from the parameter does not match an overload whose parameter it can not be made for: none for a parameter that is not a ?T, an enum literal like .red for a type without that member, an initializer literal like {1, 2} for int, or an inferred lambda for a parameter that is not a function type or that has another number of parameters. The call goes on to the next overload. When more than one overload can take the argument, the call is a compile error unless one of them is more specific (T is more specific than ?T and !T):

type Color enum:
    case red
    case blue

fn tag(x int) -> str:
    return 'int'
fn tag(c Color) -> str:
    return 'color'
fn tag(x ?str) -> str:
    return 'str'
fn tag(x ?int) -> str:
    return 'option int'

print(tag(.red))     --> color
print(tag(?int(none)))   --> option int
print(tag(none))
--> error: The call is ambiguous: both `fn tag(?str) -> str` and `fn tag(?int) -> str` match, and neither is more specific. Write `tag(?str(none))` or `tag(?int(none))`.

The declaration order does not decide what a call means. Two cases are not ambiguous: overloads that only differ in number types (float(x) with an i32 takes float, and the value is the same as through int), and str against an integer at a string literal argument (a one-character literal is a string first, so v['n'] takes the str key over the int index). Only arguments that are names, literals and member accesses are checked, since their type can depend on the parameter. When no overload takes the arguments, the call reports the error of the overload that got the furthest through the arguments, and of the first declared one among those. For a literal that is the error of that overload alone, such as 'Expected ?T to infer none value, found Int.' A closure that is passed to overloads that only take a function pointer reports 'Expected argument fn(int) -> int, found Func[fn(int) -> int], when calling fn m(int, fn(int) -> int) -> int. A closure is passed to a Func[fn(...)] or a &OpaqueFunc[fn(...)] parameter.'

Overloads must differ in their parameter types. Declaring two functions with the same parameters and only a different return type is a compile error.

Inferred lambdas. #

Inferred lambdas are declared with the capture |_| clause followed by the function body expression. The parameter and return types are inferred from the target function type:

-- Lambda without any parameters.
do(|_| print('hello'))

-- Lambda with a single parameter.
filter(|word| word.upper())

-- Lambda with multiple parameters.
symbol_name(|word, prefix| prefix + word.upper())

-- Assigning a lambda.
app.on_update = |delta_ms| update_physics(delta_ms)

The lambda declares as many parameters as the function type. apply(|a, b| a) for f fn(int) -> int reports 'Expected a lambda with 1 parameter(s) for fn(int) -> int. Found 2.'

A blockless statement can contain one lambda that has their function body continued in a new block:

    print('My important task.')
    do_stuff()

Closures. #

Lambdas can capture local variables with reference types from an immediate parent scope. The following example shows the lambda f capturing a from the main scope:

a := ^1
f := fn() -> int:
    return a.* + 2
print(f())     --> 3

A local that is not a reference ^T or a borrow &T can not be captured. Borrow it before the lambda and capture the borrow. A closure that captures a borrow becomes a pinned closure of the type OpaqueFunc[F]:

a := 1
b := &a
f := fn() -> int:
    return b.* + 2
print(f())     --> 3

A pinned closure keeps its captured values without a reference, so it is a borrow container: it can not outlive the locals it captures, it is returned only through a scope return type, and it can not be lifted with ^ or stored in a global:

type F = fn() -> int

fn make() -> OpaqueFunc[F]:
    x := 42
    b := &x
    return fn() -> int => b.* + 1
--> error: Returning a borrow container requires a `scope` modifier.

Function pointer types. #

A function pointer type is denoted as fn(P1, P2, ...) -> R where Ps are parameter types and R is the return type. Without -> R the function returns void. It can be written wherever a type is expected: a parameter, a return type, a field, a variable, a type argument and a trait method:

fn apply(x int, f fn(int) -> int) -> int:
    return f(x)

fn make() -> fn(int) -> int:
    return |x| x * 2

type Button:
    on_click fn(str)

var ops []fn(int) -> int = {make(), |x| x + 1}
print(apply(3, ops[0]))    --> 6

A type alias gives a function pointer type a name. The alias and the inline form are the same type:

type AddFn = fn(int, int) -> int

var a AddFn = |a, b| a + b
var b fn(int, int) -> int = a

Function pointer types can include optional parameter names. If one parameter has a name, the other parameters must also have names. Parameter names do not alter the function signature and only serve as documentation:

type AddFn = fn(a int, b int) -> int

Functions and lambdas (excluding closures) can be assigned to a function pointer type:

fn add(a, b int) -> int:
    return a + b

var func fn(int, int) -> int = add
func = |a, b| a + b + 123

The return type of a function type takes everything to its right, and a prefix (?, !, [], ^, &) takes the whole function type after it. Use parentheses for the other reading:

fn(int) -> fn(int) -> int      -- Returns a function: `fn(int) -> (fn(int) -> int)`.
?fn() -> int                   -- An optional function: `?(fn() -> int)`.
fn() -> ?int                   -- A function that returns an optional `int`.
!fn() -> int                   -- A function or an error: `!(fn() -> int)`.
[]fn(int) -> int               -- A slice of functions.

In a signature, the -> R inside the parentheses of the parameters belongs to the parameter and the one after ) belongs to the function. The : that begins a body is never part of a type:

fn compose(f fn(int) -> int, g fn(int) -> int) -> fn(int) -> int:
    return f

Where an expression is expected, fn(...) is a lambda and must be followed by : or =>. It is read as a type only when ), ], , or } follows the signature, which is the case for a type argument (Func[fn(int) -> int], Map[str, fn(int) -> int]{}). f := fn(a int) -> int with nothing after it reports 'Expected colon.' After a type prefix and in the positions listed above, fn(...) is always a type.

An inline function type can use the template parameters of its function that are known from the earlier arguments. It can also declare a new one (f fn(T) -> %U), which is inferred from the function or the lambda that is passed. See infer parameter.

fn filter(items []%T, f fn(T) -> bool) -> []T:
    out := []T{}
    for items |it|:
        if f(it):
            out += it
    return out

print(filter([]float{1, 4, 5}, |x| x > 3.0))    --> {4.0, 5.0}

Function union types. #

A function union type is denoted as Func[FN] where FN is a function pointer type.

It can hold closures in addition to functions and lambdas:

c := ^5

var func Func[fn(int, int) -> int] = |a, b| a + b + c.*
func(10, 20)       --> 35

A parameter of type &OpaqueFunc[FN] (such as the less function of sort) takes a function, a lambda, or a closure that captures ^T or &T variables. A local variable that is not a reference can not be captured yet: borrow it first.

counts := Map[str, int]{app=7, db=8, web=23}
c := &counts
names := counts.keys()
names.sort(|a, b| c[a] > c[b])    -- {'web', 'db', 'app'}

Generic functions. #

When function's signature contains embedded template parameters %, it becomes a generic function:

fn add(%T type, a T, b T) -> T:
    return a + b

Generic functions automatically expand to a function when invoked. The template parameter(s) are used to generate the appropriate function:

print(add(int, 1, 2))   --> 3
print(add(float, 1, 2)) --> 3.0

Note that invoking the function again with the same template parameter(s) uses the same generated function. The generated function is always memoized from the template parameters.

^topic

Infer parameter. #

When a template parameter is declared in a type specifier, it's inferred from the call argument's type:

fn add(a %T, b T) -> T:
    return a + b

print(add(1, 2))        --> 3
print(add(1.0, 2.0))    --> 3.0

Nested template parameters can also be inferred:

fn set(m Map[%K, %V], key K, val V):
    m[key] = val

The arguments of a call are matched from left to right. A parameter type can use the template parameters that the arguments before it bound and declare new ones at the same time:

type Pair[T Any, U Any]:
    a T
    b U

fn second(x %T, p Pair[T, %U]) -> U:
    return p.b

print(second(1, Pair[int, str]{a=1, b='x'}))    --> x

The parts of the type that are already known must match the argument: second(1, Pair[str, str]{a='a', b='x'}) reports 'Expected type Pair[int, str]. Found Pair[str, str].'

A template parameter that is declared in a function type is inferred from the function that is passed. The parameter types and the return type of the function type are matched with those of the function:

fn map(items []%T, f fn(T) -> %U) -> []U:
    out := []U{}
    for items |it|:
        out += f(it)
    return out

fn name(x float) -> str:
    return 'v%{x}'

print(map([]float{1, 2}, name))                 --> {'v1.0', 'v2.0'}
print(map([]int{1, 2}, fn(x int) => x * 2))     --> {2, 4}
print(map([]int{1, 2}, |x| 'n%{x}'))            --> {'n1', 'n2'}

T is bound to float by the first argument, so the function must take a float: map([]int{1, 2}, name) reports 'Expected type fn(int) -> str. Found fn(float) -> str.' U is bound to str, the return type of name.

The function type can declare a parameter anywhere in its signature (fn(%A, %B) -> %C, fn(T) -> []%U, fn(T) -> ?%U, fn(T) -> !%U). It can be written inline, as a type alias template (f MapFn[T, %U] for type MapFn[A Any, B Any] = fn(A) -> B), or as the argument of a function union (f Func[fn(T) -> %U], f &OpaqueFunc[fn(T) -> %U]), which also takes a closure. This works the same for a method (fn (&Box[]) map(f fn(T) -> %U) -> Box[U]).

An inferred lambda (|x| expr) has no types of its own. Its parameters are typed from the function type, and the template parameters in the return type are then inferred from the type of its body. So every template parameter in the parameter types of the function type must be bound by an argument before the lambda:

fn rmap(f fn(%T) -> %U, items []T) -> []U:
    out := []U{}
    for items |it|:
        out += f(it)
    return out

fn name(x float) -> str:
    return 'v%{x}'

print(rmap(name, []float{1, 2}))                    --> {'v1.0', 'v2.0'}
print(rmap(fn(x int) => x + 1, []int{1, 2}))        --> {2, 3}
print(rmap(|x| x + 1, []int{1, 2}))
--> error: Can not infer the template parameter `T` from the lambda for `f`. The type of the lambda parameter `x` must be known from the arguments before the lambda. Declare the types of the lambda (`fn(x T) -> U: ...`), or declare `%T type` as its own parameter and pass the type in the call.

A function or a lambda with declared types (fn(x int) => x + 1) binds T itself, so it can come first. Declare the function parameter after the parameters that its lambda depends on, like map above.

The result type of an inferred lambda with a block is not inferred. Where it would bind a template parameter, the call reports 'Can not infer the template parameter U from the lambda for f. The result type of a lambda with a block is not inferred. Use an expression lambda (|x| expr), declare the types of the lambda (fn(x T) -> U:), or declare %U type as its own parameter and pass the type in the call.':

print(map([]int{1, 2}, |x|)):
    return x + 1

When no argument binds a template parameter, the call reports 'Can not infer the template parameter U from the argument for f. Declare it as its own parameter (%U type) and pass the type in the call.' A parameter inside a computed size (fn(T) -> [%N + 1]T) is never bound by an argument and reports the same. An explicit parameter is always an alternative to inference:

fn convert(%U type, items []%T, f fn(T) -> U) -> []U:
    out := []U{}
    for items |it|:
        out += f(it)
    return out

print(convert(str, []float{1, 2}, |x| 'v%{x}'))   --> {'v1.0', 'v2.0'}

A template parameter is declared once. fn two(a %T, b %T) -> T reports 'The template parameter T is already declared. Write T without % to use it.'

Among overloads, a function that infers template parameters is tried only after the overloads that match the arguments exactly. An inferred lambda (|x| expr, or |x| with a block) does not match an overload when its body does not have the result type of the function parameter, like a named function with another result type, and the call goes on to the next overload:

fn conv(x int, f fn(int) -> str) -> str:
    return f(x)

fn conv(x %T, f fn(T) -> %U) -> U:
    return f(x)

print(conv(1, |x| 'v%{x}'))    --> v1
print(conv(1, |x| x + 1))      --> 2

The body does not have the result type when:

  • The type of an expression body is another type, or a literal in it can not be made for the result type ({1, 2} for str).
  • A branch of an if expression that is the body has another type. The same goes for a return with a switch expression.
  • A return in a block has another type, or the block needs a return and reaches its end without one.
  • A ! leaves the lambda and the result type is not a !T or error.
fn pick(x int, f fn(int) -> str) -> str:
    return 'str %{f(x)}'

fn pick(x int, f fn(int) -> int) -> str:
    return 'int %{f(x)}'

print(pick(1, |x| if (x > 0) x else 0))    --> int 1

r := pick(5, |x|):
    if x > 3:
        return 'big'
    return 'small'
print(r)                                   --> str big

An overload that infers template parameters is compared the same way when its function parameter declares the result type (f fn(T) -> str), also when it is declared before another overload. Such an overload does not match either, and the call goes on to the next one, when:

  • An argument does not have the type of its parameter (2 for y str).
  • The type of an argument does not have the form that the parameter declares: a function or a lambda that returns float for f fn(T) -> ?%U (the same goes for !%U, []%U and Map[%K, int]), or a closure for f fn(T) -> %U.
  • The argument is a lambda with a block and the parameter infers its result type (f fn(T) -> %U), or the lambda has another number of parameters.
fn opt(x %T, f fn(T) -> ?%U) -> str:
    return 'option'

fn opt(x float, f fn(float) -> float) -> str:
    return 'float'

fn some(x int) -> ?int:
    return x

print(opt(1, some))           --> option
print(opt(1, |x| x / 2))      --> float

When no overload takes the arguments, the call reports the error of the overload that came closest, as if it were the only one: 'Expected type str, got int.' at the branch or return of a lambda, 'Expected template Option. Found Float.' for opt(1, |x| 1.5) without the second overload, or 'Expected type str. Found bool.' Any other error in an argument, like an undeclared name in the body of a lambda, is reported right away.

Two overloads that infer template parameters can differ only in the form of a parameter type: fn f(x ?%T), fn f(x []%T) and fn f(x %T) are three overloads, and so are f fn(T) -> ?%U and f fn(T) -> []%U. Overloads whose parameter types are written the same way, apart from the names of the infer parameters (fn f(x []%T) and fn f(y []%U)), report 'f has already been declared with the same function signature.' A type argument (make(int, 1)) goes on to an overload that takes a %T type, and a compile-time call (const a = f(3)) goes on to the next overload the same way as a runtime call.

An infer parameter is declared in a parameter type only. fn f(x int) -> %U reports '%U can not be declared in a return type. Declare it in a parameter (%U type) instead.', and %T in a function body or outside of a function reports '%T can only be declared in the signature of a function.'

Cyber provides memory safety by default by providing structured memory semantics. Manual memory is also supported. An embedding host can reject raw pointers in scripts with the deny_raw_ptrs compile option.

Structured memory. #

Cyber supports value ownership, borrowing, and deinitializers. These concepts allow a value to be cleaned up automatically during execution because their lifetimes can be determined from analyzing the program's control flow.

This means that memory can be automatically managed without a garbage collector and deinitializer logic can be coupled with the value's lifetime. This prevents memory and state bugs such as:

  • Use before init, allocation.
  • Use after deinit, invalidation, free.
  • Invalid deinit, free. (decoupling value from its deinitializer logic)
  • Free before allocated.
  • Free with wrong allocator.
  • Double free.
  • Memory leaks. (forgetting to free)

At the same time, the use of structured memory is performant because it leverages cache locality and allows referencing to stack and interior heap members which flattens the memory hierarchy (less object indirection). In some cases, no-alias optimizations can be enabled because the compiler can prove there is only one reference pointing to a value.

Value ownership. #

A value can be any type such as primitives, containers, and even references.

A value created on the stack can only have one owner; the variable it was assigned to, otherwise a temporary variable. A heap value can have multiple owners as shared references ^T.

When the last owner goes out of scope (no longer reachable), its value is deinitialized.

At the end of a block, a child variable can no longer be accessed so its value is deinitialized:

a := 123

-- Deinit `a`.

In this case, it's effectively a no-op because a is a primitive int type.

If the value was a str (an immutable type backed by a reference counted buffer), the deinitialize logic would release a reference count (-1) on the underlying buffer:

a := 'hello'

-- Deinit `a`.
-- `a.buf` is released.
-- `a.buf` is freed.

Since the string buffer's reference count reaches 0, it's the last owner that points to the buffer so the buffer value is deinitialized (freed from heap memory).

The following initializes a value that holds a system resource:

a := os.open_file('foo.txt')!

-- Deinit `a`.
-- `a.@deinit()` is called.
-- `a.fd` file handle is closed.

In this case, a deinitializes by closing the file handle that it owns. a.close() closes it earlier, and a.is_closed() tells whether it was closed.

Owners can also go out of scope when they have been reassigned:

a := 123

-- Deinit `a`.
a = 234

b := Foo{a=123}

-- Deinit `b.a`.
b.a = 234

Value ownership allows the lifetime of values to be understood from the control flow. A value always knows how to deinitialize itself as described by its type, and the owner knows when to deinitialize the value.

Copy semantics. #

Commonly used data types are copyable such as primitives, str, Slice, and others. A copyable type is implicitly copied. This can result in a shallow or deep copy depending on how the type is defined:

a := 123

b := a
-- Bit copy of `int`

Composite types are also copyable if all its members are copyable:

?int       -- Copyable option.

type Foo:  -- Copyable struct.
    a int
    b str

A custom type can also be copyable if it declares a @copy method:

use c

type MyArray:
    ptr Ptr[byte]
    len int

-- Performs deep copy.
fn (&MyArray) @copy() -> Self:
    new_buf := alloc(byte, self.len)
    c.memcpy(new_buf.ptr, self.ptr, self.len)
    return {ptr=new_buf.ptr, len=self.len}

A type that implements the NoCopy trait prevents implicit copying. Where a copy would be made from a variable or a member of one, the value is moved instead, and the variable can not be used after that:

type Foo:
    with NoCopy

    a int

f := Foo{a=123}

g := f            -- Moves `f` into `g`.
print(f.a)
--> error: `f` was moved at 8:6. Borrow it with `&f` or clone it to use it here.

An Array can hold elements that are not copyable. The elements are moved into the array, read by borrow and deinitialized once:

a := Array[Foo]{Foo{a=1}, Foo{a=2}}   -- A literal moves its elements.
f := Foo{a=3}
a << f                                -- A variable is moved.
a[0] = Foo{a=4}                       -- The old element is deinitialized.

print(a[1].a)       --> 2
r := &a[0]          -- Borrow an element.
for a |&e|:         -- Iterate by borrow.
    print(e.a)

x := a[0]
--> error: Cannot copy `Foo`, type implements `NoCopy`.

The methods that copy an element, such as clone, last, contains and index, do not exist for such an array. This includes an array of arrays: Array[Array[int]]{{1}, {2, 3}}.

Some types such as Array disallows copying but can still be cloned or moved.

Cloning. #

Some value types cannot be implicitly copied but can be explicitly cloned. A type that can be cloned provides a clone method, such as Array.clone:

a := Array[int]{1, 2, 3}
b := a.clone()

A user type declares its own method. There is no builtin clone function:

type Foo:
    a int

fn (&Foo) clone() -> Foo:
    return {a=self.a}
^topic

Moving. #

Values can be moved, thereby transfering ownership from one variable to another:

a := 123
b := move a

print(a)
--> error: `a` was moved at 2:11. Borrow it with `&a` or clone it to use it here.

move is an explicit operation on any value type. It is not restricted to types that implement NoCopy. Moving a copyable value such as an int is allowed and still ends the source variable, so whether a type is copyable and whether it can be moved are independent: a copyable type can be copied (b := a) or moved (b := move a), a NoCopy type can only be moved or cloned. This differs from Rust, where a Copy type is always copied and has no move. Moving a copyable value is useful when the type has a custom @deinit and a copy would deinitialize the resource twice, and in generic code that must handle copyable and NoCopy element types with the same statement (Array.append stores its argument with move val). Reference types ^T are shared and reference counted, so a reference parameter can not be moved (Cannot move a reference parameter.).

Some types such as Array can not be passed around by default without moving (or cloning) the value. A NoCopy value that is read from a variable or a member of one where a copy would be made (an argument, an initializer, an assignment, a field or an element of a literal) is moved without move:

a := Array[int]{1, 2, 3}

print(compute_sum(a))   -- Same as `compute_sum(move a)`.
print(a.len())
--> error: `a` was moved at 3:19. Borrow it with `&a` or clone it to use it here.

In this case, the Array value is moved into the compute_sum function, so the Array is deinitialized by the callee function and not the callsite. A copyable value is still copied unless move is written.

A variable is moved in the block that declares it, or in a branch inside that block: a branch of an if statement or expression, of an if unwrap statement or a case of a switch statement or expression. A begin: block moves it like the block around it. After the statement the variable is dead. The branches that do not move it, and the implicit else when there is none, deinitialize it at their end, so @deinit can run before the end of the block:

f := open_log()!
if verbose:
    archive(f)          -- Moves `f`.
-- Without `verbose`, `f` is deinitialized here, at the end of the implicit `else`.
print('done')

A branch that moves a variable and then assigns to it leaves it alive, like a branch that did not move it. A branch can move only a whole variable of an outer block, not a member of it.

A loop body can move a variable that is declared outside the loop where it then leaves the loop with return or break, or where it assigns to the variable again before the next iteration:

buf := Array[int]{}
for items |it|:
    if it.last:
        send(buf)       -- Moves `buf`.
        break
    buf << it.value
-- `buf` is dead here. When the loop ends without that `break`, `buf` is deinitialized at the end of the loop.

After a break that follows a move, the variable is dead after the loop. The other ways out of the loop (its end, a break that moved nothing, a break that moved other variables) deinitialize it. A body that goes on to the next iteration after the move is an error at the move, because the next iteration reads the variable: 'Cannot move f here: it is declared outside the loop, and the next iteration reads it. A loop body can move it where it then leaves the loop with break or return, or gives it a value again. Borrow it with &f.'

The condition of a while loop is evaluated before every iteration, so it can not move a variable that is declared outside the loop. Neither can the option of while opt |v|: (a NoCopy option in a variable would be moved by the first iteration): 'Cannot move x in the condition of a while loop: it is declared outside the loop, and the condition is evaluated before every iteration. Borrow it with &x, or write while: and move it in the body where the body then leaves the loop with break or return.'

The each variable and the index of a for loop belong to one iteration. The body can move them:

for names |name|:
    keep(move name)

The body of a try statement and its else block move a variable of an outer block too. A variable that the body moved before a ! that can fail is dead in the else block, and a variable that either way through the statement moved is dead after it. The ways that did not move it deinitialize it: a failing ! before it leaves the body, the body or the else block at its end.

buf := Array[int]{}
try:
    n := read_into(&&buf)!      -- When this fails, `buf` is deinitialized before the `else` block runs.
    send(buf)                   -- Moves `buf`.
    flush()!
else |err|:
    print(err)                  -- `buf` is dead here.
-- `buf` is dead here.

The body of a scope block moves a variable in the same way as the body of a try statement: a ! that fails before the move deinitializes the variable, and after the block it is dead. The name of the block itself does not move ('Cannot move s: it is the scope of a scope block, which joins its fibers at the end of the block. Borrow it with &&s.'), and a variable that a fiber of the block borrows is borrowed until the block ends.

An assignment gives a moved variable a value again. The right side can move the variable that the statement assigns, and then a loop body or any other block can do it too, because the variable is alive when the statement ends:

acc := Array[int]{}
for 0..3 |i|:
    acc = step(acc, i)      -- Moves `acc` into `step` and assigns the result. No value is deinitialized.

take(acc)
acc = Array[int]{}          -- `acc` was moved, so there is no old value to deinitialize.

A variable that was moved before the statement gets a value in the block that declares it, or in the block that moved it (a branch or a loop body that moves a variable and then assigns to it). In another block the paths would differ: 'Cannot assign to acc here: it was moved at 5:6 and it is declared in an outer block. Assign to it in the block that declares it, or declare a new variable.' The right side that moved a variable of an outer block can not leave the statement with break, continue or a failing ! inside a try block ('Cannot leave the assignment to acc here: ...'), since the variable would be read after that. return can. In the REPL a top level variable that was moved is declared again with :=, not assigned.

The condition of an if statement or expression and the option of an if unwrap statement always run, so they move a variable like a statement of the block (if take(f) > 0:). So does the option of ?else (o ?else default moves a NoCopy option out of o). So does the left operand of and and or (ok := take(f) and ready). A part of an expression that is evaluated conditionally does not move a variable: the right operand of and and or, and the default and the block of ?else and !else report 'Cannot move f inside an and expression: a part of the expression is evaluated conditionally. Borrow it with &f, or move it to a variable in a statement before this one.' The condition of an else branch reports 'Cannot move f in the condition of an else branch: the condition is evaluated conditionally. Move it inside the branch, or borrow it with &f.'

Values can be partially moved if a subset of its members were moved:

type Foo:
    a int
    b str

f := Foo{a=123, b='abc'}
b := move f.b
print(f.a)
--> 123

The remaining members stay accessible and are deinitialized when the variable goes out of scope. A moved member can not be accessed again (Member is no longer alive.). Members of a nested struct member can be moved one by one as long as the nested type has no custom @deinit:

type Inner:
    s str
    t str
type Outer:
    inner Inner
    x str

o := Outer{inner=Inner{s='s', t='t'}, x='x'}
s := move o.inner.s
print(o.inner.t)     -- Ok. Sibling member is still alive.

A type with a custom @deinit is moved as a whole. Moving one of its members is a compile error, since the type can not be partially deinitialized:

type Res:
    name str
fn (&Res) @deinit():
    pass
type Pair:
    a Res
    b Res

p := Pair{a=Res{name='a'}, b=Res{name='b'}}
a := move p.a           -- Ok.
n := move p.b.name
--> error: Cannot move a member out of `Res`. The type has a custom `@deinit`.

A partially moved value can not be used as a whole. Copying it, borrowing it, or moving it is a compile error until it is reassigned (in the same block):

f := Foo{a=123, b='abc'}
b := move f.b
g := f
--> error: Cannot copy a partially moved value.
peek(&f)
--> error: Cannot borrow a partially moved value.
h := move f
--> error: Cannot move a partially moved value.
f = Foo{a=1, b='x'}     -- Ok. `f` is whole again.

Assigning to a moved member revives that member. The old value is not deinitialized since it belongs to its new owner. Once every member is alive again, the value can be used as a whole:

f := Foo{a=123, b='abc'}
b := move f.b
f.b = 'xyz'             -- Ok. `f.b` is alive again.
h := move f             -- Ok. `f` is whole again.

Like reassigning the whole value, a member can only be revived in the block that declared the variable, so the state at the end of the block is known without runtime flags:

f := Foo{a=123, b='abc'}
b := move f.b
if cond:
    f.b = 'xyz'
--> error: Can only assign to a moved member of a variable declared in the same block.

Reassigning a nested struct member while some of its members are moved out deinitializes only the members that are still alive. h := move f is rejected rather than moving the remaining members, because a value of type Foo promises that all of its members are alive. If h received a Foo without b, that promise would be broken for every function h is passed to and every container it is stored in, and the compiler would have to track the missing member at runtime. Filling the hole with a default value is not done either, since it would construct a value the program never wrote. The partial state belongs to the variable f alone and never leaves it. To move the whole value, make it whole first by reassigning it.

^topic

Borrows. #

Borrows are safe references to values that can never escape the stack. Unlike unsafe pointers, a borrow is never concerned with when to free or deinitialize a value since that responsibility always belongs to the value's owner. A borrow is guaranteed to point to an active value because they never outlive the lifetime of the active value.

Borrows grant mutability or read/write access to a value. Multiple borrows can be alive at once as long as there is no exclusive borrow alive at the same time.

A borrow type is denoted as &T where T is the type that the borrow points to. The & operator is used to obtain a borrow to a value:

a := 123
ref := &a
ref.* = 234

print(a)
--> 234

inc(&a)
print(a)
--> 235

fn inc(a &int):
    a.* = a.* + 1

A borrow can not outlive the value it's referencing:

a := 123
ref := &a
if true:
    b := 234
    ref = &b
    --> error: `ref` can not outlive `b`.

A borrow stored in a local variable is alive until the last statement of its block that names the variable. When that statement is a loop or an if, the borrow lives through all of it. A borrow that is only passed as an argument or used inside an expression ends with its statement. A local whose type has a destructor (a struct that holds a borrow and a managed field, a lambda that captures a borrow) keeps its borrow until the end of the block, where the destructor runs. A statement names the variable when the name is in its text, also in a nested block, a lambda, a string or a comment, but not after a . (h.r is a member).

A local that another live local points into keeps its borrows while that local lives, also after its own last statement: a borrow of it (hr := &h), or a value that holds a borrow of a place in it (g := H{b=&w.x} keeps w). Other locals of the block still end after their last statement. After &&h is passed to a function, h can hold a borrow of a place in any local, and every local of the block stays while h lives.

A local that holds a borrow can be borrowed again for one statement. The new borrow can not be kept in another local when it conflicts with the one the first local holds:

type Foo:
    xs []int

f := Foo{xs={1, 2, 3}}
r := &&f
r.xs.append(4)      -- Reborrows `f` through `r` for this statement.
print(r.xs.len())   --> 4
s := &r.xs[0]
--> error: Cannot borrow `f`. There is an active exclusive borrow to it.

Some dynamic data structure types allow borrowing a reference to an inner element:

a := Array[int]{1, 2, 3}
elem := &a[2]
elem.* = 300

print(a)
--> {1, 2, 300}

The element that elem points to can be mutated because the Array guarantees that the address remains stable.

^topic

Exclusive borrows. #

Like borrows, an exclusive borrow also grants mutability to a value. A single exclusive borrow can be alive as long as no other borrows are also alive. Exclusivity can be a useful constraint when invalidating an indirect buffer or value. Since no other borrows are allowed to be alive at the same time, no borrows can become invalidated. Exclusivity also enables no-alias optimizations.

The && prefix operator is used to obtain an exclusive borrow to a value. An exclusive borrow type is denoted as &&T where T is the type that the reference points to.

Array is a type that requires an exclusive borrow for operations that can resize or reallocate its dynamic buffer:

a := Array[int]{1, 2, 3}
invalidate(&&a)

fn invalidate(arr &&Array[int]):
    a << 4
    if arr.len() > 3:
        arr.clear()

Note that invoking the append << and clear methods automatically obtain an exclusive borrow for self without an explicit && operator.

Resize operations such as << and clear require an exclusive borrow because they can potentially reallocate a dynamic buffer, thereby invalidating other borrows. If another borrow is alive when an exclusive borrow is obtained, it is a compile error. A borrow stored in a local ends after the last statement that names it, so the owner can be resized after that:

a := Array[int]{1, 2, 3}
elem := &a[2]
elem.* = 300
a << 4
-- Ok. `elem` is not used after `elem.* = 300`.

elem2 := &a[2]
a << 5
--> error: Expected exclusive access. There is another active borrow to `a`.
print(elem2.*)

append_to(&a[2], &&a)
--> error: Cannot pass an exclusive borrow of `a` with another argument that borrows `a`.

fn append_to(elem &int, arr &&Array[int]):
    arr << elem.*

The same holds for a template function and a generic method (fn f(%T type, r &T, b &&Array[T])).

While an exclusive borrow is stored in a local, no other borrow of the owner can be made, including the implicit &self borrow of a method call:

a := Array[int]{1, 2, 3}
ex := &&a
r := &a
--> error: Cannot borrow `a`. There is an active exclusive borrow to it.
print(a.len())
--> error: Cannot borrow `a`. There is an active exclusive borrow to it.
ex << 4

An exclusive borrow that a local, a parameter or a field already holds is checked again where it is passed on as &&T. It can not be passed on while another local borrows through it. A loop borrows what it iterates until it ends:

type Foo:
    xs []int

fn (&&Foo) grow():
    self.xs.append(0)

fn (&&Foo) each():
    for self.xs |x|:
        print(self.xs.len() + x)    -- Ok. A read.
        self.grow()
        --> error: Expected exclusive access. There is another active borrow to `self`.

fn first(r &&Foo):
    s := &r.xs[0]
    r.grow()
    --> error: Expected exclusive access. There is another active borrow to `r`.
    print(s.*)

Copies of one exclusive borrow (r2 := r) point to the same value and do not conflict with each other. A borrow that is assigned to _ ends with its statement (_ = r.add(1)).

A borrow into one field is no conflict with an exclusive use of another field: inside for self.xs |x|: the body can call self.names.append(x).

An assignment that destructs the old value needs exclusive access too. This is the case when the type of the local, the field or the element is managed (an array, a str, a struct that has such a field). The conflict is a borrow that points into a buffer of the old value, and a loop over it. A borrow of the place itself (&x, &g.xs) stays valid and reads the new value, and so does a borrow of a value that is not managed:

g := Foo{xs={1, 2, 3}}
s := &g.xs[0]
g.xs = {7}
--> error: Expected exclusive access. There is another active borrow to `g`.
print(s.*)

x := 1
c := &x
x = 7
print(c.*)
--> 7

t := 'abc'
p := &t
t = 'zzz'
print(p.*)
--> zzz

A value that contains an exclusive borrow (a struct with an &&T field, ?&&T) keeps exclusive access to the owner like the borrow, and it is checked the same way when it is passed to a function. It borrows from every local that one of its fields borrows, also from a borrow that is assigned to a field later:

type Holder:
    r &&Foo

f := Foo{xs={1, 2, 3}}
h := Holder{r=&&f}
print(f.xs.len())
--> error: Cannot borrow `f`. There is an active exclusive borrow to it.
h.r.grow()

A shared borrow gives no exclusive access to what is behind it. An exclusive borrow that is read through a shared borrow (b.* of b := &r, self.r in a &Holder method) can not be passed on as &&T: 'Cannot use an exclusive borrow that is read through a shared borrow.'

A shared borrow does not replace or change a managed value behind it either. Another shared borrow of the same owner can point into that value:

type Foo:
    xs []int
    n  int

fn (&Foo) grow():
    self.xs.append(1)
--> error: Cannot borrow exclusively through a shared borrow. Declare the borrow as `&&T`.

fn (&Foo) reset():
    self.xs = {}
--> error: Cannot replace a managed value through a shared borrow. Declare the borrow as `&&T`.

fn (&Foo) count():
    self.n += 1       -- A value that is not managed is written in place.

Declare the receiver or the parameter as &&T (fn (&&Foo) grow(), fn fill(out &&[]int)). The call then needs exclusive access: s := &f.xs[0] followed by f.grow() and a later use of s is 'Expected exclusive access. There is another active borrow to f.' The rule also holds for an element (self.items[i].name = 'x') and for a dereference (p.* = {} of p &[]int). It does not hold behind a reference or a pointer (self.node.xs.append(1) of node ^Node), and not in @deinit, which has the only access to the value that it ends.

A borrow can not be an element of a type that keeps its elements in a buffer ([]&int, Array[Holder], a Map of borrows), where its lifetime is not checked. Use an owned type, ^T or a vector [N]T.

A managed value can not be moved while a local borrows from it:

h := move g
--> error: Cannot move `g`. There is an active borrow to it.
^topic

self borrow. #

Methods can be declared to accept borrows or exclusive borrows from the self receiver:

type Foo:
    a int

fn (&Foo) mutate():
    self.a = 123

A &Foo receiver writes the fields that are not managed (int, float, bool, a struct of those). To replace or change a managed field (str, []T, Map, a struct with one), declare the receiver as &&Foo. Choosing a receiver lists what each receiver can do, with the error messages.

Invoking methods automatically attempts to obtain the correct borrow type as specified by the method:

f := Foo{a=1}
f.mutate()
-- Obtain borrow to `f`.
^topic

scope parameter. #

Functions can only return borrows if the scope is bound to a borrow parameter. This is possible with the scope modifier:

fn (scope &FooArray) @index_addr(idx int) -> scope &Foo:
    return &self.inner[idx]

The scope binding informs the callsite that the returned borrow belongs to the same scope as a borrowed argument. This ensures the returned borrow's lifetime does not exceed the lifetime of the borrowed argument. The returned value can not point into a local of the function, also not into a scope parameter that is passed by value (return &w.x). Every branch of the returned value (if, switch, ?else, !else) must borrow from a scope parameter, whatever their order, and the same check applies to ?&T, !&T and borrow containers: return if (k == 1) &p[0] else &y is the compile error 'Expected to return a borrow from the same scope as p.'

Any type that contains a borrow member becomes a borrow container and requires the scope binding:

type FooIterator:
    rec &FooArray
    idx int

fn (scope &FooArray) iterator() -> scope FooIterator:
    return {
        rec = self,
        idx = 0,
    }

A borrow container value lives only as long as the shortest lived local it borrows. Assigning it to a local of an outer block is a compile error:

type Ref:
    p &int

z := 1
var r Ref = Ref{p=&z}
begin:
    y := 2
    r = Ref{p=&y}
--> error: `r` can not outlive `y`.

The same holds when the value is wrapped in an option (var o ?Ref), comes from an if or switch expression or a ?else or !else default, or is assigned to a field or an element (o.r = Ref{p=&y}). A function can not store a borrow of one of its own locals, or of another parameter, behind a parameter: self.r = Ref{p=&y} is the compile error 'The value behind self can not outlive y.' Only a scope parameter can be stored there (fn (&&Outer) set(scope p &int): self.v = View{a=p}), and the caller checks each other borrow argument as if the scope argument were assigned to its field: o.set(&z) is the compile error 'o can not outlive z.' when z ends first.

A borrow that can come from one of several branches (if (c) &y else &a[0]) borrows from the owner of each branch: a can not be modified while the borrow is in use. This holds also when the borrow is stored in a field or an element, or passed as an argument: f(if (c) &y else &a[0], &&a) is a compile error.

A case capture of a switch borrows what the control borrows: a value capture |p| of a borrow payload borrows the value that the control borrows from, and a borrow capture |&v| borrows the local that holds the control. A borrow of a case local can not leave the case: case .one |n| => &n is the compile error 'The result of switch can not outlive n.'

A borrow of a place in a borrow container (&&r, &r.p) points into the container, so it can not outlive the container either, even when the local that the container borrows from lives longer. A copy of a borrow that is read out of a container (p = r.p, p = xs[i], p = r.inner.p, an option field r.o) borrows what the container borrows instead: it can outlive the container, but not the locals that the container borrows, and it keeps all of them borrowed. When the container can hold a borrow of a place in another borrow container (H{b=&w.x}, h.b = &w.x, or after &&h was taken), the copy can not outlive the container. The same holds for a borrow of a place that is read through a borrow of the container (&hr.b of hr := &h), and for a copy of a container that holds a borrow of a place in another container (r = h of h := H{b=&w.x}).

An unwrap capture of if and while (if o |q|:) borrows what the option borrows, like a switch capture: r = q compiles when r does not outlive that owner. A borrow of a capture of a value (r = &q) can not leave the branch.

A vector of borrows ([2]&int) is a borrow container: it lives only as long as the shortest lived local that its elements borrow, and it keeps all of them borrowed. It can be iterated, also through a span (for xs[1..] |p|:), and a capture borrows what the vector borrows. A copy of a borrow container (r = h) keeps all the owners of h borrowed, and it can not outlive any of them, also a borrow that was stored in h after it was declared (h.b = &z). A borrow stored through a borrow (pp.* = &z) is checked like one stored in a field.

Deinitializers. #

When a value is no longer alive, its deinitializer is invoked. Under normal conditions, the procedure follows these steps:

  1. The value's custom @deinit method is invoked.
  2. Performs the deinitialize procedure for any child values (defined as type members).

Custom deinitializers can be declared with a @deinit method:

type File:
    fd int

fn (&File) @deinit():
    C.close(self.fd)

At the end of the program, the locals of the main block are deinitialized first (in reverse declaration order), then the globals. A local's @deinit can still read the globals:

global log Log = Log{}

type Res:
    name str
fn (&Res) @deinit():
    log.write('deinit %{self.name}')   -- `log` is still alive.

r := Res{name='r'}
-- End of program: `r.@deinit()`, then `log.@deinit()`.

Locals of a function are deinitialized when the function returns, before the program ends.

On thread panic, no @deinit is invoked. The runtime sweeps the heap objects and raw buffers that are still alive (memory only) and the operating system reclaims external resources (files, sockets) when the process exits. Embedders that enable single_run in CLEvalConfig get the same sweep instead of the main block's deinitializers, so a script that relies on @deinit for cleanup needs the default single_run = false.

^topic

Shared references. #

Shared references ^T point to objects (values that were allocated on the heap). The usage of shared references has been described in Basic types -> References. This section describes their implementation details and how the runtime manages them.

^topic

ARC. #

Objects in Cyber are reference counted. Each shared reference retains the count upon initialization and releases the count when it goes out of scope. The value that the reference points to is deinitialized and freed when the reference count reaches zero. This is also known as ARC (automatic reference counting).

Shared references are meant to describe a shared dependency to an object when it would be inconvenient to do so through single value ownership. It is not meant to describe a cyclic graph of objects (where there is no clear ownership hierarchy). In fact, reference cycles is a sign of a bug in the program and is reported.

^topic

Retain optimizations. #

Reference counting is not zero-cost. Retaining and releasing an object's reference count is a write operation so the compiler will look for opportunities to keep the book keeping to a minimum. It turns out a significant amount of retain/release ops can be avoided when the lifetime of a reference is known on the stack. For example, passing a reference to a function call doesn't need a retain since it is guaranteed to be alive when the call returns.

^topic

Default allocator. #

Currently, mimalloc is used as the default heap allocator for objects, but it can be swapped with libc malloc or a custom allocator.

^topic

Back references. #

There is no weak reference type, and none is planned: a reference cycle is a bug, not a structure to support. A back reference from a child to its parent can not be a ^T without forming a cycle. Keep an index or a key of the parent instead, or pass the parent to the function that needs it.

^topic

Cycle detection. #

When shared references form a reference cycle, it's considered a runtime error. Cycle detection is dispatched at the end of a thread. The thread will panic if a cycle is detected which subsequently begins the runtime's fatal deinitialization procedure.

^topic

Manual memory. #

Memory can be managed by hand with pointers. This memory is not tracked: the compiler and the runtime do not check its lifetime or its bounds.

^topic

Pointers. #

See FFI / Pointers.

^topic

Memory allocations. #

alloc allocates memory with the default allocator and free returns it. Both are unsafe. alloc(T) returns a Ptr[T] to one value and alloc(T, n) returns a PtrSpan[T] of n values. The memory is not initialized:

p := alloc(int)
p.* = 5
print(p.*)         --> 5
free(p)

s := alloc(int, 4)
s[0] = 3
print(s[0])        --> 3
print(s.len())     --> 4
free(s.ptr)

A negative length panics, and a length of zero returns an empty span without an allocation. free does not run a @deinit, and using the memory after free is undefined.

An embedding host can reject raw pointers in scripts with the deny_raw_ptrs compile option (see Denying raw pointers).

Errors. #

An error is copyable value that should be handled at the call site or bubbled up.

^topic

error literal. #

An error value can be constructed from an error literal:

err := error.Oops

error values can be compared using the == operator:

if err == error.Oops:

An error value holds only its name, and it does not carry a payload. To return details with a failure, return a struct or a choice type that describes it, or fill a value that the caller passes in, as the standard modules do with a Diag (json.parse(s, &&diag)).

Results. #

A result value forces the call site to unwrap it in order to use the payload.

A result type is a choice type that holds either an error or a payload. It is denoted as !T where T is the payload type.

It can be constructed by inferring an error or a payload value:

var res !str = error.Failed

res = 'abcxyz'

In practice, results are typically constructed when returning from a function:

fn compute(input int) -> !int:
    if input == 42:
        return error.WhyPick42

    return fib(input)

A function that can fail but has no payload would return !void:

fn validate(name str) -> !void:
    if name.len() > 64:
        return error.NameTooLong
^topic

Unwrap or rethrow. #

The ! postfix operator unwraps a result's payload or rethrows the error:

data := os.read_file('data.txt')!

In the main block, the rethrow case would result in a thread panic. Inside a try block, the rethrow case jumps to the block's else instead.

If the unwrap expression is inside a function, the rethrow case would bubble up the error to the caller. This suggests that the function must have a !T (or error) return type:

fn content_length(path str) -> !int:
    data := os.read_file(path)!
    return data.len()

In a function that returns another type, ! is a compile error that names the return type and the two fixes: declare it -> !T, or handle the error in place with !else or a try block.

.! unwraps a choice case (s.!line), not an option or a result. x.! with no case name is a parse error that names .? for an option and f()! for a result.

A result can not be printed before it is unwrapped. print(os.read_file(path)) and '%{os.read_file(path)}' are compile errors that say to unwrap it with ! or to handle the error. Generic code (a %T parameter that is a result) prints the payload or the error.

^topic

Unwrap or default. #

The !else expression either unwraps a result's payload or defaults to a value:

res := do_something() !else 0

The default case can be implemented in a block:

res := do_something() !else:
    panic('Failed.')

The error value can be captured:

res := do_something() !else |err|:
    panic('Failed with %{err}')

Like ?else, one return, break or continue can follow on the same line without ::

n := int.parse(s) !else return 0
data := os.read_file(path) !else |err| return err

An !else block can not reach its end. It must end with return, panic, break or continue. To continue after handling the error, use the unwrap block.

^topic

Unwrap or guard. #

An !else block that captures the error is a guard: it handles the failure and leaves the function, and the code after it sees the payload:

fn load(path str) -> !Config:
    data := os.read_file(path) !else |err|:
        eprint('Can not read %{path}: %{err}')
        return err

    return parse(data)

The block can return another error or a value of the function's return type. In a loop it can end with break or continue. There is no separate guard statement.

^topic

Unwrap block. #

Sometimes it can be useful to handle every rethrow in a block at one place. A try block runs its body, and when a ! in the body meets an error, execution jumps to the else block with that error instead of rethrowing or panicking:

try:
    res := do_something()!
    do_even_more_things(res)!
    validate(res)!
    print('Success.')
else |err|:
    print('Failed with %{err}.')

Only the ! operator in the body is redirected. !else, return error.X, a Result value that is not unwrapped, and panics keep their meaning. Since errors are values, nothing is thrown at runtime: the compiler lowers the block to a branch on each !.

The capture |err| is optional and has the type error. When the body reaches its end, the else block is skipped. Both paths continue after the try statement, so unlike an !else block, the else block does not have to end with return or panic:

var count int = 0
try:
    count += parse(a)!
    count += parse(b)!
else:
    count = -1
print(count)

The body is its own scope: variables declared in it are not visible after the block, and they are destructed before the else block runs when a ! fails. In a function, a ! inside a try body does not require a Result return type:

fn content_length(path str) -> int:
    try:
        return os.read_file(path)!.len()
    else:
        return 0

Nested try blocks are resolved from the inside out. A ! inside the else block belongs to the enclosing try, or to the function when there is none. A lambda declared in the body has its own rules: its ! follows the lambda's return type.

An expression lambda without a declared return type (fn(x str) => expr, |x| expr) takes its return type from its body. A ! in the body that leaves the lambda makes the return type !U, where U is the type of the body: fn(x str) => int.parse(x)! is a fn(str) -> !int, the same as the declared fn(x str) -> !int => int.parse(x)!. A body that is a !T or an error already keeps its type. For a function type that infers its result (f fn(T) -> %U), U is bound to that type: map(items, |x| int.parse(x)! * 2) returns a []!int. A return in the body (in an !else: block) returns the type of the body, and its value is checked against that type: fn(x str) => int.parse(x) !else: with return 0 in the block is a fn(str) -> int.

^topic

Panics. #

The builtin panic is a fail-fast mechanism to quickly exit the current thread with an error message:

panic('oops')

Panics can not be caught. Once panic is invoked, the current thread stops execution and begins to unwind its call stack. Afterwards, the thread can not be used and transitions to a panic state. If the main thread panics, then the program aborts without unwinding other child threads.

A panic of a spawned thread reaches the thread that awaits its Future: await panics with Spawned thread panicked: . A parent thread can not query the status of a child thread in another way.

A panic reports the stack trace automatically to the console.

^topic

Stack traces. #

The builtin stack_trace() and stack_trace_info() are used to obtain the stack trace info at any point in the program:

fn some_nested_func():
    -- Prints the stack trace summary.
    print(stack_trace())

    -- Provides structured info about the stack trace.
    info := stack_trace_info()
    print(info.frames.len())

Overview. #

Cyber has three units of concurrency. They differ in what they share and in who decides when they run:

A Future is the result of work that is not done yet, and await is the one way to wait for it. What await does depends on where it is called: in the main block and in a spawned thread it blocks, and inside a fiber it suspends only that fiber.

Threads do the CPU bound work and fibers keep several waits in progress on one thread. A scope block starts a group of fibers and ends when all of them are done:

fn fib(n int) -> int:
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

fn compute(n int, out &int) -> !void:
    -- The fiber is suspended while the thread computes.
    out.* = spawn fib(n).await()

fn main() -> !void:
    a := 0
    b := 0
    scope |s|:
        s.start(compute, {20, &a})
        s.start(compute, {25, &b})
    -- Both threads ran at the same time and both fibers are done here.
    print('%{a} %{b}')     --> 6765 75025

Threads. #

Threads are light-weight virtual threads that have their own execution context and heap memory. The program can spawn many threads but only some of them can run in parallel depending on the operating system and the number of CPU cores.

Threads are isolated from one another and can communicate by message passing or by sharing memory safely.

^topic

Spawn threads. #

spawn followed by a function call creates and starts a new thread. The arguments are evaluated and sent now, and the function is called on the new thread:

task := spawn fib(40)

fn fib(n int) -> int:
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

spawn takes the first call only, so spawn fib(40).await() waits for the thread, like (spawn fib(40)).await(). A prefix operator takes the whole term: -spawn fib(40).await() is -(spawn fib(40).await()). fiber is read the same way.

The entry point can be a lambda in a variable. It can not capture variables, because a closure is not Sendable:

inc := fn(n int) -> int => n + 1
print(spawn inc(3).await())    --> 4

A method is named through its type, with the receiver as the first argument: spawn Job.run(job). spawn job.run() is a compile error, and so is an entry function that takes a borrow (&T): the arguments are sent to the new thread.

spawn returns a Future[T] where T is the return type of the entry function. If the runtime could not dispatch the thread, a panic is raised. The Future contains the asynchronous result of the new thread. A thread can not be stopped from the script and its status can not be queried. The Future is the only handle to it. The result stays in the heap of the spawned thread until await copies it to the awaiting thread. A Future that is dropped without await frees the spawned thread and its result when the thread ends. The thread still runs to its end, also when it had not started yet: _ = spawn log(msg) runs log. Threads that are still running or queued when the program ends are stopped.

^topic

Sendable values. #

Values that can be transferred from one thread to another must be types that implement Sendable.

The arguments of spawn and the return value of the entry function are sent. These types can be sent:

  • Integers of any width: int, i8, i16, i32, byte, r16, r32, r64.
  • bool, float, f32, symbol, error and enums.
  • str. The string is copied to the receiving thread.
  • A struct that declares a @send method.
  • A struct without references is sent as its bytes.
  • ?T and !T if T can be sent.

Sending another type is a compile error: Expected sendable: []int. An option or a result is sent when its payload can be sent: ?str and !str are sent with the @send of str, and ?[]int is a compile error: Expected sendable: ?[]int. The arguments and the result follow the same rules.

A struct is sent with its @send method. It receives the thread that the value is sent to and returns the value for that thread:

type Point:
    x int
    y int

fn (&Point) @send(dst Thread) -> Point:
    return Point{x = self.x, y = self.y}

fn sum(p Point) -> int:
    return p.x + p.y

print(spawn sum(Point{x = 1, y = 2}).await())    --> 3

These types are not Sendable yet: Planned Feature

  • []T if T is Sendable. []T is cloned when sending.
  • Array[T] if T is Sendable
  • Map[K, V] if K and V are Sendable
  • [N]T if T is Sendable
  • [..N]T if T is Sendable
  • Composite types if all member types are Sendable.
  • Choice types if all member payload types are Sendable.
  • Function pointers.
  • Ptr[T].

Types that don't implement Sendable include:

  • Reference types: ^T, &T, &&T, [&]T.
  • Function unions. (Closures are not Sendable)
^topic

Worker threads. #

Spawned threads run on a pool of operating system threads that belongs to the VM. A worker is started when a thread is spawned and no worker is idle, up to one less than the number of CPU cores. A spawned thread that no worker picks up stays queued, and a thread that waits in await runs the queued threads itself.

The WebAssembly builds have no threads: spawn is not available there and stops the VM. Fibers, scope blocks and generators work on every target.

There is no API to create or to name an operating system thread from a script.

^topic

Growable stacks. #

When running on Cyber's VM, threads can grow their stack on demand. The compiler generates pointer layouts that tells the runtime where pointer values are so they can be patched with new addresses.

Growable stacks allow threads to be lighter. They can be initialized with a smaller stack and grow on demand.

A fiber has a growable stack of its own.

^topic

Fuel and interrupts. #

A script can not limit its own run time. The host that embeds the VM can: it gives an eval a number of checkpoints (loop back edges and calls) as fuel, or it interrupts the eval from another thread. See Limiting an eval.

A spawned thread that was interrupted or ran out of fuel interrupts the thread that awaits it.

^topic

Futures. #

A Future is an asynchronous result type. It represents the result of work that will either complete or fail at some point in the future. This abstraction allows the current thread to continue execution without waiting for the completion of the Future.

Futures can represent asynchronous work that is run in parallel or on a single thread. I/O bound work can be delegated to the operating system and CPU bound work can be run across multiple threads. A Future is not concerned with how the work is accomplished.

spawn returns a Future, and so does a host function that answers later:

work := spawn fib(30)
-- `work` is a `Future[int]`. The main block continues while `fib` runs.
print(work.await())    --> 832040

There is no asynchronous I/O module yet: the functions of os and io block the thread that calls them.

Futures can be created with a completed value:

work := Future.complete(100)
print(work.await())
--> 100

A Future is a reference to a shared result. A copy of it waits for the same result.

^topic

Future await. #

Future.await() asynchronously waits for a Future to complete.

await blocks the current thread until the Future completes. It can be called from the main thread and from spawned threads. While a thread waits, it runs other spawned threads that are still queued, so waiting on nested spawn calls does not deadlock the worker pool.

If the spawned thread panicked, await panics with Spawned thread panicked: . If the spawned thread was interrupted or ran out of fuel, the waiting thread is interrupted too.

A future that no spawned thread completes (one from a host function, or from FutureResolver before complete) can only be completed from outside the running program. Awaiting it on the main thread suspends the whole program and returns to the host, which completes the future and resumes the program at the await (see Suspending an eval). This works at any call depth and in a generator body. Inside a fiber the await suspends the fiber instead (see Fibers). The cyber command completes no futures, so there the program ends with panic: Abandoned while awaiting a future. A spawned thread can not wait for such a future, and neither can a function that a host function called: both panic.

When await returns, the expression evaluates to the completed value of the Future:

a := spawn fib(20)
b := spawn fib(25)
print(a.await() + b.await())    --> 81790

await can be used in any function which makes asynchronous functions colorless. They do not need a special function modifier. This means that asynchronous work can be wrapped in a synchronous API.

^topic

Waiting for the first future. #

Future.wait_any waits for the first of several futures and returns its index in the list. When several are done it returns the first of them in the list. The future at that index does not wait when it is awaited:

futs := []Future[str]{tool_async('a'), tool_async('b'), tool_async('c')}
i := Future.wait_any(futs.span())
print(futs[i].await())

Futures of spawned threads are waited for inside the VM. When none of the futures belongs to a spawned thread, the program is suspended until the host completes one of them (see Suspending an eval). An empty list panics.

The futures of one call have the same type T.

^topic

Resolving futures. #

A FutureResolver produces a Future and completes it later. FutureResolver.new takes the type of the value, future returns the Future, and complete sets the value:

r := FutureResolver.new(int)
f := r.future()

r.complete(234)
print(f.await())    --> 234

The resolver is not Sendable, so it completes a future for a fiber of the same thread. A host function can return such a future and complete it later (see Suspending an eval).

^topic

Fibers. #

A fiber is a cooperative execution context that belongs to a thread. It has its own stack and shares the thread's heap. A fiber waits and gives up control. It carries no value: use a generator to produce values.

^topic

Creating fibers. #

fiber in front of a call creates a Fiber. The arguments are evaluated at once and the function is called at the first resume:

fn two_steps(name str):
    print('%{name}: first')
    suspend
    print('%{name}: last')

f := fiber two_steps('a')
print(f.status())      --> FiberStatus.suspended

_ = f.resume()         --> a: first
_ = f.resume()         --> a: last
print(f.status())      --> FiberStatus.done

fiber takes the first call only: fiber f(x).resume() resumes the new fiber.

Each fiber starts with a stack of 512 bytes that grows on demand like the thread's stack. A spawned thread can create fibers of its own.

^topic

suspend and resume. #

suspend gives control back to the resume call that is running the fiber. It takes no value and it can be used at any call depth, in a function of any signature:

fn crunch(data ^ArrayStore[int]) -> int:
    sum := 0
    for data |x|:
        sum += x
        if sum % 4096 == 0:
            suspend
    return sum

Outside of a fiber, suspend does nothing.

resume returns .suspended when the fiber suspended and .done when its function returned. Resuming a fiber that is done returns .done again. status returns .suspended, .running or .done. A fiber that resumed another fiber is .running until the other one gives control back.

A generator can be consumed inside a fiber, and suspend in a generator body suspends the fiber that consumes the generator. The generator stays .running until that fiber is resumed.

^topic

Sharing state. #

Fibers interleave on the same heap. Share state with a ^T reference:

fn worker(name str, log ^ArrayStore[str]):
    for 0..2 |i|:
        log << '%{name} %{i}'
        suspend

log := ^ArrayStore[str]{}
a := fiber worker('a', log)
b := fiber worker('b', log)
while a.status() != .done or b.status() != .done:
    _ = a.resume()
    _ = b.resume()
--> log: a 0, b 0, a 1, b 1

A fiber of a scope block can borrow a value instead (see Scope borrows).

^topic

fiber blocks. #

fiber: takes a body instead of a call. The body is a closure, so it captures variables that are declared with a reference type:

log := ^ArrayStore[str]{}
t := fiber:
    log << 'step 1'
    suspend
    log << 'step 2'

_ = t.resume()         -- log: step 1
_ = t.resume()         -- log: step 1, step 2
^topic

Fiber entry rules. #

The rules of a fiber entry are checked at the fiber expression:

generator fn countdown(n int) -> int:
    yield n
f := fiber countdown(3)    --> CompileError: A generator cannot be a fiber entry.

fn one() -> int:
    return 1
f := fiber one()           --> CompileError: A fiber entry function must return `void`.

fn bump(n &int):
    n.* += 1
n := 1
f := fiber bump(&n)        --> CompileError: Cannot borrow a stack value across fibers. The parameter type is `&int`. Use `^T`.

suspend 1                  --> ParseError: `suspend` takes no value. Use `yield` in a generator.

The arguments are copied into the call at the first resume, so a parameter of a fiber entry can not have a NoCopy type.

A method is a fiber entry through its type, with the receiver as the first argument. A method call on a value is not an entry:

type Job:
    n int

fn (^Job) work(by int):
    self.n += by
    suspend
    self.n += by

job := ^Job{n=0}
f := fiber Job.work(job, 2)
_ = f.resume()
print(job.n)               --> 2
g := fiber job.work(2)     --> CompileError: A fiber entry cannot be a method call on a value. Pass the receiver as the first argument: `fiber T.work(obj)`.

The receiver follows the rules of a parameter, so a method with a &T receiver can not be a fiber entry.

^topic

await in a fiber. #

Future.await() inside a fiber does not block. When the future is not done, the fiber is suspended and resume returns .suspended, so the other fibers can run. Future.wait_any inside a fiber behaves the same way. A fiber that waits is not entered by resume: it returns .suspended at once until the future is done. waiting tells such a fiber apart from one that stopped at suspend:

fn waiter(fut Future[int], out ^int):
    out.* = fut.await()

r := FutureResolver.new(int)
out := ^0
w := fiber waiter(r.future(), out)
print(w.resume())     --> FiberStatus.suspended
print(w.waiting())    --> true
r.complete(7)
print(w.waiting())    --> false
print(w.resume())     --> FiberStatus.done
print(out.*)          --> 7

In the root context, outside of any fiber, await waits as before.

^topic

Waiting for fibers. #

A loop that resumes fibers calls Fiber.wait_ready() when every fiber waits. It blocks the root context until a future that a suspended fiber awaits is done and returns true. It returns false at once when no fiber awaits a future:

fn fetch(name str, n int, log ^ArrayStore[str]):
    res := spawn compute(n).await()
    log << '%{name}: %{res}'

log := ^ArrayStore[str]{}
a := fiber fetch('a', 2000000, log)
b := fiber fetch('b', 10, log)
while a.status() != .done or b.status() != .done:
    _ = a.resume()
    _ = b.resume()
    if a.waiting() and b.waiting():
        _ = Fiber.wait_ready()

Both computations are started before either result is taken. A loop that resumes fibers needs Fiber.wait_ready(): without it the loop spins while the fibers wait, and it does not end when nothing else completes the futures. That is the case on a machine without spare worker threads, where the waiting root context runs the spawned tasks itself, and for futures that only the host can complete. For those, Fiber.wait_ready() suspends the program and the host sees the futures of all fibers (see Suspending an eval). Called inside a fiber, Fiber.wait_ready() suspends that fiber until a future is done that one of its own fibers awaits: a fiber that it resumed last or asked waiting() about last, or a fiber of one of those. A future of a fiber that another fiber runs does not end the wait, and the call returns false at once when none of its own fibers awaits a future.

A scope block does this loop itself.

^topic

Fiber panics. #

When a fiber panics, the thread panics and all of its fibers are terminated. The stack trace continues at the resume call of each fiber down to the main block.

A fiber can not resume itself or a fiber that is waiting for it:

--> panic: Fiber is already running.
^topic

Structured concurrency. #

Structured concurrency ties the lifetime of a group of fibers to a block of code. The fibers are started in the block, and the block is not left before all of them are done. A failure of one fiber ends the others, and the error leaves the block like any other error.

^topic

scope block. #

A scope block runs a group of fibers and does that loop itself. The name between the bars is a Scope that lives for the block. start adds a fiber: the arguments are evaluated at once, and the fibers run when the body is done. A fiber that stops at suspend gives the others a turn, a fiber that awaits a future runs again once the future is completed, and when every fiber waits for a future the block waits like Fiber.wait_ready():

fn fetch(name str, n int, log ^ArrayStore[str]) -> !void:
    res := spawn compute(n).await()
    if res < 0:
        return error.Negative
    log << '%{name}: %{res}'

fn fetch_all(log ^ArrayStore[str]) -> !void:
    scope |s|:
        s.start(fetch, {'a', 2000000, log})
        s.start(fetch, {'b', 10, log})
    -- Both fibers are done here.
    log << 'done'

The fibers of a scope do not outlive the block:

  • When the body reaches its end, the block waits until every fiber is done.
  • return, break and continue leave the block after the fibers are done. The result of return expr is evaluated after that, so it sees what the fibers did.

Blocks can be nested, and a fiber of a scope can have a scope block of its own.

^topic

Scope errors. #

The entry function of a fiber returns void or !void. An error ends the whole group:

  • When a fiber returns an error, the other fibers are cancelled and the error leaves the block like a failing !: the function returns it, or it goes to the else block of an enclosing try, or it panics at the top level. The fibers that come after it in the same round are cancelled at once.
  • When a ! in the body fails, the fibers that were started are cancelled and the error goes on the same way.
  • When a fiber returns an error while the block is left with return, break or continue, the error leaves the block instead of the statement.
  • A fiber that can not be cancelled runs to its end instead.
fn slow(log ^ArrayStore[str]) -> !void:
    log << 'slow: start'
    suspend
    suspend
    log << 'slow: end'

fn fail() -> !void:
    suspend
    return error.Failed

fn run(log ^ArrayStore[str]) -> !void:
    scope |s|:
        s.start(slow, {log})
        s.start(fail, {})

log := ^ArrayStore[str]{}
try:
    run(log)!
else |err|:
    print(err)         --> error.Failed
-- log: slow: start

Since an error leaves the block like a failing !, a scope block in a function needs a !T or error return type, or an enclosing try block:

fn run() -> int:
    scope |s|:             --> CompileError: A `scope` block needs a function that returns `!T` or `error`, or an enclosing `try` block. An error of its fibers leaves the block like a failing `!`.
        s.start(work, {})
    return 1
^topic

Scope borrows. #

Because the fibers are done when the block is left, start on the name of the block takes borrows. A fiber can read and write a value of the function that holds the block without a ^T reference:

fn add(out &int, n int):
    suspend
    out.* += n

fn sum() -> !int:
    total := 0
    scope |s|:
        s.start(add, {&total, 1})
        s.start(add, {&total, 2})
    return total           -- 3

The rules follow from the lifetime of the fibers:

  • The borrowed value is declared before the block. A value that is declared in the body is gone before the fibers are done: 'A fiber of the scope block can not borrow inner: it is declared inside the block and is gone before the fibers are done. Declare it before the block.'
  • The borrow lasts until the end of the block, like a borrow that a local of the block holds. While a fiber holds &a, the body can not resize a, and an exclusive borrow &&a is given to one fiber only.
  • The arguments are written as a literal at the call: s.start(func, {&a, 1}).
  • Only the name of a scope block takes borrows. start on any other Scope, including a &Scope that is passed to a function, and fiber f(&a) are compile errors: Cannot borrow a stack value across fibers.
^topic

Scope type. #

The block is built on the Scope type, which can be used directly when the group does not fit a block:

  • Scope.new() returns an empty scope.
  • start(func, {args}) adds a fiber. It does not take borrows.
  • join() -> !void runs the fibers until all are done. It returns the first error after cancelling the others.
  • abort() cancels the fibers that are not done.
  • active() returns how many fibers are not done.
fn work(n int, log ^ArrayStore[int]) -> !void:
    suspend
    if n == 2:
        return error.Two
    log << n

log := ^ArrayStore[int]{}
s := Scope.new()
s.start(work, {1, log})
s.start(work, {2, log})
s.start(work, {3, log})
print(s.active())      --> 3
try:
    s.join()!
else |err|:
    print(err)         --> error.Two
print(s.active())      --> 0
print(log.len())       --> 1

A Scope value that is destructed joins its fibers first, and an error that is left then panics. A fiber that calls join on the scope that is running it panics: The scope is already running its fibers.

^topic

Cancellation. #

Cancellation ends a fiber at the point where it is suspended. It is how a scope ends the fibers that are left after a failure, and it is what happens to a fiber that is dropped before it is done. Threads and generators are not cancelled: a thread runs to its end, and a generator is ended.

^topic

cancel. #

cancel ends a fiber that is not done without running the rest of its function. Every call that the fiber is in returns at once, from the innermost one out, and the values that the calls own are destructed as at a return. No code of the fiber runs after the point where it was suspended, except the @deinit of those values:

type Conn:
    id int

fn (&Conn) @deinit():
    print('closed %{self.id}')

fn query(conn &Conn) -> int:
    suspend                -- Waiting for the reply.
    return 1

fn session(id int):
    conn := Conn{id = id}
    print('rows: %{query(&conn)}')

f := fiber session(7)
_ = f.resume()
print(f.cancel())          --> closed 7
                           --> true
print(f.status())          --> FiberStatus.done

cancel returns whether the fiber is done afterwards. A fiber that was never resumed is ended without the call and its arguments are released. A fiber that is running is not cancelled: cancel returns false and the fiber stays as it is.

A fiber that is suspended inside a @deinit is cancelled too. The @deinit does not run further, like any other function that the fiber is in, and the rest of the value is destructed: its fields, the other elements of the collection it is in, the object of the ^T reference that held it, and the frame of a generator that was ended.

A fiber that is suspended inside the body of a generator is cancelled like any other: the body's values are destructed, the generator is done, and the function that consumes it returns.

A fiber that holds a Scope, or that waits in a scope block of its own, cancels the fibers of that scope when it is cancelled.

^topic

Destructing a fiber. #

A fiber that is destructed while it is in progress is cancelled first, and so is every fiber that its frames hold. A @deinit that the cancel calls runs, and when it stops at a suspend or an await it ends there, like the functions that the fiber was in. The cancel then goes on with the other values:

type Res:
    id int

fn (&Res) @deinit():
    print("deinit %{self.id}")
    suspend
    print('not reached while cancelled')

fn work():
    a := ^Res{id = 1}
    b := ^Res{id = 2}

fn start():
    f := fiber work()
    _ = f.resume()      -- Suspended in the `@deinit` of `b`.

start()                 -- The cancel ends that `@deinit` and releases `a`, whose `@deinit` stops too.
--> deinit 2
--> deinit 1

Code after a suspend or an await in a @deinit does not run when the fiber is cancelled. Put the cleanup that must happen before it.

A fiber that can not be cancelled panics with Fiber is still in progress. when it is destructed.

^topic

Generators. #

Generators are stackless coroutines that are intended to yield values incrementally. A function declared with generator fn returns a Generator[Fn] when invoked. The return type in the signature is the type of the yielded values:

generator fn iterate() -> int:
    yield 123
    yield 456

gen := iterate()
print(gen)
--> Generator[fn()->int]

yield pauses the current generator and returns a value back to the call site of Generator.next.

^topic

Generator rules. #

A generator outlives the call that created it, so its parameters (including a method's receiver) can not be borrow types such as &T, [&]T, ?&T or a struct that holds a borrow. Pass a value or a ^T pointer instead:

generator fn watch(p &int) -> int:    --> CompileError: A `generator fn` can not take the borrow type `&int` as a parameter.
    yield p.*

generator fn watch(p ^int) -> int:    -- OK
    yield p.*

A method can be a generator. The receiver is kept by the generator like any other parameter, so it must be a ^T pointer and not a borrow:

type Bag:
    n int

generator fn (^Bag) items() -> int:
    for 0..self.n |i|:
        yield i

b := ^Bag{n=3}
for b.items() |v|:
    print(v)

A generator can be a function template. As with any function template, [T] parameters are expanded explicitly and %T parameters are inferred from the arguments:

generator fn rep[T Any](x T, n int) -> T:
    for 0..n |i|:
        yield x

generator fn rep2(x %T, n int) -> T:
    for 0..n |i|:
        yield x

for rep[int](1, 3) |v|:
    print(v)
for rep2('a', 3) |s|:
    print(s)

generator is not a reserved word. It is a modifier only when fn follows it, so it can still be used as a name. A hidden generator is written -generator fn, and attributes go before the modifier (#[inline] generator fn). yield outside a generator fn is a compile error.

The #[generator] attribute of earlier versions was removed. It is a parse error that names the replacement: 'The #[generator] attribute was replaced by generator fn.'

^topic

Resuming a generator. #

A generator begins and resumes execution with next which returns the next yielded value as an optional:

while gen.next() |res|:
    print(res)
    --> 123
    --> 456

A generator can also be iterated with for, which resumes it until it is done:

for iterate() |res|:
    print(res)
    --> 123
    --> 456

The current state of a generator can be obtained with Generator.status:

gen := iterate()
print(gen.status())
--> GeneratorStatus.suspended

while gen.next() |res|:
    pass

print(gen.status())
--> GeneratorStatus.done

next returns none once when the function returns: at the end of its body or at a return without a value. After that the generator is .done, and another next panics: Generator is already done.

^topic

Ending a generator. #

end ends a generator that is not done. The values of its body are destructed and the status becomes .done:

gen := iterate()
print(gen.next())      --> 123
gen.end()
print(gen.status())    --> GeneratorStatus.done

A generator that is destructed before it is done is ended the same way.

A generator can not be reset to its entry point. Call the function again for a new generator.

Inline evaluation. #

Inline evaluation is a form of compile-time execution where the code is evaluated as each node in the AST is visited. This can not emulate the entire language but many basic operations can be evaluated and eligible types can be materialized into IR for code generation.

A const declaration evaluates its initializer at compile-time which also evaluates the recursive calls to the fib function:

fn fib(n int) -> int:
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

const fib30 = fib(30)

An expression needs to be wrapped with #{} to perform inline evaluation if it's not already in a compile-time context:

-- Assign pre-computed value to a local.
res := #{fib(30)}

Inside a compile-time body, locals (t := 0), compound assignment (t += 1), for ranges, if, switch and fixed-size vectors (v := [3]int(0), v[i], v[i] += 1) evaluate the same as at runtime. A vector index out of range is a compile error. The operators of the built-in number types give the same value as at runtime: an integer wraps at its width, / truncates, >> is a logical shift, and a narrower integer widens to the type of the other operand. An integer and a float mix as they do at runtime: const r = k * 2.5, const r = 2.5 * k and const t = k == 7.0 work for an integer constant k. Integer / or % by zero is a compile error instead of the runtime panic. Operations the evaluator does not support yet are reported as Unsupported inline eval.

^topic

Inline type creation. #

Types can be created from inline evaluation. Currently, only structs can be created with meta.new_struct:

type MyType[T Any] const: 
    struct_t := type.info(T).!struct
    fields := [struct_t.fields.length]meta.StructField({name='', type=void, offset=0, state_offset=0})
    for 0..struct_t.fields.length |i|:
        field := struct_t.fields[i]
        fields[i] = {
            name = 'myfield' + str(i),
            type = field.type,
            offset = 0,
            state_offset = 0,
        }
    return meta.new_struct(fields, {})

#if inline. #

The #if statement performs inline evaluation on the condition expression and inserts it's child statements if the condition evaluates to true:

fn report():
    #if meta.system() == .windows:
        print('Running on Windows.')
    #else:
        print('Running on %{meta.system()}')

See Conditional compilation for what an #if can hold at the top level of a file.

^topic

#for inline. #

The #for statement iterates at compile-time and inserts it's child statements on every iteration. The following prints the name of every field in the type Foo:

#struct_t := type.info(Foo).!struct
#for 0..struct_t.fields.length |i|:
    #field := struct_t.fields[i]
    print(#{field.name})
^topic

#switch inline. #

The #switch statement evaluates at compile-time and inserts the child statements of the matching case block:

#switch type.info(T):
    #case .struct |struct_t|:
        print('a struct')
    #case .option |option_t|:
        print('an optional')
    #else:
        print('unsupported')

At the top level of a file, the case blocks of #switch and the body of #for can hold declarations and compile-time statements only. A statement that runs is a compile error there:

#switch meta.system():
    #case .macos:
        print('macos')    --> CompileError: Only compile-time statements are allowed in this context.
^topic

switch #for inline. #

A regular switch statement with a #for block can automatically expand all case statements:

switch value:
    #for meta.enum_values(MyEnum) |Tag|:
        case Tag:
            print('value is a %{Tag}')

Conditional compilation. #

Code is compiled conditionally with #if and a condition that is known at compile-time. Only the branch that is taken is analyzed, so the other branch can use declarations that do not exist on the current target:

use meta

fn path_sep() -> str:
    #if meta.system() == .windows:
        return '\\'
    #else:
        return '/'

The meta module provides the conditions:

  • meta.system() returns the target system (.macos, .linux, .windows, ...), meta.cpu() the CPU architecture, meta.endian() the byte order and meta.pointer_width() the width of a pointer in bits.
  • meta.is_vm_target() tells whether the program is compiled for the VM. It is always true: the bytecode VM is the only backend.
  • meta.build_mode() returns the build mode of the compiler, and meta.build_flag(name) and meta.build_option(name) read the options of the build.

At the top level of a file, an #if can only hold compile-time statements such as #c.bind_lib(...) or a compile-time variable. A statement that runs is a compile error: Only compile-time statements are allowed in this context. A declaration (fn, type, use) can not be placed in an #if. Declare one function and select inside its body, as in the example above.

Runtime execution. #

The cy module provides an API to libcyber.

cy.eval evaluates source code in an isolated VM:

use cy

res := cy.eval('''
fn main() -> int:
    return 1 + 2
''')!
print(res)
--> 3

Isolated means that the new VM prints where this VM prints and has none of its other settings. It imports the modules of the library (core, meta, math, cy, c, io, test, time, json, peg, regex, toon, path) and nothing that the host's loader adds: not os, not a file. cy.VM() creates such a VM for more than one eval, and cy.repl(read_line) runs a REPL session in one.

Who makes a VM decides what it can import. The CLI has cli.new_vm(), a VM that imports what a script run by cyber imports. cy.REPL.new(vm) runs a REPL session in a VM that the caller made:

use cli

print(vm.value_desc(res.val_t, res.value))
--> `str` '/home/user/project'

A host that embeds the library gives its own modules to a session the same way: a function that it binds sets the resolver and the loader of the new VM (VM.inner is the CLVM*) before the VM goes to cy.REPL.new(vm).

Generic types. #

Generic types are type constraints for parametric polymorphism. They aren't concrete types themselves but rather a placeholder that constrains an input type. They are used in template parameters and generic function parameters.

The Any type is a generic type that has no constraints, allowing any type:

type MyContainer[T Any]:
    inner T

Traits are considered generic types and constrain types to those that implement its interface:

type Shape trait:
    fn area() -> float

fn less(a Shape, b Shape):
    return a.area() < b.area()

When a function parameter contains a generic type, the function becomes generic. The function is then specialized by the call site arguments.

A type template is not a generic type: fn size(c MyContainer) is a compile error. Use an inferred parameter instead, which also works when the template is composed (?MyContainer[%T]):

fn size(c MyContainer[%T]) -> int:
    return type.size(type.of(c))

Reading input. #

The os module reads stdin, whether it is a terminal where someone types or a pipe (cat data.txt | cyber app.cy). os.input(prompt) prints the prompt without a line break and reads a line. Like read -p of a shell, it prints the prompt only when stdin is a terminal: a pipe is not asked, and the output stays clean for the next program. os.read_line() reads a line without a prompt. Both return the line without its line break (\n or \r\n), and none at the end of the input: when a pipe or a file runs out, or after Ctrl-D (Ctrl-Z and Enter on Windows) at a terminal:

use os

name := os.input('Name: ')! ?else 'stranger'
print('Hello, %{name}.')

while os.input('> ')! |cmd|:
    if cmd == 'quit':
        break
    print('you typed `%{cmd}`')

os.stdin_lines() gives the lines for a for loop, whose else |err|: block handles an error. os.read_stdin() returns the rest of the input as one string:

-- cat names.txt | cyber upper.cy
for os.stdin_lines() |line|:
    print(line.upper())
else |err|:
    eprint(err)

os.read_password(prompt) reads a line without showing what is typed when stdin is a terminal. The terminal is set back when the line is read, and also when Ctrl-C ends the program. From a pipe it reads a line as input does, without the prompt. os.stdin().is_terminal() tells a terminal from a pipe or a file, and os.stdout().is_terminal() whether the output is shown or goes on to another program.

Stdin is one stream for the whole process. Every read of it goes through one buffer, so read_line, input, stdin_lines, read_stdin and the File methods of os.stdin() (read, read_line, read_all) can be used one after another without losing input. close() of os.stdin(), os.stdout() or os.stderr() leaves the stream open. While a script waits for input on Linux or macOS, the host can stop it (cl_vm_interrupt). A line can be as long as memory allows. For a file other than stdin, File.read_line() reads one byte at a time so that it consumes nothing past the line. To read many lines of a file, use io.Scanner(&file).next_line().

Running programs. #

os.cmd makes a command: a program and its arguments. A Cmd is a value. Its methods return a new command, and nothing starts until run, read or run_status is called:

use os

-- The stdout of a program.
branch := os.cmd({'git', 'rev-parse', '--abbrev-ref', 'HEAD'}).read()!.trim()

-- A pipe joins the stdout of one program to the stdin of the next.
top := os.cmd({'du', '-sk', dir}).pipe(os.cmd({'sort', '-rn'})).read()!

-- A working directory and an environment variable. The output goes to the terminal.
os.cmd({'make', 'test'}).dir('build').env('CI', '1').run()!

-- Text for stdin. `run_status` returns the exit code instead of an error.
res := os.cmd({'grep', '-c', 'TODO'}).stdin(text).run_status()!
if res.code != 0:
    eprint(res.err)

-- Files for the streams, and a time limit in milliseconds.
os.cmd({'make'}).stdout_file('build.log').stderr_append('errors.log').timeout_ms(60000).run()!

There is no shell. An argument reaches the program as it is, with its spaces, quotes and $, so a file name or other text from outside can not turn into more arguments or another command. The list of arguments is built like any list: os.cmd([]str{'grep', '-n', pattern} + files).

MethodStarts the command and
run() -> !voidwaits for it. stdin, stdout and stderr are those of this process.
read() -> !strreturns the stdout of the last program. stderr is that of this process.
run_status() -> !ExecResultreturns the stdout of the last program, the stderr of all programs and the exit code (out, err, code).

run and read return error.ExitStatus when a program ends with an exit code other than 0 or is stopped by a signal. With run_status that is not an error: code is 0 when every program succeeded, otherwise the code of the last program that failed (128 plus the signal number for a signal). A pipeline fails when any of its programs fails. A program that is stopped because the next one closed its input, like yes in front of head -1, succeeded.

A program that can not be started is an OS error from all three: error.NotFound for a missing program or working directory, error.PermissionDenied, and error.InvalidArgument for an empty list of arguments. Captured output is limited to 10 MiB for stdout and for stderr: more is error.TooBig and the programs are stopped. A pipeline has at most 16 programs.

dir(path) and env(name, value) apply to the programs that the command has when they are called, so a.dir('x').pipe(b) runs only a in x. In a.pipe(b) the input is that of a: text that stdin gave to b is not used. A program gets the environment of this process as it is when the command runs, with the variables of env on top. stdin(text) gives the first program its input. Without it, read and run_status give an empty input.

MethodSends
stdin_file(path)the file to the stdin of the first program, in place of the text of stdin.
stdout_file(path), stdout_append(path)the stdout of the last program to the file, which is emptied or added to.
stderr_file(path), stderr_append(path)the stderr of the programs that the command has so far to the file.
stderr_to_stdout()the stderr of the programs that the command has so far where their stdout goes, like 2>&1: into the pipe to the next program, into what read or start reads, into the file of stdout_file, or to the stdout of this process.

The files are opened when the command runs, before any program starts. A relative path is relative to the working directory of this process, not to that of dir. A file that can not be opened is an OS error like a program that can not be started. In a.pipe(b) the stdout is that of b. A stream that goes to a file is not in the result of run_status, and read of a command whose stdout goes to a file is error.InvalidArgument. Programs that send stderr to the same file write to it together.

timeout_ms(ms) stops the programs (SIGKILL, TerminateProcess) when the command has run for ms milliseconds, and run, read and run_status return error.TimedOut. The programs that a program started itself are not stopped. In a.pipe(b) the limit is the shorter one. A limit that is not over 0 is error.InvalidArgument. When the host of an embedded VM asks it to stop (cl_vm_interrupt), a running command stops its programs too.

start() starts the command and returns it while it runs, as a Process, to read the stdout of the last program while it is written:

p := os.cmd({'tail', '-f', 'app.log'}).timeout_ms(60000).start()!
while p.read_line()! |line|:
    if line.contains('ready'):
        break

JSON and TOON. #

The json module parses and writes JSON (RFC 8259). The toon module encodes and decodes TOON (spec v4.4), a line-based form of the same data that takes fewer tokens in an LLM prompt. Both use json.Value:

use json
use toon

v := json.parse('{"users": [{"id": 1, "name": "Ada"}, {"id": 2, "name": "Bob"}]}')!
print(v['users'][1]['name'].as_str().?)   --> Bob
print(json.stringify(v))                  --> {"users":[{"id":1,"name":"Ada"},{"id":2,"name":"Bob"}]}
print(toon.encode(v)!)
--> users[2]{id,name}:
-->   1,Ada
-->   2,Bob
print(json.stringify(toon.decode('tags[2]: a,b')!))   --> {"tags":["a","b"]}

json.Value is a choice: null, bool, int, float, number, str, array ([]Value) and object (json.Object). A number without a fraction or an exponent that fits int parses as int, and another number as float. A number that neither holds without loss, an integer beyond int or a number beyond the float range, parses as number, which keeps its JSON text. json.parse(src, json.ParseOptions{exact=true}) also keeps every number with a fraction or an exponent as number:

v := json.parse('[9223372036854775808, 0.1000000000000000055511151231257827]')!
print(json.stringify(v))            --> [9223372036854775808,0.1]
print(v[0].kind())                  --> number
x := json.parse('[0.1000000000000000055511151231257827, 1.50]', json.ParseOptions{exact=true})!
print(json.stringify(x))            --> [0.1000000000000000055511151231257827,1.50]
print(x[1].number_text().?)         --> 1.5

number_text() returns any number in one form (1.50 and 1.5 give 1.5, 1e2 gives 100), and json.fmt_number(text) does the same for a token. json.stringify writes a number as it is, so its text must match the JSON number grammar. An object keeps its keys in insertion order, and a duplicate key keeps its first position and takes the last value.

  • Read: v['key'] and v[idx] return Value.null when the member is missing. get(key) and at(idx) return an option. as_bool, as_int, as_float (also converts an int and a number, none beyond the float range), as_str, as_array and as_object return an option of the payload. kind() returns the JSON type name.
  • Compare: a.eq(b) compares by the JSON model (1 equals 1.0, key order does not matter). A number compares by number_text(). == compares the case and payload as for any choice, so 1 == 1.0 is false and an array or object compares by reference. An option can be tested with == none.
  • Build: json.Object has set, get, remove, contains, keys and len. json.object and json.array make values from lists.
  • Write: json.stringify(v) is compact and json.stringify(v, 2) puts each element on its own line. NaN and infinities become null. A float uses the shortest digits that read back as the same value, without a trailing .0, and an exponent below 1e-6 or from 1e21 (1e+21).
  • Convert: json.encode(x) and json.from(x) take a Cyber value: numbers, bool, str, slices, structs (fields in order), optionals (none is null), enums (the case name), choices ({"case": payload}) and Map with str keys (sorted). An r64 from 2^63, which does not fit int, becomes a number with its unsigned digits (18446744073709551615). Pass a borrow for a value that can not be copied: json.encode(&map).

json.to(T, v) converts a Value back to a Cyber type, and json.decode(T, src) parses and converts in one step. It takes the same types as from, except Array and fixed size arrays. A struct field must be present unless it has a default value (port int = 8080, a missing member takes it) or is an optional (a missing member is none), and members that are not fields are ignored. An integer type takes a whole float such as 3e2, a float type takes an integer, and str takes any number as its text, so a large ID can be read whole whatever its size. On failure it returns error.Type (another kind of value or an unknown case name), error.MissingField or error.Overflow (a number out of the type's range, such as 1e39 for f32; a number too small for f32 becomes 0), and a json.Diag tells where through path:

type User:
    id    int
    name  str
    email ?str

u := json.decode(User, '{"id": 7, "name": "Ada"}')!
print(u.name)       --> Ada

var diag json.Diag = {}
try:
    _ = json.decode([]User, '[{"id": 1, "name": 2}]', &&diag)!
else |err|:
    print('%{err} %{diag.path}: %{diag.msg}')
--> error.Type $[0].name: Expected a string, found number.

Parsing returns error.Syntax for malformed text and error.Unicode for text that is not UTF-8. Arrays and objects can nest 256 levels. A json.Diag passed to parse tells where and why parsing failed:

var diag json.Diag = {}
try:
    v := json.parse('{"a": tru}', &&diag)!
    print(v)
else |err|:
    print('%{err} at %{diag.line}:%{diag.col}: %{diag.msg}')
--> error.Syntax at 1:7: Expected a value, found `t`.

toon.encode(v) follows the spec's forms: key: value, nested objects by indentation, inline primitive arrays (tags[2]: a,b), a table for an array of uniform objects (users[2]{id,name}:), a keyed table for an object whose values are uniform objects (env[2:]{region}:), and - items otherwise. toon.EncodeOptions sets indent (2) and delim (.comma, .tab or .pipe). It returns error.Unicode for a string that is not UTF-8.

toon.decode(src) checks declared lengths, table widths, indentation and duplicate keys. toon.DecodeOptions{strict=false} applies the spec's non-strict recoveries. Errors are error.Syntax with a json.Diag (line and column). indent in toon.EncodeOptions and toon.DecodeOptions must be at least 1: below that encode and decode return error.Range. An unquoted token that matches the JSON number grammar is a number, others are strings (05 stays "05"); numbers decode as json.parse reads them, and toon.DecodeOptions{exact=true} keeps them as text like json.ParseOptions. A number encodes in the canonical form of json.fmt_number. toon.from_json(src) and toon.to_json(src) convert text directly. The implementation passes the spec's 564 conformance fixtures (src/test/assets/toon-spec).

Regular expressions. #

The regex module searches text with regular expressions. Matching never backtracks: a search takes time linear in the length of the input, whatever the pattern. The syntax is a subset of the Rust regex crate's, which is the default syntax of ripgrep. A pattern that compiles here matches what it matches there:

use regex

re := regex.compile(`(?P\w+)=(\d+)`)!
line := 'retries=3 timeout=250'

print(re.is_match(line))                --> true
print(re.find(line).?.text)             --> retries=3
for re.find_all(line) |m|:
    print('%{m.start}..%{m.end} %{m.text}')
--> 0..9 retries=3
--> 10..21 timeout=250

for re.captures_all(line) |c|:
    print('%{c['key']} is %{c[2]}')
--> retries is 3
--> timeout is 250

print(re.replace_all(line, '$2=$key'))  --> 3=retries 250=timeout
print(regex.compile(`[,;]\s*`)!.split('a, b;c'))   --> {'a', 'b', 'c'}

Write patterns as raw strings (backticks) so that \d needs no second backslash.

find returns a ?regex.Match with start, end (byte offsets) and text. captures returns a ?regex.Captures: c[0] is the whole match, c[1] and c['name'] are the text of a group, and '' when the group did not take part in the match. c.get(1) and c.get('name') return a ?Match and tell the two apart. Both take a second argument, the byte offset where the search starts. find_all and captures_all return every match from left to right. Matches do not overlap, and an empty match that touches the end of the match before it is left out (a* on baaac matches at 0, 1..4 and 5).

In the replacement of replace (first match) and replace_all, $1 and ${1} stand for a group by number, $name and ${name} by name, and $$ for a dollar sign. A name takes the longest run of letters, digits and _, so write ${1}a: $1a is the group named 1a. A group that does not exist gives nothing. replace and replace_all also take a function of the groups in place of the replacement. It is called once for each match, from left to right, and what it returns goes in as it is: $ has no meaning in it. A closure works too:

re := regex.compile(`(?P\w+)=(\d+)`)!
print(re.replace_all('a=1 b=22', |c| c['key'].upper() + ':' + c[2]))   --> A:1 B:22

split(s) returns the pieces between the matches, split(s, limit) at most limit pieces. regex.escape(s) returns a pattern that matches s itself.

The syntax:

Charactersa, . (any character but \n), \n \t \r \a \f \v, \x7F, \x{1F600}, é, \u{E9}, \U0001F600, \. and other escaped punctuation
Classes[abc], [^abc], [a-z], nested [a[^b]], [a-z&&[^aeiou]] (intersection), [a-z--[aeiou]] (difference), [a-c~~b-d] (in one but not both), [[:alpha:]], [[:^digit:]]
Perl classes\d (digit), \s (white space), \w (word character), \D, \S, \W
Unicode classes\pL, \p{Lu}, \p{Letter}, \p{Hangul}, \p{Greek}, \p{gc=Nd}, \p{sc=Latin}, \p{Alphabetic}, \p{Lowercase}, \p{Uppercase}, \p{White_Space}, \p{Any}, \p{ASCII}, \p{Assigned}, and \P{...} for the rest
Repetition*, +, ?, {n}, {n,}, {n,m}, and the lazy forms *?, +?, ??, {n,m}?
Assertions^, $, \A, \z (start and end of the input), \b, \B, \b{start} (\<), \b{end} (\>), \b{start-half}, \b{end-half}
Groups(...), (?:...) (not captured), (?P...), (?...), a\|b (the first alternative that matches wins)
Flags(?i) ignore case, (?m) ^ and $ match at line boundaries, (?s) . matches \n, (?U) swap greedy and lazy, (?x) ignore white space and # comments. (?i:...) for a group, (?-i) to turn off

Matching is by Unicode code point. \d, \s, \w, \b and (?i) are Unicode aware (\w+ matches 한글, (?i)k matches the Kelvin sign), as in ripgrep. The tables are those of Unicode regex.unicode_version(). A byte of the input that is not UTF-8 matches no class, not even ., and the search goes on after it. $ matches only at the end of the input unless (?m) is on. ripgrep searches line by line, this module the whole string: \s and [^a] match a line feed.

Not supported, because they need backtracking or are rarely used: look-ahead and look-behind, backreferences (\1), possessive and atomic groups, \Z, octal escapes, the R flag, turning off u, and Unicode properties other than general categories, scripts and the ones listed. regex.compile returns error.Syntax for these and for a malformed pattern. Pass a regex.Diag to see why:

var diag regex.Diag = {}
try:
    re := regex.compile(`(\w+)\s+\1`, &&diag)!
    print(re.is_match('a a'))
else |err|:
    print('%{err} at %{diag.pos}: %{diag.msg}')
--> error.Syntax at 8: Backreferences (`\1`) and octal escapes are not supported: matching never backtracks. Capture both parts and compare them in code. A character by number is `\x41` or `\x{1F600}`.

A counted repetition is expanded, so \w{100} is 100 steps of the program. A program over regex.MaxInsts (32768) instructions is error.TooBig, and groups, classes and repetitions nest at most regex.MaxDepth (250) deep. The number of instructions times the capture slots (two per group, counting group 0) must not be over regex.MaxSlotTable (1048576), or compile returns error.TooBig, so a search with captures takes at most 16 MiB. Write (?:...) for a group that needs no capture. One search takes at most the size of the program times the length of the input. A compiled Regex does not change: compile once and use it for every search.

Parsing expression grammars. #

The peg module matches text with a parsing expression grammar (PEG): patterns with rules that call each other. It is for input that a regular expression can not describe, such as nested brackets, and for a format with several parts that is easier to read as rules. The syntax is that of the re module of LPeg:

use peg

p := peg.compile("""
    list <- '(' item (',' item)* ')'
    item <- {:list: list :} / {:num: %d+ :}
""")!
c := p.parse('(1,(22,3),4)')!

print(c.len())                  --> 3
print(c[0])                     --> 1
print(c['list'])                --> (22,3)
for c.all('num') |n|:
    print('%{n.start}..%{n.end} %{n.text}')
--> 1..2 1
--> 4..6 22
--> 7..8 3
--> 10..11 4

A grammar is a list of rules name <- pattern, and matching starts at the first rule. A pattern without rules is a grammar too. Two things differ from a regular expression. A choice a / b is ordered: when a matches, b is not tried, so 'a' / 'ab' never matches ab. And a repetition takes all it can and gives nothing back: 'a'* 'a' never matches. To stop a repetition before something, say so with !: (!'"' .)* takes characters up to a quote.

'text' "text"The text. The escapes are \n \r \t \\ \' \" \[ \] \- \^ \xHH \u{H..}
'text'i "text"iThe text in any case, by the simple case folding of Unicode as (?i) in regex: 'select'i matches SELECT and Select, 'k'i also the Kelvin sign. The i comes right after the quote: 'x' i and 'x'id call the rules i and id
[a-z_] [^"]One character of the class, or one that is not in it. A class can hold %d and the like: [_%w]
.Any one character
%a %c %d %g %l %p %s %u %w %xLetter, control, digit, printable but space, lower case, punctuation, white space, upper case, letter or digit, hex digit. ASCII only. The upper case form is the opposite: %S
%nlA line feed
nameThe rule name
( p )A group
p? p* p+Zero or one, zero or more, one or more
p^3 p^+3 p^-3Exactly 3, at least 3, at most 3

p1 / p2p1, or else p2

{:name: p :}A capture with a name

-- ... # ...A comment to the end of the line

A match is a peg.Capture: start and end (byte offsets), text, name and kids, the captures inside it. Captures nest as they are written in the grammar, so the result is a tree. c[0] is the text of the first capture directly inside c, and c['name'] the text of the first capture with that name at any depth, '' when there is none. c.get('name') returns a ?Capture, c.all('name') every capture with that name in the order of the input, and c.len() the number of captures directly inside.

parse(s) matches all of s. match(s) matches at the start of s and does not have to reach the end, and match(s, start) matches at a byte offset. find(s) returns the first place where the grammar matches, find_all(s) every match from left to right, without overlaps. replace, replace_all and split work as in regex: in the replacement, $0 is the match, $1 its first capture and $name or ${name} the first capture with that name. A function in place of the replacement gets the peg.Capture of each match and returns its text: kv.replace_all(line, |c| c['key'].upper()).

kv := peg.compile(`{:key: [_%w]+ :} '=' {:val: %d+ :}`)!
line := 'set retries=3 timeout=250'

print(kv.match(line) == none)             --> true
print(kv.find(line).?['key'])             --> retries
for kv.find_all(line) |m|:
    print('%{m['key']} is %{m['val']}')
--> retries is 3
--> timeout is 250
print(kv.replace_all(line, '$val=$key'))  --> set 3=retries 250=timeout

-- The quote that closes is the quote that opened.
quoted := peg.compile(`{:q: ['"] :} { (!=q .)* } =q`)!
print(quoted.match(`'it is "so"' he said`).?[1])   --> it is "so"

-- A substitution capture rewrites what it matches.
csv := peg.compile("""
    row   <- {~ field (',' -> ';' field)* ~}
    field <- '"' [^"]* '"' / [^,]*
""")!
print(csv.match('a,"b,c",d').?[0])        --> a;"b,c";d

When parse fails it returns error.NoMatch. Pass a peg.Diag to see the farthest place that the match reached and what the grammar could have matched there:

var diag peg.Diag = {}
try:
    _ = p.parse('(1,(22,),4)', &&diag)!
else |err|:
    print('%{err} at %{diag.pos}: %{diag.msg}')
--> error.NoMatch at 7: Expected `'('` or `%d` at line 1, column 8, found `)`.

diag.line and diag.col start at 1, and diag.expected has the expected patterns as they are written in the grammar. peg.compile(grammar, &&diag) fills the same Diag for a grammar that does not compile (error.Syntax). A grammar is checked when it is compiled: a rule that is not defined, a repetition of something that can match nothing (('a'?)*), and a rule that is left recursive, that is, calls itself before it takes any input (expr <- expr '+' num), are errors. Write a left recursive rule as a loop: expr <- num ('+' num)*.

Matching is by Unicode code point: . and [가-힣] take a whole character, and offsets are in bytes. A byte of the input that is not UTF-8 is one character for . and for a negated class. The syntax is a subset of LPeg's re with the same meaning, with these differences: strings and classes have escapes, 'text'i ignores case, a named capture is a node of the result, =name matches the whole text of the capture, and what calls a Lua function (p -> name, p => name) or builds a table ({| p |}) is not supported. In a class, a % name goes on to the last letter, as in re: write [_%w], not [%w_].

A grammar backtracks, so there is no bound on the time of a match as there is for regex: a grammar can take time that grows fast with the length of the input. A match keeps a stack of open rule calls and choices. When the stack is over peg.MaxStack (100000) entries, for input that nests very deep, parse returns error.TooDeep, and for a match with more than peg.MaxCaptures (1000000) captures it returns error.TooBig. The functions that return an option panic in these cases. A call at the end of the last choice of a rule takes no stack: tail <- !. / . tail runs over any length of input. A grammar over peg.MaxInsts (65536) instructions is error.TooBig (p^100 takes 100 times the instructions of p), and patterns nest at most peg.MaxDepth (250) deep. A compiled Peg does not change: compile once and use it for every match.

Paths. #

The path module reads and builds path strings with / as the separator. It does not look at the file system, so an embedding host that refuses os can still allow it. It works like Go's path package: a Windows path with \ is not split.

use path

p := path.join('src', 'std/path.cy')   --> 'src/std/path.cy'
path.base(p)                           --> 'path.cy'
path.dir(p)                            --> 'src/std'
path.ext(p)                            --> '.cy'
path.stem(p)                           --> 'path'
path.normalize('a//b/./../c/')         --> 'a/c'
path.is_absolute('/usr/bin')           --> true
  • join(a, b) and join(parts) skip empty parts and normalize the result. A part that starts with / does not drop the parts before it: path.join('a', '/b') is 'a/b'.
  • normalize removes empty and . parts, removes a .. together with the part before it and removes a trailing /. A .. at the start of a relative path stays ('../a'), and '/..' is '/'. An empty path is '.'.
  • base and dir ignore a trailing /: base('a/b/') is 'b' and dir('a/b/') is 'a'. A path without / has the dir '.'.
  • ext is the end of the last part from its last ., with the .. A name that only starts with a . ('.bashrc') has no extension. stem is the last part without ext.

os.baseName and os.dirname were removed. Use path.base and path.dir.

Dates and times. #

The time module has four types. A Time is an instant, a DateTime is an instant seen at a UTC offset or in a time zone, a Date is a calendar day and a Duration is a length of time. An offset is an int: the minutes east of UTC, so +09:00 is 540 and -03:30 is -210:

use time

dt := time.parse('2026-11-15T10:22:03.5+09:00')!
print(dt.utc().format())                 --> 2026-11-15T01:22:03.5Z
print(dt.format('%d %b %Y %H:%M')!)      --> 15 Nov 2026 10:22
print(dt.year())                         --> 2026
print(dt.weekday())                      --> Weekday.sunday
print(dt.offset())                       --> 540
print(dt.to_offset(330)!.format())       --> 2026-11-15T06:52:03.5+05:30
print(dt.add_months(3)!.format())        --> 2027-02-15T10:22:03.5+09:00

There is no date and time without an offset, and nothing uses the time zone of the system unless the script asks for it with time.local(): a value always says which instant it is. The calendar is the proleptic Gregorian one, with years 1 to 9999. Leap seconds are not counted, as in Unix time, and a :60 in a text reads as :59.

time.now() returns the Time of the system clock. Instants compare with <, <=, >, >= and ==, and their difference is a Duration. The times of a file in os.FileInfo are Unix seconds and nanoseconds, and time.unix turns them into a Time:

use os
use time

fn mtime(path str) -> !time.Time:
    info := os.file_info(path)!
    return time.unix(info.mtime_sec, info.mtime_nsec)

a := mtime('build.zig')!
b := mtime('zig-out/bin/cyber')!
if a > b:
    print('the build is out of date')
if time.now() - b > time.hours(24):
    print('built more than a day ago')

The system clock can be set, so it can go back. To measure how long something takes, use time.monotonic(), a Duration that only grows and that has a meaning only as the difference of two readings:

start := time.monotonic()
work()
print((time.monotonic() - start).format())   --> 1.204s

A Duration is made with time.nanos(n), micros, millis, seconds, minutes, hours and days (24 hours). It adds, subtracts, negates, multiplies by an int and compares. A result out of the range of Duration, about 10000 years either way, panics with 'The duration is out of range.'. d.secs() and d.millis() return it as a whole number rounded toward zero, d.to_float() in seconds, and d.format() as text such as 1h2m3.5s.

A Time has no calendar fields. t.utc() and t.to_offset(minutes) return a DateTime, which has year(), month() (1 to 12), day(), hour(), minute(), second(), nanosecond(), offset(), weekday(), day_of_year() and date(). dt.time() returns the instant, and time.unix(sec), time.unix(sec, nsec), time.unix_millis(ms), t.unix() and t.unix_millis() convert between a Time and Unix time. dt.to_offset(m) is the same instant at another offset, dt.replace_offset(m) the same date and time of day at another offset. <, <=, > and >= compare two DateTime values by their instants, and a - b is the Duration between them, whatever the offsets and the zones. == compares all the fields, as for any value, so two values of the same instant at different offsets are not ==. Compare the instants with time():

a := time.parse('2026-11-15T10:22:03+09:00')!
b := time.parse('2026-11-15T01:22:03Z')!
print(a == b)                   --> false
print(a.time() == b.time())     --> true
print(a < b or a > b)           --> false
print((a + time.seconds(5) - b).format())   --> 5s

A Date is for calendar arithmetic. The difference of two dates is a number of days. add_months and add_years keep the day of the month, or take the last day when the month is shorter. DateTime has the same three methods, and they keep the time of day:

d := time.date(2024, 1, 31)!
print(d.add_months(1)!.format())        --> 2024-02-29
print(d.add_days(30)!.format())         --> 2024-03-01
print(time.date(2024, 12, 25)! - d)     --> 329
print(d.weekday())                      --> Weekday.wednesday
print(d.iso_week())                     --> IsoWeek{year=2024, week=5}
print(d.at(9, 30, 0)!.format())         --> 2024-01-31T09:30:00Z

time.date(y, m, d) and time.datetime(y, mo, d, h, mi, s) (UTC) or time.datetime(y, mo, d, h, mi, s, nsec, offset) return error.Range for a date that does not exist. So do the methods that move a value out of the years 1 to 9999. The operators + and - with a Duration panic instead: use add(d) when the input is not trusted.

time.parse(s) reads RFC 3339. The text must have an offset. A space can stand for the T, a , for the ., and the offset is Z, +09:00, +0900 or +09. A record without an offset is read with time.parse(s, offset), which takes the offset to read it at. time.parse_format(s, fmt) reads other shapes by a strptime format, and reads a text without %z as UTC, or at the offset in a third argument. time.parse_date(s) reads 2026-11-15 as a Date:

-- Python logging, log4j
print(time.parse('2026-11-15 10:22:01,123', 540)!.format())
--> 2026-11-15T10:22:01.123+09:00

-- Common Log Format
print(time.parse_format('15/Nov/2026:10:22:01 +0900', '%d/%b/%Y:%H:%M:%S %z')!.format())
--> 2026-11-15T10:22:01+09:00

-- syslog has no year: a field that the format does not have is that of 1970-01-01T00:00:00
print(time.parse_format('Nov  5 10:22:01', '%b %e %T')!.format())
--> 1970-11-05T10:22:01Z

format() writes RFC 3339 (Z for UTC, and the fraction of the second only when it is not zero). format(fmt) takes a strftime format and returns error.Format for a specifier that is not in this table:

Date%Y (four digits), %y (two digits: 69 to 99 are 1969 to 1999), %m, %d, %e (day padded with a space), %j (day of the year), %b %h (Nov), %B (November), %a (Sun), %A (Sunday)
Time of day%H, %I (12 hour clock), %p (AM, PM), %M, %S, %f (six digits), %3f, %6f, %9f
Offset%z (+0900), %:z (+09:00)
Zone%Z: the abbreviation of the time zone (KST, EDT). UTC or the offset for a value without a zone. Output only
Short forms%F (%Y-%m-%d), %T (%H:%M:%S), %R (%H:%M), %D (%m/%d/%y)
Others%s (Unix seconds), %n, %t, %%
Week%u (Monday is 1, Sunday is 7), %w (Sunday is 0), %G and %V (ISO 8601 year and week), %U and %W (week of the year, 00 to 53, with weeks from Sunday and from Monday as in C: the days before the first Sunday or Monday are week 00)

Names are in English. When parsing, a number takes one or two digits (%Y four, %j up to three, every %f one or more), %j can not be used with %m, %d, %e or %b, a space in the format takes one or more, a name can be short or full in any case, and both offset specifiers take Z, +0900, +09:00 and +09. A Date formats with the date and week specifiers only.

A week gives the date together with a day of the week (%a, %A, %u or %w): %U or %W with %Y or %y, or %V with %G. It can not be used with %m, %d, %e, %b or %j, and a day that the week does not have (2026 00 Wed by %Y %W %a: the first Monday is January 5) is error.Range. When the format has a whole date (a year, and a month and a day or %j), a day of the week in the text must be the day of that date: Fri 2026-11-26 by %a %F is error.Range with '2026-11-26 is a Thursday, not a Friday.'

print(time.parse_format('2026-W53-4', '%G-W%V-%u')!.format())
--> 2026-12-31T00:00:00Z

The parse functions return error.Syntax when the text has another shape, error.Range when a field is out of range and error.Format when the format is wrong. Each takes a time.Diag as its last argument to see why:

var diag time.Diag = {}
try:
    _ = time.parse('2026-02-30T10:22:01Z', &&diag)!
else |err|:
    print('%{err}: %{diag.msg}')
--> error.Range: February 2026 has no day 30.

time.is_leap_year(y), time.days_in_month(y, m), time.parse_offset('+05:30') (330) and time.format_offset(330) are there for code that works on the fields.

A Zone is a time zone with its daylight saving time. time.zone(name) reads one by its IANA name from the time zone database of the system, and t.to_zone(z) or dt.to_zone(z) gives the date and time of day there:

ny := time.zone('America/New_York')!
t := time.parse('2026-07-04T12:00:00Z')!.time()
dt := t.to_zone(ny)
print(dt.format())               --> 2026-07-04T08:00:00-04:00
print(dt.format('%H:%M %Z')!)    --> 08:00 EDT
print(ny.offset_at(t))           --> -240
print(ny.is_dst(t))              --> true

z.datetime(y, mo, d, h, mi, s) makes a value from a clock reading in the zone, and so do d.at(h, mi, s, z) and dt.replace_zone(z), which keeps the date and time of day of dt. When the clock is set forward, an hour of readings does not exist, and when it is set back, an hour comes twice. Such a reading is taken the way most calendars do: the skipped time moves forward by the gap, and the repeated time is the first of the two. A last argument says otherwise: .earlier, .later, or .reject, which returns error.Skipped or error.Ambiguous:

print(ny.datetime(2026, 3, 8, 2, 30, 0)!.format())               --> 2026-03-08T03:30:00-04:00
print(ny.datetime(2026, 11, 1, 1, 30, 0)!.format())              --> 2026-11-01T01:30:00-04:00
print(ny.datetime(2026, 11, 1, 1, 30, 0, 0, .later)!.format())   --> 2026-11-01T01:30:00-05:00
print(ny.datetime(2026, 3, 8, 2, 30, 0, 0, .reject).unwrap_error())   --> error.Skipped

-- a record without an offset, written by a machine in New York
print(time.parse('2026-11-15 10:22:01', 0)!.replace_zone(ny)!.format())   --> 2026-11-15T10:22:01-05:00

A value in a zone keeps the zone (dt.zone() returns it, or none). add_days, add_months and add_years keep the time of day and read it in the zone again, so a day can be 23 or 25 hours long. +, - and add with a Duration move the instant by that much. utc(), to_offset and replace_offset give a value at a fixed offset, without the zone:

noon := ny.datetime(2026, 3, 7, 12, 0, 0)!       -- the day before the clock is set forward
print(noon.add_days(1)!.format())                --> 2026-03-08T12:00:00-04:00
print((noon + time.hours(24)).format())          --> 2026-03-08T13:00:00-04:00

The database is the zoneinfo directory of the system: the one in TZDIR, or /usr/share/zoneinfo and the like. time.zone returns error.NotFound for a name that is not there. Windows and wasm have no such directory, so only time.zone('UTC') is found there. A zone can also be made from data: time.zone_from_tzif(name, bytes) takes the bytes of a TZif file (the format of the files in that directory), and time.zone_from_posix('EST5EDT,M3.2.0,M11.1.0') or time.zone_from_posix('KST-9') takes a POSIX TZ rule. time.local() returns the zone of the system: what the TZ environment variable says, or else /etc/localtime. It returns error.NotFound when the system does not say (Windows, wasm), or says something that can not be read.

dt.format() writes the offset and not the zone. To keep the zone in text, dt.format_zoned() writes RFC 9557, which is RFC 3339 with the name of the zone in brackets, and time.parse_zoned(s) reads it back:

a := ny.datetime(2026, 11, 1, 1, 30, 0, 0, .later)!
print(a.format_zoned())                                     --> 2026-11-01T01:30:00-05:00[America/New_York]
b := time.parse_zoned('2026-11-01T01:30:00-05:00[America/New_York]')!
print(b == a)                                               --> true
print(b.add_days(1)!.format_zoned())                        --> 2026-11-02T01:30:00-05:00[America/New_York]

The offset in the text says which of two readings it is. parse_zoned returns error.Conflict when it is not the offset of the zone at that time (the rules of a zone can change after a text is written) and error.NotFound when the system does not have the zone. With Z in the place of the offset the instant is kept and the zone gives the offset, and without an offset the text is a clock reading in the zone. A text without brackets is read as time.parse reads it, and a value without a zone is written as format() writes it. So is a value in a zone made from data with zone_from_tzif or zone_from_posix: parse_zoned could not look its name up.

An offset of the database that is not a whole minute is rounded to the minute. These are the local mean times from before standard time, mostly before 1920. Two zones are == when their name and their data are the same, and both or neither came from the database (time.zone, time.local).

Symbol visibility. #

Symbols can have private visibility when declared with a - prefix. This only allows the source module to access the symbol:

-type Foo:
    a int
    b int

-fn add(a, b int) -> int:
    return a + b

The prefix applies to functions and methods, globals, constants, types (including templates, traits and type aliases) and fields. The module is the file that declares the symbol, so m.add(1, 2) from another module is a compile error: Can not access the private symbol addinm. A persist_main session (the REPL) counts as one module, whatever uri each eval is given, so a private symbol declared by an earlier eval stays visible to the next one and to cl_vm_validate.

Binding to C. #

Cyber supports binding to an existing C ABI compatible library at runtime. This allows calling into dynamic libraries created in C or other languages. Static linking is not available: the bytecode VM is the only backend.

There are two approaches to binding a C library:

  1. Runtime binding. The C library is loaded and binded upon program start-up.
  2. When embedding libcyber, compiler hooks can bind VM or C functions with the host language.
^topic

Runtime binding. #

Cyber uses libtcc to JIT compile the bindings from extern declarations. An example can be found in ffi.cy.

#extern bindings are resolved from a dynamic library upon program startup.

c.bind_lib tells the compiler where to look for the dynamic library. The extern declarations in the same module are then resolved at runtime:

#c.bind_lib('./mylib.dylib')

A path with a directory component is opened as is. A bare file name is searched by the system loader (LD_LIBRARY_PATH, the directory of the cyber executable, then the system library paths), so use an explicit path like ./mylib.so to load a library from the current directory.

^topic

extern functions. #

An extern function is configured with a C call convention and registered for runtime binding:

#[extern]
fn SDL_CreateWindow(title Ptr[c_char], w c_int, h c_int, flags WindowFlags) -> Ptr[Window]

An extern symbol name can be declared if it differs from the API name:

#[extern='SDL_CreateWindow']
fn CreateWindow(title Ptr[c_char], w c_int, h c_int, flags WindowFlags) -> Ptr[Window]

The example above would be bound to this C function:

SDL_Window* SDL_CreateWindow(const char *title, int w, int h, SDL_WindowFlags flags);

An extern function is bound by the c module, so the c module must be loaded: use c, or a module that imports it. Otherwise the declaration is a compile error: 'An #[extern] function needs the c module. Add use c.'

^topic

extern globals. #

An extern global is registered for runtime binding. It is declared with the type of the C variable, and the script reads and writes the variable of the library:

#[extern] global count i32
#[extern] fn bump() -> i32

print(count)       --> 5
count = 40
print(bump())      --> 41

The example above would be bound to this C code:

int count = 5;
int bump(void) { return ++count; }

An extern symbol name can be declared as for a function: #[extern='lib_count'] global count i32. An extern global can not be read in the initializer of another global, because it is bound after the global initializers run.

libcyber allows embedding the Cyber compiler and VM into an application. Cyber's builtin types, functions, and the CLI app were built using libcyber.

The API is defined in the C header file. The examples shown below can be found in the repository under libcyber. The examples are in C, but it can be easily translated to C++ or any C-ABI compatible language.

Create VM. #

A VM instance is required to compile and interpret Cyber code. To create a new VM instance, call cl_vm_init. It returns NULL when there is no memory for the VM:

#include "cyber.h"

int main() {
    CLVM* vm = cl_vm_init();
    if (vm == NULL) return 1;
    // ...
    cl_vm_deinit(vm);
    return 0;
}

Override print. #

The builtin print function does nothing by default, so it needs to be overrided to print to stdout for example:

void printer(CLThread* t, CLBytes str) {
    printf("Invoked printer: %.*s\n", (int)str.len, str.ptr);
}

int main() {
    // ...
    cl_vm_set_printer(vm, printer);
    // ...
}

Note that prints invokes printer once. But print invokes the printer twice, once for the value's string and another for the new line character.

void eprinter(CLThread* t, CLBytes str) {

Compile errors. #

When the result code is CL_ERROR_COMPILE, cl_vm_compile_error_summary returns the message, the source line and a marker under the reported range. The compiler stops at its first error, so there is one error per compile. The text has no terminal escape codes. A host that prints to a terminal can color the marker with cl_vm_set_error_color(vm, true).

cl_vm_compile_error returns the same error as data, so that a host does not parse the summary:

CLCompileError err;
if (cl_vm_compile_error(vm, &err)) {
    // `line` and `col` start at 0. `col` and `len` count bytes.
    if (err.has_loc) {
        printf("%.*s:%u:%u: ", (int)err.uri.len, err.uri.ptr, err.line + 1, err.col + 1);
    }
    printf("%.*s\n", (int)err.msg.len, err.msg.ptr);
}

msg and uri are owned by the VM and stay valid until its next eval, compile, validate or reset. kind is CL_REPORT_TOKEN_ERROR, CL_REPORT_PARSE_ERROR or CL_REPORT_COMPILE_ERROR. cl_vm_compile_error returns false if the last result was not CL_ERROR_COMPILE.

cl_vm_compile_report returns the whole reported range and cl_vm_compile_report_note the other places that the summary prints with an error, for a host that marks errors in an editor:

size_t count = cl_vm_compile_report_count(vm);
for (size_t i = 0; i < count; i += 1) {
    CLReport rep;
    cl_vm_compile_report(vm, i, &rep);
    // Lines and columns start at 0, columns count bytes, and the end is exclusive.
    // `pos` and `end_pos` are the same range as byte offsets in the source.
    if (rep.has_loc) {
        printf("%u:%u-%u:%u: ", rep.line + 1, rep.col + 1, rep.end_line + 1, rep.end_col + 1);
    }
    printf("%.*s\n", (int)rep.msg.len, rep.msg.ptr);

    CLReport note;
    for (size_t j = 0; cl_vm_compile_report_note(vm, i, j, ¬e); j += 1) {
        // `First declared at:` with the first declaration, or the call that expanded a template (empty `msg`).
    }
}

A range can end on a later line than it starts. A token or parse error reports a position: its range is the code point there, or empty at the end of a line.

When the compiler knows the edit that fixes an error, has_fix is set: replace the bytes fix_pos to fix_end_pos (exclusive) of the source with fix_text. A misspelled member (Did you mean ...?), a function that was renamed in its module, and xs = xs.append(v) have one. cyber-lsp offers it as a quick fix. A note never has a fix. By default the compiler stops at its first error and the count is 0 or 1. cl_vm_set_error_recovery(vm, true) lets it go on. Every syntax error is reported: a statement with a syntax error is skipped together with the lines indented under it, and parsing goes on at the next line of the same block or of a block around it. A source with a syntax error is not checked further, so its other errors are reported once the syntax errors are fixed. In a source without syntax errors, the main block, each function and each method is checked again without the statement that failed, so the errors of its other statements are reported too, and the other bodies are still checked. A statement that failed to declare a local (x := ...) ends its block, so the uses of the local after it are not reported as undeclared. A body is checked at most ten times. Every declaration is resolved too: a signature, the fields of a type, the type of a global or of a const and a type alias that fail are reported, and the next declaration is resolved. A declaration that refers to one that failed fails without a report of its own. With an error in a declaration no body is checked, so the errors in bodies are reported once the declarations are fixed. An error in a top level compile-time statement, a use or a template header still ends the compile. The result is CL_ERROR_COMPILE either way and nothing is run. The summary and cl_vm_compile_error describe the first error.

A compile error does not end a session. The next eval or validate compiles on top of what the evals before the failed one left: with persist_main their locals and declarations are still there, and nothing that the failed script declared is kept, including a method that it declared for a type of an earlier eval. A module that the failed compile loaded for the first time is loaded again by the next use. The template instances that it expanded from earlier modules ([]str with sort) are checked and generated by the next compile. If the body of such an instance does not compile (Map[[]int, int] behind an earlier error), the next compile drops the instance instead of reporting its error, and a later use of it reports that it could not be expanded. These instances are checked before the next compile resolves the script, so the script itself is compiled once, and the module loader, the resolvers and the compile-time host functions are not called again for it. The loader is called again for a module that the failed compile loaded first. Make it return the same source for the same module. When the first compile of a VM fails, the next eval resets the VM.

Asking what a name is. #

For editor tooling, cl_vm_set_symbol_info(vm, true) makes the compiler record what the names in the main source refer to. After a compile, cl_vm_symbol_at describes what is at a byte offset:

cl_vm_set_symbol_info(vm, true);
cl_vm_validate(vm, src);

CLSymbolInfo info;
if (cl_vm_symbol_at(vm, pos, &info)) {
    // `fn add(a int, b int) -> int`, `total int`, or the type of an expression.
    printf("%.*s\n", (int)info.detail.len, info.detail.ptr);
    if (info.has_def) {
        // The declaration is at bytes `def_pos`..`def_end_pos` of the source `def_uri`.
    }
}

detail is the first line of the declaration for a function, a type, a constant or a global, name Type for a local, a parameter or a field, and the type for any other expression. The compile may have failed: what was resolved before the error is still answered. detail and def_uri are owned by the VM and stay valid until the next call, eval, compile, validate or reset. info.kind tells a local (CL_SYMBOL_LOCAL) from something declared outside of a function body (CL_SYMBOL_DECL) and from an expression that is not a name (CL_SYMBOL_EXPR).

cl_vm_symbol_refs(vm, pos, &ranges) returns the number of places in the main source that name the same thing as the name at pos, and sets ranges to them: the uses and, if it is declared in the main source, the name in the declaration. Uses in other modules are not found. For completion, cl_vm_members_at(vm, pos, &items) lists the members of the expression that ends at pos (the fields and methods of its type, or what a module or a type declares), and cl_vm_names_at(vm, pos, &items) lists the names that can be used at pos: the locals and parameters of the function around it, what the main source declares and uses, and the builtins. Each CLItem has a name, a one line detail and a kind. Source that is being typed usually does not parse, so a host compiles a copy without the unfinished part (v. as v) and asks at the end of the receiver. A name in a declaration of the main source can be asked like a use of it. To find the uses of a symbol in the other sources of a project, a host compiles each of them as the main source and calls cl_vm_symbol_refs_to(vm, def_uri, def_pos, &ranges) with the declaration that cl_vm_symbol_at reported. cl_vm_symbol_tokens(vm, &tokens) lists every resolved name of the main source with its CLItemKind, for highlighting by meaning. cl_vm_symbol_hints(vm, &hints) lists notes on the main source for an editor, sorted by position: the type inferred for each x := expr (CL_HINT_LOCAL_TYPE), each return, break and continue that waits for the fibers of a scope block before it leaves it (CL_HINT_SCOPE_EXIT), the name of the parameter at each argument of a call to a function with two or more parameters, from the overload that the call picked, unless the argument is a name that ends in it (CL_HINT_PARAM_NAME), and, after a compile without errors, the locals and uses that are never used (CL_HINT_UNUSED_LOCAL, CL_HINT_UNUSED_USE). A name that starts with _ is not called unused, nor is one that is also written where the compiler did not look (a branch of #if that was not taken). The language server cyber-lsp uses all of these.

Checking a script without running it. #

cl_vm_validate compiles a script against the current session and reports compile errors without running it. Locals and declarations persisted by earlier evals (persist_main) are visible to it, and nothing the script declares is kept for the next eval, including a method that it declares for a type of an earlier eval. It compiles the script as part of the session, so it accepts what the eval of the same script accepts: a private field of an earlier eval, a method for a type of an earlier eval. The VM is not reset. A module the script loads for the first time (use math) is initialized by the next eval that runs. It checks with the options of the last eval (persist_main, deny_raw_ptrs, deny_spawn, deny_ffi). Before the first eval they are all off, so eval a prelude with the session's config first.

CLResultCode code = cl_vm_validate(vm, src);
if (code == CL_ERROR_COMPILE) {
    CLBytes summary = cl_vm_compile_error_summary(vm);
    printf("%.*s\n", (int)summary.len, summary.ptr);
    cl_vm_freeb(vm, summary);
}

cl_vm_compile and cl_vm_compile_path compile a whole program instead. They reset the VM first, like cl_vm_reset, so persisted state is gone afterwards.

Limiting an eval. #

A host that runs scripts it does not trust bounds the time, the stack and the memory of an eval:

  • cl_vm_interrupt(vm) asks the running eval to stop at its next checkpoint (a loop back edge or a call). It is safe to call from another thread, for example from a wall clock timer. The eval returns CL_ERROR_INTERRUPT after unwinding like a panic, and the VM can be used again. Each eval clears an earlier request when it starts.
  • cl_vm_set_fuel(vm, fuel) limits each following eval to fuel checkpoints. An eval that runs out returns CL_ERROR_INTERRUPT. Zero or less removes the limit. Unlike a timer, fuel gives the same result on every run.
  • cl_vm_set_stack_limit(vm, bytes) caps the stack of the main thread and of the threads it spawns. The default is 128 MiB. A call that needs more panics with Stack overflow.
  • cl_vm_set_memory_limit(vm, bytes) limits the memory that the VM holds through its allocator. An allocation of the script that does not fit panics with OutOfMemory. cl_vm_memory_used(vm) returns what the VM holds now, so a host that gives a script N bytes sets cl_vm_memory_used(vm) + N.
cl_vm_set_fuel(vm, 10 * 1000 * 1000);
cl_vm_set_memory_limit(vm, cl_vm_memory_used(vm) + 64 * 1024 * 1024);

CLEvalResult res;
CLResultCode code = cl_vm_eval(vm, src, &res);
if (code == CL_ERROR_INTERRUPT) {
    // The script ran out of fuel or `cl_vm_interrupt` was called.
}

A script has no access to these limits. An eval that is suspended at an await keeps the fuel that is left (see Suspending an eval).

Module loader. #

A module loader is set with cl_vm_set_loader. It describes how a module is loaded when triggered by a use import statement:

bool loader(CLVM* vm, CLSym* mod, CLBytes uri, CLLoaderResult* res) {
    if (strncmp("my_mod", uri.ptr, uri.len) == 0) {
        const char* src = (
            "#[bind] fn add(a, b float) -> float\n"
            "#[bind] global my_global float\n"
            "\n"
            "type MyNode:\n"
            "  data float\n"
            "\n"
            "#[bind] fn MyNode :: @init() -> MyNode\n"
            "#[bind] fn (&MyNode) @deinit()\n"
            "#[bind] fn (&MyNode) compute() -> float\n"
        );

        cl_mod_add_func(mod, CL_BYTES("add"), CL_BIND_FUNC(add));
        cl_mod_add_func(mod, CL_BYTES("MyNode.@init"), CL_BIND_FUNC(mynode_init));
        cl_mod_add_func(mod, CL_BYTES("MyNode.@deinit"), CL_BIND_FUNC(mynode_deinit));
        cl_mod_add_func(mod, CL_BYTES("MyNode.compute"), CL_BIND_FUNC(mynode_compute));
        cl_mod_add_global(mod, CL_BYTES("my_global"), CL_BIND_GLOBAL(&myglobal));

        res->src = CL_BYTES(src);
        return true;
    } else {
        // Fallback to the default module loader to load builtin modules such as `core`.
        return cl_default_loader(vm, mod, uri, res);
    }
}

int main() {
    //...
    cl_vm_set_loader(vm, loader);
    //...
}

The above example loads my_mod by setting the appropriate function and global bindings, and returning its source code. Other modules get delegated to the default loader cl_default_loader which knows how to load the builtin modules such as core.

Allowing modules. #

A host that runs untrusted scripts decides which modules a script may import with a resolver, not with the loader. The loader is called once per module, when it is first loaded, and gets only the module's name: core has already loaded meta before the script runs, and a refused c would also break math, which imports c itself. The resolver set with cl_vm_set_resolver is called for every use and gets the importing module (curUri) with the specifier (uri), so it can check only the imports of the script and pass the imports of the standard modules on to cl_default_resolver:

bool resolver(CLVM* vm, CLResolverParams params, size_t* res_uri_len) {
    // The script is evaluated with the URI "main". An empty `curUri` resolves the script itself.
    if (params.curUri.len == 4 && strncmp(params.curUri.ptr, "main", 4) == 0) {
        if (!is_allowed(params.uri)) {
            return false;   // Compile error: Failed to resolve module `c`.
        }
    }
    return cl_default_resolver(vm, params, res_uri_len);
}

Before returning false, the resolver can give its own message with clReportApiError. The compiler's own lookups of the builtin modules it needs (c for a module with #[extern] functions such as math, meta) do not call the resolver, so it sees only the use declarations of the sources. Modules to keep from an untrusted script include c (raw memory and foreign calls), os (files and processes, when the host's loader provides it), cy (cy.eval, cy.VM() and cy.repl run code in a new VM that has none of the host's settings) and meta (meta.load reads a file at compile time).

Denying raw pointers. #

A host that runs untrusted scripts can set deny_raw_ptrs in CLEvalConfig or CLCompileConfig. Every chunk that is not a standard module (core, meta, math, cy, c, io, test) then gets a compile error for any expression of a raw pointer type: Ptr[T], PtrSpan[T] or an option of them. That covers as[Ptr[int]] 8, Ptr[int](8), as[Ptr[int]] &x, alloc(int) and PtrSpan[int]{length=4}, so a script can not read or write an arbitrary address. Slices, spans, maps, strings and borrows keep working; the core library uses raw pointers for them internally. The default is false. The CLI does not set it.

CLEvalConfig cfg = clDefaultEvalConfig();
cfg.deny_raw_ptrs = true;
cl_vm_evalx(vm, CL_BYTES("turn"), src, cfg, &res);
^topic

Denying threads. #

spawn runs a function on another thread, and a host function that the function calls runs on that thread too. A host whose functions only work on the thread of the eval sets deny_spawn in CLEvalConfig or CLCompileConfig. A spawn in a chunk that is not a standard module is then a compile error. Fibers and scope blocks stay available: they run on the thread of the eval.

CLEvalConfig cfg = clDefaultEvalConfig();
cfg.deny_spawn = true;

Denying C FFI. #

A module allowlist does not keep a script from C: math imports c, so a script that may only use math can still declare #[extern] fn getpid() -> i32 and call any symbol of the host process. A host that runs untrusted scripts sets deny_ffi in CLEvalConfig or CLCompileConfig. In every chunk that is not a builtin module (core, meta, math, cy, c, io, test, time, json, peg, regex, toon, path) these are then compile errors:

  • #[extern] on a function, a global or a function type (#[extern] fn() -> i32): '#[extern] is not allowed. The host disabled C FFI for this script (deny_ffi).' A none of an extern function type is a call to the null address.
  • use c, under any alias: 'The module c is not allowed. The host disabled C FFI for this script (deny_ffi).' Its #c.bind_lib loads a library, and #c.include and #c.flag add to the C compile of every extern function, those of math too.

Creating a cy.VM (cy.eval, cy.VM()) panics with 'cy.VM is not allowed. The host disabled C FFI for this script (deny_ffi).': the new VM has the default loader and none of the host's options. The builtin modules keep their own extern functions, so math.acos still works. A module that the host's loader provides as Cyber source is not a builtin module and can not declare extern functions either. The default is false. The CLI does not set it. A host that runs untrusted scripts sets all three options with its resolver:

CLEvalConfig cfg = clDefaultEvalConfig();
cfg.deny_raw_ptrs = true;
cfg.deny_spawn = true;
cfg.deny_ffi = true;

Session reset. #

A session (persist_main) keeps its locals, functions and use imports across evals, and a compile error in one eval keeps them. A panic drops the main locals and keeps the functions and imports. Two failures drop everything: the first compile of a VM, and an allocation that fails in the compiler or while the main locals are carried over. The next cl_vm_eval or cl_vm_validate then starts from a reset VM, like cl_vm_reset. cl_vm_reset_pending(vm) returns true when that is the case, so a host asks it after an eval that did not return CL_SUCCESS and sets the session up again (and tells the writer of the scripts that the variables are gone).

Allocation failure. #

A host can give the VM its own allocator (cl_vm_init_mem, cl_vm_initx). When that allocator fails during an eval, the eval returns an error and the VM can be used again:

WhereResult
In the compilerCL_ERROR_COMPILE. The summary names OutOfMemory, or WriteFailed when the allocation was behind a text writer, or it is empty without memory for the report. The next eval starts from a reset VM, like cl_vm_reset: locals and declarations persisted by earlier evals (persist_main) are gone.
In the scriptCL_ERROR_PANIC with panic: OutOfMemory. Without memory for the message or the stack trace of another panic, its message is replaced by OutOfMemory and its trace is empty.
After the run (the result value, the persisted locals)CL_ERROR_UNKNOWN, with no summary.

A summary function returns the null string if there is no memory for the text. Creating a VM (cl_vm_init, cl_vm_initx, cl_vm_init_mem) returns NULL if the allocator fails, after giving back every block it took. cl_vm_alloc returns NULL and cl_vm_allocb the null string, cl_vm_ensure_func_sig NULL and cl_symbol · cl_error -1.

The functions a host function calls to create values (cl_str_init, cl_astr_init, cl_ustr_init, cl_slice_init, cl_new_func_union, cl_lift, cl_array_empty, cl_map_empty) return an empty string, an empty slice or the value 0 when they can not allocate, and the host function ends with panic: OutOfMemory when it returns, whatever it returns. A panic it returns itself with cl_thread_ret_panic is kept. The host does not use that value or put it in another value, and returns as soon as it can:

CLRet make(CLThread* t) {
    CLstr* ret = cl_thread_ret(t, sizeof(CLstr));
    *ret = cl_str_init(t, CL_BYTES("hello"));
    // On an allocation failure `*ret` is empty and the call ends with `panic: OutOfMemory`.
    return CL_RET_OK;
}

To bound the memory of a script use cl_vm_set_memory_limit and not an allocator that fails: a limit ends in panic: OutOfMemory only where the script grows its heap or a stack, and it never stops the compiler part way.

VM functions. #

A VM function binding is created with CL_BIND_FUNC() and mapped to a module function name with cl_mod_add_func:

// ...
cl_mod_add_func(mod, CL_BYTES("add"), CL_BIND_FUNC(add));
// ...

A VM function is a C function that the VM can call into. Cyber is a statically typed language so it requires the return and parameters to be defined by how much space they occupy on the stack:

CLRet add(CLThread* t) {
    double* ret = cl_thread_ret(t, sizeof(double));
    double a = cl_thread_float(t);
    double b = cl_thread_float(t);
    *ret = a * b;
    return CL_RET_OK;
}

The parameters are read one by one in the order they are declared, each with the function of its type (cl_thread_int, cl_thread_str, ..., or cl_thread_param with a size). Each call moves on to the next parameter. cl_thread_ret may come before or after the parameters, but not in between: it starts the parameters over from the first.

Suspending an eval. #

A host function that can not answer at once (it needs the user's approval, or a slow tool) returns a pending Future instead of blocking inside the call. When the script awaits it, the eval returns CL_AWAIT. The script is suspended with its stack, its locals and its remaining fuel intact. The host completes the future and calls cl_vm_resume:

// #[bind] fn write_async(path str, text str) -> Future[!void]
CLRet write_async(CLThread* t) {
    CLValue* ret = cl_thread_ret(t, sizeof(CLValue));
    CLstr path = cl_thread_str(t);
    CLstr text = cl_thread_str(t);
    // ... remember the request as number `id` ...
    CLFuture* f = cl_future_new(t, cl_find_type(cl_thread_vm(t), CL_BYTES("Future[!void]")), id);
    *ret = (CLValue)(uintptr_t)f;
    cl_str_deinit(t, &path);
    cl_str_deinit(t, &text);
    return CL_RET_OK;
}

CLResultCode code = cl_vm_evalx(vm, uri, src, config, &res);
while (code == CL_AWAIT) {
    CLFuture* f = cl_vm_pending_future(vm);
    uint64_t id = cl_future_tag(f);        // The request this future belongs to.
    if (cancelled) {
        cl_vm_abandon(vm);                 // Like an interrupt. The VM takes the next eval.
        break;
    }
    if (approved) {
        cl_future_complete(vm, f, NULL);   // `!void` has no value to pass.
    } else {
        cl_future_complete_error(vm, f, cl_error(vm, CL_BYTES("Denied")));
    }
    code = cl_vm_resume(vm, &res);
}

A wrapper in the module source keeps the script API synchronous:

#[bind] fn write_async(path str, text str) -> Future[!void]

fn write(path str, text str) -> !void:
    return write_async(path, text).await()
  • cl_future_complete copies the value and the future owns it afterwards, as a return slot does. For a Future[!U] the value is the U. cl_future_complete_error completes a Future[!U] with an error.
  • cl_vm_resume follows the rules of cl_vm_evalx. It returns CL_AWAIT again at the next await, and also when the pending future was not completed. A resume clears an interrupt request that arrived while the eval was suspended, as the start of an eval does, so a wall clock timer does not count the time the host waited. The fuel is not refilled.
  • While an eval is suspended, cl_vm_eval*, cl_vm_validate and cl_vm_compile* return CL_ERROR_SUSPENDED. cl_vm_reset and cl_vm_deinit abandon the suspended eval first.
  • cl_vm_abandon drops the suspended eval with the outcome of an interrupt: the main locals are gone, the declarations stay. The panic summary names the abandoned await.
  • A script can start several requests before it waits. cl_vm_pending_futures returns the futures the suspended eval waits for: one for await, the whole list for Future.wait_any. The host completes any of them, in any order and more than one if it likes, before the resume.
  • The tag given to cl_future_new is the host's number for the request, read back with cl_future_tag. Futures that the host did not create have the tag 0. Find the request of a pending future by its tag and not by its pointer: a future that the script never awaits, or that is still pending when the eval ends, is freed like any other object, and its address can be given to the next future.
  • The host does not have to keep future pointers. A host that completes a future the eval is not waiting for at that moment keeps its pointer and retains it with cl_thread_retain. It releases it after it completed the future or when the eval ends with CL_SUCCESS. After a panic, an interrupt or cl_vm_abandon the heap of the eval is already freed with the futures in it: the host forgets its pointers without releasing them.
  • All of these functions are called from the thread that runs the evals of the VM. A future is not completed from another thread.

The full program is examples/libcyber/host_await.c.

Type binding. #

A type binding describes how to load a #[bind] type. The module's source declares the type with #[bind] and the loader answers with cl_mod_add_type:

const char* src = (
    "#[bind] type MyNode:\n"
    "  data float\n"
);

// Use the declaration from the source. `CL_NULLID` generates a new type id.
cl_mod_add_type(mod, CL_BYTES("MyNode"), CL_BIND_DECL_TYPE(CL_NULLID));

There are three kinds of type bindings:

  • CL_BIND_DECL_TYPE(type_id) uses the declaration from the source, with a predefined type id or with a generated one (CL_NULLID).
  • CL_BIND_CREATE_TYPE(create_fn) calls a CLCreateTypeFn that creates the type from the declaration node. Returning NULL fails the compile.
  • CL_BIND_ALIAS_TYPE(resolve_fn) calls a CLResolveAliasFn that returns the symbol that the name is an alias of.

A type that needs no host callback does not need #[bind]. Its methods can still be bound as functions.

Types in Cyber have the same memory layout as a C type (assuming the member types are mapped correctly):

-- Cyber
type MyNode:
    data float

// C
typedef struct MyNode {
    double data;
} MyNode;

REPL. #

The default behavior of cyber is to start a REPL:

cyber
> a := 123
> a * 2
`int` 246

Unlike conventional Cyber code, the REPL allows variable redeclarations:

> a := 'a is now a string'
> a
`str` 'a is now a string'

Top level variables are carried over to the next input by moving their values. A borrow would keep pointing at the old location, so a top level variable can not have a borrow type such as &T or [&]T. Use an owned type, or declare the borrow inside a block:

> sp := [&]int{1, 2}
CompileError: Cannot persist local `sp` of borrow type `[&]int` across evals. Declare it inside a block or use an owned type.
> sp := []int{1, 2}

A top level variable of the REPL does not move without move, because later inputs read it. A NoCopy value that would move in a script is a compile error that says to write move a or to borrow. After move a, later inputs can not use a until they declare it again (a := ...). A member of a top level variable can not be moved:

> a := Array[str]{'x', 'y'}
> b := a
CompileError: Cannot copy `Array[str]`, a `NoCopy` type. The top level variable `a` of the REPL does not move without `move`: later inputs read it. Write `move a` to give it away (later inputs can not use `a` then), or borrow it.
> b := move a
> a
CompileError: `a` was moved by an earlier input. Declare it again with `a := ...` to use the name.

When the first input ends with :, the REPL will automatically indent the next line. To recede the indentation, provide an empty input. Once the indent returns to the beginning, the entire code block is submitted for evaluation:

> if true:
    | print('hello!')
    | 
hello!

An attribute line such as #[inline] is held until the declaration it annotates is complete. A one line declaration after an attribute is submitted with an empty input:

> #[inline]
| fn one() -> int:
    | return 1
    | 
> one()
`int` 1

Top level declarations such as imports, types, and functions can be referenced in subsequent evals:

> use math
> math.random()
`float` 0.3650744641604983

The session imports what a script run by cyber imports: the standard modules, files and urls. The path of a file is relative to the working directory, since the session is not a file:

> use os
> os.cwd()!
`str` '/home/user/project'
> use util 'lib/util.cy'

The session runs in a VM of its own, made by cli.new_vm(). Its variables, globals and types are not those of the script that started the REPL, and a panic resets the session only.

> type Foo:
    | a int
    |
> f = Foo{a=123}
> f.a
`int` 123

A later input declares a method, a type function, a constant or a function template for a type of an earlier input. It works like one declared in the same source:

> fn (&Foo) twice() -> int:
    | return self.a * 2
    |
> fn Foo :: make() -> Foo:
    | return Foo{a=1}
    |
> f.twice() + Foo.make().twice()
`int` 248
  • A method with the same name and other parameter types is another overload. The methods of the earlier inputs stay.
  • A method with the signature of an earlier one is a compile error, like in one source: CompileError: `twice` has already been declared with the same function signature. A method is not replaced, because the code that was compiled before would keep calling the old body. To start over, declare the type again and then its methods. The new type hides the old one, and the values of the old type keep its methods.
  • A member that is declared for a template type (fn (&Box[]) get() -> T:) also reaches the instances that earlier inputs made.
  • @deinit, @copy, @clone and @send are declared with the type. The code of the earlier inputs destroys, copies and sends the values of the type without them: CompileError: Can not declare `@deinit` for `Foo` after the input that declares `Foo`. The code that the session compiled since then destroys, copies and sends a `Foo` without it. Declare the type again, together with `@deinit`. A script or a host puts the type and these methods in one source. The REPL submits a type block as one input, so a type with these methods can not be declared in the REPL.
  • An input that fails to compile leaves nothing in the type, so the method can be declared again.
  • An instance of a template keeps what it found when it was expanded. A template that asks meta.has_decl(T, 'twice') does not see a twice that is declared after its instance for the type was made.

Records, slices, maps and optionals are shown with their contents. Nesting stops after a few levels and long containers are cut short:

> f
`Foo` {a=123}
> []str{'a', 'b'}
`[]str` {'a', 'b'}
> Map[str, int]{a=1}
`Map[str, int]` {'a': 1}
> ?int(none)
`?int` none

.which compiles the expression against the session and does not run it. It shows the function that the outermost call picks out of the overloads: the first line of its declaration, the instance when it comes from a template, the number of overloads when there are several, where it is declared, and its doc comment. Without a call it describes the name at the end of the expression. A compile error is printed as the answer:

> fn largest(a %T, b T) -> T:
    | return if (a > b) a else b
    |
> .which largest(1.5, 2.5)
fn largest(a %T, b T) -> T
  as fn largest[float](float, float) -> float
  at eval:1:1
> xs := []int{3, 1, 2}
> .which xs.sort()
fn (&Slice[]) sort()
  one of 2 overloads
  at core:1636:1
  Sorts in ascending order with `<`. The element type needs a `<` operator.
> .which xs
xs []int

.bc prints every compiled function of a name: the overloads, and the instances of a template that calls have made. The name is the function name alone (len2) or with its type (Vec2.len2):

> fn sq(x int) -> int:
    | return x * x
    |
> .bc sq
fn sq(int) -> int  (eval)
3:25 .chk_stk: ret=1, frame=6
3:28 .imul: %0 = %5 * %5
3:32 .ret: 
3:33 .trap:

A script can ask the same of a cy.VM: vm.which(code) and vm.bytecode(name) return the text.

Format source. #

cyber fmt rewrites source files in one fixed style and prints the paths that changed. There are no options for the style.

cyber fmt main.cy            # Rewrite one file.
cyber fmt src examples       # Rewrite every `.cy` file under the directories.
cyber fmt --check src        # Write nothing. Print the paths that would change and exit with 1 if there are any.
cyber fmt --stdout main.cy   # Print the result instead of writing the file.
cat main.cy | cyber fmt      # Read stdin, write stdout.

The formatter changes whitespace only. It never joins or splits lines, and it never moves or rewrites a token or a comment:

-- Before.
use   math
nouns:=[]str{'World','mundo'}   -- Trailing comment.


for nouns |n|:
  print( 'Hello, %{n}!' )
  total+=n.len()*2

-- After.
use math
nouns := []str{'World', 'mundo'}   -- Trailing comment.

for nouns |n|:
    print('Hello, %{n}!')
    total += n.len() * 2
  • Blocks are indented by 4 spaces. Tabs and other widths are converted.
  • A line inside open brackets is indented 4 spaces from the line that opened the bracket. A line that starts with the closing bracket lines up with it. Other continuation lines, such as the right side of an operator, keep their indentation relative to the statement.
  • Binary operators, :=, ->, => and assignments have one space on each side. Unary operators have none after them. An operator inside a range bound is kept as written: a[i..i+n].
  • = of a literal field has one space on each side like an assignment: Vec2{x=1} becomes Vec2{x = 1}. = inside an attribute is kept as written: #[extern='puts'] stays.
  • There is no space inside brackets, none before , and :, and one after them.
  • Any other run of spaces becomes one space, so columns that were aligned by hand are not kept. The gap before a trailing comment is kept.
  • Trailing whitespace is removed, several blank lines become one, and the file ends with one new line.
  • The contents of strings, including multi-line strings and the expressions in a string template, are not touched.

A file with a syntax error is reported as path:line:col: error: message and left alone. Before anything is written, the result is parsed again and compared with the original syntax tree and comments. If they differ the file is left alone and an internal error is reported.

A directory search skips directories whose name starts with . (such as .git and .zig-cache), zig-out and node_modules, and it does not follow symbolic links. A path that is named on the command line is always formatted. A file or directory that can not be read or written is reported as path: error: Name, the other files are still formatted, and the exit code is 1.

A file is rewritten in place, it is not replaced by a new file. A symbolic link stays a link and its target is rewritten, hard links stay linked, the permission bits are kept, and a read-only file is reported as an error.

Hosts that embed libcyber call the same formatter with cl_vm_format. It returns CL_FORMAT_OK, CL_FORMAT_SYNTAX_ERROR (the source needs a fix, the message is line:col: message), CL_FORMAT_INTERNAL_ERROR (the formatter refused its own output, the source is fine and should be kept) or CL_FORMAT_NO_MEMORY.

Documentation. #

cyber doc prints this manual from the executable, so the text matches the cyber that prints it. It works offline and needs no files next to the executable:

cyber doc                 # Print the usage and the chapters with their section ids.
cyber doc optionals       # Print one section with its subsections.
cyber doc unwrap-or-panic
cyber doc --list          # Print every section id, indented by level.
cyber doc --for-agents    # Print a short guide for coding agents and the topic index.
cyber doc --api json      # Print the functions and types of the json module.

A section id is the anchor of the section on the docs site: the heading text in lower case, with spaces replaced by - and ., /, $, [, ] and # removed. A repeated heading gets -1, -2 and so on. The heading text also works (cyber doc 'Optionals.'). A part of an id works when only one section contains it. Otherwise the matching ids are listed and the exit code is 1.

cyber doc --for-agents prints docs/agent-guide.md of the source tree: the differences from Python, the common methods, the modules, examples, and the compile errors whose message does not say the fix. It ends with the chapters and their section ids. A project that is written in Cyber can point its agent instructions (AGENTS.md, CLAUDE.md) at this command instead of keeping a copy of the guide.

cyber doc --api prints the functions of a module, then its types with their methods (fn (&T) m(...)) and type functions (fn T :: f(...)), each with its signature and the first line of its doc. cyber doc --api lists the modules. The source is docs/api.json, which docs/gen-api-json.cy makes from the module sources. The file is in the source tree and in the Zig package, so a host that embeds Cyber can read it at build time, and every entry has a module field to filter by. The docs site has the same API as api.html.

Since doc is a command, a script file named doc without an extension is run as cyber ./doc.

JIT compiler. #

The JIT compiler is not supported. Passing -jit (or CL_JIT through the embedding API) fails with a compile error. Use the default bytecode VM.

The JIT was an experiment that stitched together pregenerated machine code targeting the same runtime stack slots used by the VM, a technique known as copy-and-patch. Its code generator did not keep up with the current IR and bytecode, and the code was removed.
