# `cyber fmt` 포매터 (2026-11-11)

## 배경

`cyber fmt`는 도움말에만 있었고 `main.zig`에서 `TODO: Embed src/tools/fmt.cy`로 panic했다(F-33). 그 파일은 fork에도
upstream에도 없다. upstream의 도구 관련 논의는 fubark/cyber#86(2024-03, tokenizer/parser를 Zig 패키지로 공개하자는 제안)
뿐이고 포매터 계획은 없다. upstream 마지막 커밋은 2025-12-21이다. 기다릴 대상이 없어 fork가 설계했다.

## 결정

- 구현 언어는 Zig다(`src/format.zig`). upstream이 암시한 "Cyber로 쓴 `fmt.cy`를 임베드"는 택하지 않았다. 포매터가 언어
  런타임과 `core.cy`에 의존하면 문법을 바꾸는 순간 포매터가 먼저 깨지고, VM 기동과 `cy.cy` 컴파일 비용이 매 실행에 붙는다.
  Cyber로 쓴 판은 언어 활용 예제로 `examples/fmt.cy`에 둔다(아래).
- 줄 너비에 맞춘 재배치는 하지 않는다. 줄바꿈은 작성자의 것이고, 줄을 합치거나 나누지 않는다. 옵션도 없다.
- 본체는 라이브러리, CLI는 껍데기다. `format.format(alloc, src, &diag)`는 tokenizer · parser · AST에만 의존하고 VM이
  필요 없다. `src/format_cli.zig`가 파일 입출력을, `cl_vm_format`이 C 호스트용 입구를 맡는다(VM은 할당자만 빌려준다).

## 구조: 토큰을 다시 내보내고, AST는 판단과 검증에만 쓴다

처음 계획은 AST를 순회해 출력하는 것이었다. 구현하면서 바꿨다. AST는 손실이 있고(빈 줄, 일부 문법 변형), 노드 120종의
출력 규칙을 모두 맞게 쓰지 못하면 토큰이 사라진다. 지금 구조는 다음과 같다.

1. 소스를 다시 토큰화해 토큰과 주석을 위치순 "atom" 목록으로 만든다. 문자열 템플릿(`'a %{x} b'`)은 여는 토큰부터 닫는
   토큰까지 atom 하나로 묶어 그대로 복사한다. 출력은 atom의 원문과 그 사이 공백뿐이라 토큰을 잃거나 순서를 바꿀 수 없다.
2. AST 순회(`walk`)는 세 가지만 기록한다.
   - 줄의 역할: 블록의 문장/멤버 줄(`child`, 블록을 연 줄 + 4칸), `else` · attribute처럼 같은 수준의 줄(`same`),
     문장의 이어지는 줄(`cont`). 블록을 연 줄은 그 블록을 가진 노드의 `pos()`가 있는 줄이다. 그래서 인자 안의 람다 본문은
     람다가 시작한 줄을 기준으로 들여쓴다.
   - 이항 연산자 위치(`binExpr.op_pos`), 단항 연산자 위치, `+=`의 연산자 위치.
   - 범위식 경계 안의 이항 연산자는 "쓴 대로 둠"으로 표시한다(`0..n - 1`은 범위가 더 강하게 묶이는 것처럼 읽힌다).
3. 순회는 comptime 리플렉션으로 일반화했다(`@typeInfo(NodeData(t)).@"struct".field_names`). 필드 타입이 노드 포인터 ·
   옵션 · 슬라이스면 자식으로 본다. 블록인 필드는 이름으로 고른다(`stmts`, `else_stmts`, `cases`, `fields`, `members`,
   `funcs`, `impls`). 새 노드 타입이 생겨도 이 규칙을 따르면 포매터를 고칠 필요가 없다. `case_stmt`만 union이라 따로 다룬다.
   이를 위해 `ast.NodeData`를 `pub`으로 열었다.
4. 이어지는 줄의 들여쓰기는 괄호 스택으로 정한다. 괄호 안이면 "그 괄호를 연 줄 + 4칸", 닫는 괄호로 시작하면 "연 줄과 같게".
   괄호 밖의 이어지는 줄(연산자 뒤 등)은 문장 기준 상대 들여쓰기를 유지한다.
5. 토큰 사이 공백은 `spacing` 한 함수에 있다. 기본은 "있던 공백은 한 칸, 없던 곳은 그대로"이고 그 위에 규칙을 얹는다.
   공백을 없앨 때는 두 토큰이 다른 토큰으로 붙지 않는지 본다(`- -x`가 주석 `--x`가 되면 안 된다). `[` 앞 공백은 피연산자
   뒤에서는 건드리지 않는다(tokenizer가 `a [1]`과 `a[1]`을 다른 토큰으로 낸다).
6. 검증: 결과를 다시 파싱해 원본과 AST(위치 필드 제외) · 주석 목록을 비교한다. 다르면 `VerifyError`로 실패하고 아무것도
   쓰지 않는다. 비교기도 같은 리플렉션으로 만든 일반 코드다.

## 스타일 규칙

`docs/docs.md`의 "Format source." 절이 사용자용 설명이다. 근거가 필요한 것만 적는다. 저장소 `.cy` 443개를 집계해 정했다.

- 괄호 안쪽 공백 없음: `{x`가 858곳, `{ x`가 21곳.
- 이항 연산자 양쪽 한 칸: `a + b` 540곳, `a+b` 29곳. `-`는 붙여 쓴 곳이 더 많았지만(211 대 117) 한 규칙으로 통일했다.
- 괄호 안의 `=`는 쓴 대로 둔다: `{x=1}` · `#[extern='x']`와 `{x = 1}`이 섞여 쓰이고 어느 쪽도 압도적이지 않다.
- 손으로 맞춘 열 정렬(`case .read       =>`, 필드 타입 열)은 한 칸으로 줄어든다. 정렬 알고리즘 없이 "한 가지 모양"을
  지키려면 이렇게 된다. 줄 끝 주석 앞의 간격만 예외로 쓴 대로 둔다(정렬된 주석 42곳, 한 칸 8곳).
- 이름 붙인 인자는 `name: value`다(`:` 앞 공백 없음, 뒤 한 칸).

## 같이 고친 것

- tokenizer: `!=` · `<=` · `>=` · `<<` · `>>` · `<>` 토큰의 끝 위치가 한 글자 짧았다(`pushToken`이 `advance`보다 먼저였다).
  파서는 이 토큰들의 끝 위치를 쓰지 않아 드러나지 않았다. 포매터가 원문을 잘라 쓰면서 `a ! 0`이 나와 검증이 잡았다.
- parser: `parseRightExpr2`의 왼쪽 재귀 루프가 두 번째 이후 연산자의 `op_pos`에 첫 연산자 위치를 넣었다
  (`i*N+N`의 `+`가 `*` 위치). 위치만 고쳤고 구문 트리 모양은 그대로다.

## 한계

- 구문 오류가 있는 파일은 포맷하지 않는다. 파서에 오류 복구가 없어 부분 포맷과 범위 포맷도 없다.
- 2칸 들여쓰기 파일에서 중첩 블록 뒤에 같은 문장이 이어지고 그 줄이 블록 본문과 같은 열이 되는 드문 경우는 한 단계 밀어
  피한다. 그래도 맞지 않으면 검증이 실패로 끝낸다.
- 열 정렬을 보존하거나 만들어 주지 않는다.
- Cyber에서 부르는 `cy.format`은 아직 없다. 에이전트 루프에서는 `cl_vm_format`을 쓴다.
- 저장소의 기존 `.cy` 파일은 다시 포맷하지 않았다. 297개가 바뀌므로 별도 커밋으로 결정한다.

## 코드 리뷰 뒤 수정(2026-11-11, PR #5)

- 쓰기 방식: 임시 파일을 만들어 rename하던 것을 제자리 쓰기(`Dir.writeFile`)로 바꿨다. rename은 symlink를 일반 파일로
  바꾸고 hard link를 끊고 읽기 전용 파일도 덮어썼다. 제자리 쓰기는 파일의 정체를 유지한다. 잃는 것은 원자성이다: 쓰는 도중
  실패하면 파일이 잘릴 수 있다. 결과가 이미 메모리에 있어 쓰기는 한 번이고, 버전 관리 아래의 소스에 쓰는 도구라 이쪽을 골랐다
  (gofmt · rustfmt도 제자리에 쓴다).
- 디렉터리 탐색: `Dir.walk` 대신 직접 재귀한다. 읽을 수 없는 디렉터리 하나가 전체를 중단시키지 않고 `path: error: Name`으로
  센다. `.`으로 시작하는 디렉터리 · `zig-out` · `node_modules`에는 들어가지 않는다. 명령줄에 직접 준 경로는 항상 처리한다.
  symlink는 전과 같이 따라가지 않는다.
- shebang 줄 뒤의 빈 줄을 유지한다(prefix가 줄 끝 개행을 가져가 첫 atom의 빈 줄 판정이 항상 거짓이었다). 선행 빈 줄 뒤의
  `#!` 줄은 빈 줄을 다 지우면 shebang이 되므로 개행 하나를 남긴다.
- dot literal(`.name`)은 `.`과 이름이 붙어 있어야 한다. 파서가 `.`부터 이름 끝까지를 literal의 원문으로 잡아 공백이 값에
  들어갔고, 포매터가 공백을 줄이면 구문 트리가 달라져 검증이 거부했다. sema도 그런 literal을 어떤 case와도 맞추지 못했으므로
  파서에서 구문 오류로 만들었다.
- 검증기 · walk의 `.other` 필드: 노드에 닿는 타입(`holdsNodes`)인데 일반 순회가 모르는 모양이면 `checkOtherField`가 컴파일을
  실패시킨다. `case_stmt`의 union 둘은 일반 순회 전에 손으로 처리하고 반환한다. 블록 필드의 이름 목록(`stmts` 등)에 없는 새
  블록 필드는 여전히 자동으로 잡지 못한다. 그런 필드는 이어지는 줄로 취급되고 검증은 통과한다(들여쓰기만 덜 맞는다).
- `cl_vm_format`의 반환을 `bool`에서 `CLFormatResult`로 바꿨다. 구문 오류(소스를 고칠 것)와 검증 실패(소스는 그대로 둘 것)를
  호스트가 구분해야 한다. 릴리스 전의 API라 호환성 문제는 없다.
- 같이 고친 파서 · tokenizer 버그(포매터가 드러냈거나 새로 노출한 것): `parseRightExpr2`의 우선순위(`a == 2 * 3 + 4 * 5`),
  소스 끝에서의 `peek` 범위 밖 읽기, 지수 첫 글자 검사(`1e_5`), 8진 숫자 판정(`0o7_8`).

## 내장 도구의 기준

컴파일러 프런트엔드가 필요하고 버전이 함께 잠겨야 하는 도구만 CLI에 넣는다. fmt가 여기 해당한다. LSP · 패키지 관리자는
라이브러리 위의 별도 프로그램으로 둔다. 동작하지 않는 명령은 도움말에 두지 않는다(`-jit`과 같은 원칙).

## `examples/fmt.cy`

Cyber로 쓴 토큰 기반 포매터다(758줄). AST 없이 같은 규칙을 휴리스틱으로 적용한다(단항/이항은 앞 토큰으로, 블록은 원래
들여쓰기로 판단). 순서는 tokenize → 연산자 분류 → 들여쓰기 → 출력 → 검증(출력을 다시 토큰화해 토큰 원문이 같은지 본다)이고,
먼저 `cy.parse`로 구문 오류를 거른다. 실제로 쓸 도구는 `cyber fmt`이고, 이 파일은 언어 활용 예제다.

- 확인(2026-11-11, ReleaseFast): `cyber fmt`가 포맷하는 저장소 `.cy` 417개 모두에서 출력이 바이트 단위로 같다. 파일 자신도
  `cyber fmt --check`에서 바뀌지 않는다. 작성 중에는 탭 · 3칸 들여쓰기 · CRLF · 붙여 쓴 연산자로 망가뜨린 사본 두 벌로도
  대조했고 한 파일이 달랐다(아래 1번).
- AST가 없어 다른 곳: (1) 4칸이 아닌 들여쓰기에서 이어지는 줄에 놓인 한 줄 블록 본문(`case 10,` / `   123: res = 2`),
  (2) 비대칭으로 쓴 이항 `*` · `%` · `&&`(`a *b`는 `a *T`처럼 보여 그대로 둔다), (3) 선언의 붙은 `*`(`var p*int`), (4) `if (c) - a
  else a`의 단항/이항, (5) 연산자 · 쉼표로 끝나지 않은 줄 뒤의 더 깊은 줄을 블록으로 본다.
- 속도: `core.cy`(4649줄)에 Debug 빌드로 약 3.3초(`cyber fmt`는 0.1초). 스크립트와 `cy` 모듈 컴파일이 0.8초다.

### 예제를 쓰면서 드러난 언어 · 라이브러리 문제

고치지 않았고 예제는 우회했다. 앞의 둘은 다시 실행해 확인했다. 앞의 셋은 2026-11-12에 고쳤다(findings 표 F-96). 뒤의 둘은 그대로다.

- `fn main() -> !void`가 돌려준 오류가 버려진다. `os.read_file_str('nofile')!`로 끝나도 아무것도 출력하지 않고 종료 코드 0이다.
- `str.trimRight(delims)`가 구분자마다 한 번씩만 훑는다. `'abc  \r'.trimRight({' ', '\r', '\t'})`가 `'abc  '`를 돌려준다.
- `[]str.join`이 `res += sep + …`로 이어 붙여 길이에 대해 제곱 시간이다(10만 개에 6초). 예제는 `[]byte`에 모아 한 번에 `str`로 바꾼다.
- `cy.parse`는 구문 오류에서 오류 값을 돌려주지 않고 panic한다. 예제는 잡을 수 없어 스택 트레이스와 함께 종료 코드 1로 끝난다.
- Debug 빌드에서 `os.exit()`가 `error(SafeAllocator): leaked …`를 출력한다.
