# 이니셜라이저의 키 구분자는 `=`

2026-11-18 정리. 문법 자체는 upstream에서 물려받은 것이고, 이 문서는 그 근거를 기록한다(새 구현 없음).

## 배경

맵 리터럴은 `Map[str, int]{a=1}`처럼 `key=value`로 쓴다. JSON · Python · JS에 익숙한 사람과 모델은 `{'app': 7}`을 쓰고,
tars-agent M0 스파이크(2026-11-13)에서 실제로 걸렸다(F-122, `docs/study/10-findings-register.md`). 그때는 오류 문구만 고쳤고,
왜 `:`가 아닌지는 어디에도 적혀 있지 않았다. 사용자가 이유를 물었다.

## 결정

`{...}` 이니셜라이저의 키와 값 사이는 `=`다. `key: value`는 받지 않고, 안내가 붙은 파스 오류를 낸다.

근거.

1. **이니셜라이저 하나가 세 가지를 만든다.** 구조체 `Point{x=1, y=2}`, 맵 `Map[str, int]{a=1}`, 목록 `[]int{1, 2}`.
   파서는 대상 타입을 모른다. `parseInitEntry`(`src/parser.zig`)는 `=`를 보면 `keyValue` 노드 하나를 만들 뿐이고,
   필드 대입인지 맵 엔트리인지는 sema가 대상 타입으로 정한다. 같은 노드이니 구분자도 하나다.
2. **구조체 쪽에서 보면 필드 대입이다.** `x=1`은 "필드 `x`에 1을 넣는다"는 뜻이다. C99 지정 초기화자(`.x = 1`),
   Zig(`.{ .x = 1 }`), Odin(`Point{x = 1}`)과 같은 계열이다. 맵은 같은 노드라서 따라간다.
3. **`:`는 이미 다른 뜻이 있다.**
   - 블록 시작: `if c:`, `for xs |x|:`, 한 줄 블록 `if true: print(1)`.
   - 이름 붙은 호출 인자: `parseCallArg`가 `ident :`를 `namedArg`로 읽는다. sema는 아직 다루지 않는다
     (docs.md "Named parameters" — Planned Feature).
   - `:=` 선언, `::`.

   `{a: 1}`을 받으면 `f(a: 1)`과 겉모양이 같고, "콜론은 블록 또는 이름표"라는 규칙이 깨진다.
4. **`=`는 식 위치에서 비어 있다.** 대입은 문장이지 식이 아니고, 동등 비교는 `==`다. 그래서 `{}` 안의 `=`는
   모호하지 않다. 대입이 식인 C · JS였다면 쓸 수 없는 선택이다.
5. **키 규칙은 Lua 테이블 생성자와 같다.** 맨 이름은 문자열 키(`{a=1}`의 키는 `'a'`), 계산 키는 감싼다.
   Lua는 `[k]=1`, Cyber는 `(k)=1`이다. `[`는 타입 인자와 인덱싱에 쓰이므로 괄호를 쓴다.
   허용하는 키 노드는 `isRecordKeyNodeType`: 이름, 작은따옴표 문자열, 정수 리터럴, `(expr)`.

~~~cy
p := Point{x=1, y=2}
var m Map[str, int] = {a=123, b=234}
k := 'name'
n := Map[str, int]{(k)=1, (k + '2')=2, 'my key'=3}
ids := Map[int, str]{1='one', (1 + 1)='two'}
~~~

## 택하지 않은 안

- **`:`로 바꾸기** (Rust · Swift · JS 계열). 리터럴을 "선언적 데이터"로 보는 쪽이다. 위 3번의 충돌이 생기고,
  구조체 초기화와 맵 초기화의 표기가 갈리거나 둘 다 `:`가 되어 이름 인자와 겹친다.
- **`=`와 `:` 둘 다 받기.** 익숙함 문제는 풀리지만 같은 뜻에 표기가 둘이 된다. `cyber fmt`가 한쪽으로 고쳐야 하고,
  `{a: b}`가 이름 인자 · 블록과 겹치는 문제는 그대로다. 대신 오류 문구로 고칠 방법을 알려 준다.

## 대가

- JSON · Python 습관과 다르다. 사람과 모델이 `key: value`를 쓴다. 파스 오류
  "Expected `=` between a key and a value. An initializer uses `key=value`, not `key: value`."로 메운다
  (0.4.11, F-122, 테스트 `src/test/syntax/init_colon_error.cy`).
- 맨 이름 키는 변수가 아니라 문자열이다. `k := 'x'; {k=1}`의 키는 `'k'`다. Lua · JS와 같은 함정이고, 변수 값을 키로 쓰려면
  `(k)=1`이다.
- 맵 리터럴은 대상 타입이 있어야 한다. `{a=1}` 단독은 컴파일 오류다(`syntax/init_infer_pairs_error.cy`).

## 확인하지 못한 것

upstream Cyber가 초기 버전에서 `{a: 123}`을 쓰다가 `=`로 바꿨다는 기억이 있지만, 이 저장소의 히스토리는 얕아
확인할 수 없다. 확인되면 이 절을 고친다.
