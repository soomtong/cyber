# tars-linux 내장 에이전트 요구사항 초안 검토 (Cyber 런타임 관점)

2026-11-01. 사용자가 tars-linux용으로 쓰고 있는 "내장 에이전트 시스템 요구사항" 초안을 이 fork의 실제 상태(0.4.2 + 2026-11-01 master)와
대조한 결과다. 초안은 아직 논의 중이며 여기 적은 것은 결정이 아니라 검토다. 추측은 넣지 않았고 소스에서 확인한 것만 적었다.

## 결론

- 초안의 §1.3(Cyber 소개)은 0.3 시절 기준이다. 파이버 키워드, 점진적 타입, Zig 세대, 보간 문법이 모두 지금과 다르다.
- 초안의 핵심 가정 "능력 호출 지점에서 파이버가 멈추고 호스트가 나중에 재개한다"는 현재 런타임에 없다. 이것이 가장 큰 간극이다.
- 초안이 "첫 작업"으로 둔 Zig 0.17 업그레이드, 그리고 실행 중단 · 연료 상한은 이 fork에서 이미 끝났다.
- 메모리 목표(인스턴스 유휴 5 MB)는 측정상 VM당 약 2 MB로 충족된다. 첫 VM만 약 7 MB다.

## 초안의 배경(§1.3)과 실제

| 초안 | 실제(소스 확인) |
|---|---|
| 마지막 릴리스 0.3, 활동 느림 | upstream은 2025-12-21 `c853fcc2`에서 멈춤. 이 fork가 0.4.1(2026-10-29) · 0.4.2(2026-10-31)를 릴리스 |
| 파이버 `coinit` · `coyield` · `coresume` | 2025-11-21 `b751ca6c`에서 삭제. 지금은 `#[generator]`(stackless, `yield`)와 `spawn` Thread + `Future`. 스택형 `Fiber`는 문서만 있음 |
| 점진적 타입 | `dyn` · `any` 삭제. 정적 타입 + 값 소유권(`move` · `&T` 빌림 · `^T` ARC) |
| 바이트코드 VM + JIT | JIT는 미완성 스텐실, `-Djit` 옵션, 기본 꺼짐. VM이 기본 |
| Zig 0.12~0.13 세대일 것 | 0.15.2였고 fork가 2026-10-26~29에 0.17로 올렸다(`docs/specs/2026-10-25-zig-0.17-upgrade-design.md`) |
| `$()` 보간 | `%{}` 보간 |
| FFI · cbindgen은 샌드박스 구멍 | `-Dffi=false` 빌드 옵션이 있고 libcyber는 FFI 기본 꺼짐(`435813c1`). FFI를 끄면 tcc도 링크되지 않는다(`build.zig`의 `if (opts.ffi)`) |
| `use`로 임의 모듈 로딩 | 라이브러리 기본 로더는 고정 표 7개(`core` `meta` `math` `cy` `c` `io` `test`)만 안다(`src/compiler.zig`의 `mods`). `os`는 CLI 전용. 파일 경로 import는 호스트 로더가 거부하면 불가 |
| Cyber 0.3 사이클 검출기 | 지금은 safe mode에서 스레드 종료 시 탐지 · 에러 보고. 인스턴스 폐기 시 힙을 통째로 버리는 경로(`single_run` 스윕)가 있다 |

남는 샌드박스 구멍은 `c` 모듈이다. 라이브러리 로더에 남아 있고 포인터 · libc 접근을 준다. 로더에서 거르는 옵션이 필요하다
(`project_embedding_agent_loop.md`에 미결로 있음).

## 핵심 가정: 호스트 경계에서 멈추고 재개하기 (§1.2 · §3.2 · §4.2)

현재 런타임에는 호스트 함수 안에서 실행을 멈추고 임의 시간 뒤 재개하는 수단이 없다. 세 가지 사실.

1. 제너레이터는 stackless다. `yield`는 `#[generator]` 함수 본문에서만 쓸 수 있고, 호스트 함수나 중첩 호출 안에서는 불가능하다.
2. `Future.await()`는 main 스레드에서 spin-wait로 블록한다(`src/vm.zig`의 `zAwait`). 비-main 스레드의 await는 `@panic("TODO")`이고,
   continuation 큐(`FutureValue.cont_head`)와 `cl_run_ready_tasks`는 주석 처리돼 있다.
3. 초안 §7의 첫 질문 "호스트 함수 안에서 coyield할 수 있는가"의 답은 "불가. 스크립트 레벨에서도 제너레이터 본문에서만"이다.

가능한 길 세 가지.

- A. 동기 호스트 함수 + VM당 OS 스레드. `#[bind]` 능력 함수가 정책 검사 · 승인 대기까지 블로킹하고 값을 돌려준다. 지금 그대로 되는
  방식이고 `examples/libcyber/host_tool.c`가 이 패턴이다. 취소는 다른 스레드에서 `cl_vm_interrupt`를 부르면 다음 체크포인트(루프
  back edge · 호출)에서 멈춘다. 단 호스트 함수 안에서 대기 중이면 호스트 함수가 같은 취소 플래그를 보고 스스로 돌아와야 한다.
  세션 수십 개 = OS 스레드 수십 개이고, 아래 메모리 측정상 가능하다. 초안의 "파이버가 멈춰 있을 뿐"을 "그 세션의 VM이 블록되어
  있을 뿐"으로 바꾸면 §3.2 불변식은 그대로 유지된다.
- B. 컴파일러가 능력 호출을 yield 지점으로 바꿔 스크립트 전체를 제너레이터로 돈다. stackless라 모델이 함수를 정의하고 그 안에서
  능력을 부르면 깨진다. 비현실적.
- C. 스택형 `Fiber` 또는 `RES_AWAIT` continuation 경로를 VM에 구현한다. upstream이 비워 둔 자리라 비용이 크지만 초안의 설계 의도와
  가장 맞는다. 출발점은 `project_coroutines.md`와 `zAwait`의 주석 처리된 코드.

권고: A로 §5.3의 2단계(호스트 50~100줄 증명)를 먼저 통과시키고, A의 한계(승인 대기 중 OS 스레드 점유, 호스트 함수 안 취소)가 실제로
문제인지 본 뒤 C를 결정한다. 초안 §4.2 "지원하지 않으면 VM을 수정한다"는 문장은 그대로 두되 "먼저 A로 증명"을 앞에 둔다.

## 자원 상한과 실패 복구 (§4.2)

- 실행 중단: `cl_vm_interrupt`(다른 스레드에서 호출 가능), 연료: `cl_vm_set_fuel`(체크포인트 수). 2026-11-01 `f21993e2`. 중단된 eval은
  패닉처럼 되감고 `CL_ERROR_INTERRUPT`를 돌려주며 VM은 재사용 가능하다. 시간 기준 타임아웃은 호스트 타이머가 interrupt를 부르는 식.
- 메모리 상한: 없다. 출력 크기 상한: printer 콜백을 호스트가 받으므로 호스트에서 자를 수 있다.
- spawn된 스레드가 중단 · 연료 소진으로 끝났을 때 main의 `await`가 깨어나는 경로는 작업 트리에서 진행 중(2026-11-01, 커밋 전).
- 패닉: `cl_vm_eval`이 `CL_ERROR_PANIC`을 돌려주고 VM은 살아 있다(`host_tool.c`가 이 복구를 보여 준다). 그러나 Zig 쪽 `@panic("TODO")`
  경로(비-main await 등)는 프로세스를 죽인다. 에이전트 런타임은 그런 경로에 닿는 기능을 막아야 한다.

## 메모리 (§2.1 목표 4)

`zig-out/lib/libcyber.a`(2026-11-01 14:06 빌드, 최적화 모드 미확인)에 C 호스트를 링크해 macOS에서 RSS를 잰 값이다. 스크립트는
1,000회 루프 하나.

| 시점 | RSS |
|---|---|
| 프로세스 시작 | 1.7 MB |
| VM 1개 init | 2.5 MB |
| 첫 eval 뒤 | 8.4 MB |
| VM 10개 init + eval | 24.7 MB |
| VM 20개 init + eval | 42.7 MB |
| 모두 deinit | 49.8 MB |

- VM 하나당 증가분은 약 1.8 ~ 2.0 MB. 첫 VM만 내장 모듈 컴파일로 약 6.7 MB. 초안의 "유휴 5 MB 이하"는 VM당 기준으로 충족한다.
- deinit 뒤 RSS가 줄지 않는다. allocator가 페이지를 보유하는 것으로 보이며, 인스턴스를 자주 만들고 버리는 풀에서는 재사용이 낫다.
- 측정 코드는 scratchpad에 있고 저장소에는 넣지 않았다. 필요하면 `examples/libcyber`에 넣는다.

## 언어 표면과 표준 라이브러리 (§4.3 · §4.4)

- 에러 모델: `!T` Result와 `error.Name` 값. 초안의 "실패는 예외가 아니라 값" 요구와 정확히 맞는다. 호스트 함수는 `cl_thread_ret_panic`으로
  패닉도 낼 수 있다.
- 없는 순수 라이브러리: JSON 파서 · 직렬화(CYON은 삭제됐고 `cy.parse`는 Cyber 소스 파서다), 정규식, 날짜 계산(`os.now`는 CLI 전용 모듈).
  초안이 요구하는 표준 라이브러리 중 셋을 새로 써야 한다. 문자열 · `Map` · `Slice` · `math`는 있다.
- 모델 적합성: 정적 타입과 소유권은 Python류보다 모델이 틀리기 쉽다. 다만 스크립트 수준에서 `:=`와 복사 가능한 타입(`int` · `str` · `[]T`)만
  쓰면 `move` · `&`를 거의 만나지 않는다. 스펙 문서 4,000토큰 안에 소유권 규칙을 넣지 말고 "복사 가능한 타입만 쓰는 부분집합"을 가르치는
  쪽이 현실적이다. 이것은 §4.4의 측정으로 확인할 일이다.
- Attributes(`#[bind]` 등) 문서가 비어 있어 스펙 생성기가 참고할 자료가 없다(`docs/history/type_system.md`).

## 구조 결정에 대한 의견 (§1.3 · §5)

- 포크를 또 만들지. 이 fork(soomtong/cyber)가 이미 Zig 0.17, 릴리스 CI, 임베딩 패턴, interrupt · fuel, 호스트 소유 규약을 가진다.
  별도 이름의 두 번째 포크를 만들면 같은 변경을 두 번 유지한다. 권고는 런타임은 이 저장소 하나, `agentd`는 tars-linux 쪽, 샌드박스는
  빌드 옵션(`-Dffi=false` · `-Djit=false`)과 로더 구성(허용 모듈 표)으로 프로파일을 나누는 것. 이름은 CLI 제품명과 라이브러리명을 따로
  둘 수 있다.
- Zig→Zig 링크: `42c5227e`(2024-09-21)가 lib 코드를 Zig에서 쓸 수 있게 분리했다. 지금 공개 API는 `export fn cl_*`(C ABI) 모양이다.
  Zig 모듈로 import는 가능하지만 API 표면이 C 스타일인 점은 그대로다. Zig 전용 표면을 따로 만들지는 결정 사항.
- 라이선스: Cyber MIT, mimalloc MIT, linenoise BSD. tcc는 LGPL이지만 `-Dffi=false`면 링크되지 않는다. 초안의 BSD 호환 조건은
  FFI를 끈 빌드에서만 성립한다. `docs/deps.md`에 이 조건을 적어야 한다.

## 초안 §7 열린 질문에 대한 답

- 호스트 함수 안에서 coyield 가능한가: 불가. 위 "핵심 가정" 참고.
- 인스턴스 격리 시 공유되는 전역: VM은 컴파일러 + 힙 + 내장 타입 표를 각자 가진다(`cl_vm_init`마다). 내장 타입 id는 VM별이다(`a27cc8ae`).
  정적 전역이 완전히 없는지는 이 검토에서 확인하지 않았다. 열린 질문으로 남긴다.
- 사이클 검출기 필요성: 인스턴스 폐기 시 힙을 통째로 버리는 쪽으로 충분하다. `single_run` 스윕이 그 경로이고, 단지 소멸자를 건너뛴다.
- 나머지(MCP 인증, 승인 UI 위치, 하위 에이전트)는 런타임과 무관하다.

## 초안에 반영을 권하는 수정

1. §1.3을 0.4.2 기준으로 다시 쓴다. 파이버 → 제너레이터 · Thread · Future, 점진적 타입 → 정적 타입 + 소유권, 0.3 → 0.4.2.
2. §4.1 "첫 작업 Zig 0.17"을 "완료, `docs/specs/2026-10-25-zig-0.17-upgrade-design.md` 참고"로 바꾸고, 첫 작업을 "호스트 경계 증명(A 방식)"으로 옮긴다.
3. §4.2에 `cl_vm_interrupt` · `cl_vm_set_fuel`을 적고, 남은 상한은 메모리임을 명시한다.
4. §4.3 표준 라이브러리 목록에서 JSON · 정규식 · 날짜가 "새로 쓸 것"임을 적는다.
5. §1.3 "버리는 것"에 `c` 모듈 필터를 추가하고, FFI를 끈 빌드가 라이선스 조건의 전제임을 적는다.
6. §7에 "비-main 스레드 await와 continuation 경로가 TODO"를 추가한다.
