# Cyber 0.4.6

릴리스일 2026-11-11. 태그 `0.4.6` → (태그 후 기록), 빌드 (태그 후 기록).

0.4.5 이후의 도구 보강이다. 도움말에만 있던 `cyber fmt`가 동작하고, 숫자 리터럴에 자릿수 구분자 `_`를 쓸 수 있고,
tree-sitter 문법이 현재 문법을 따라간다. 0.4.5에서 돌던 스크립트와 호스트 코드는 그대로 동작한다.

## 설치

```bash
curl -fsSL https://raw.githubusercontent.com/soomtong/cyber/master/install.sh | bash -s 0.4.6
cyber version   # Cyber 0.4.6
```

## 호환성

- 우선순위가 낮은 연산자 뒤에 `높음 중간 높음` 꼴이 오는 식의 값이 바뀐다. `26 == 2 * 3 + 4 * 5`는 0.4.5에서 `false`였다
  (`2 * 3 + 4 * 5`가 `((2 * 3) + 4) * 5`로 묶였다). 이제 `true`다. 이전 값이 틀렸다.
- `.`과 이름 사이에 공백이 있는 dot literal(`var x E = .  a`)은 구문 오류다. 0.4.5에서도 컴파일 오류였다
  (``Could not infer `E` enum case from `  a`.``).
- `1_000`처럼 숫자 바로 뒤에 `_`와 숫자가 이어지는 표기는 0.4.5에서 구문 오류였고 이제 숫자 하나로 읽힌다.

## 버그 수정

- tokenizer가 `!=` · `<=` · `>=` · `<<` · `>>` · `<>` 토큰의 끝 위치를 한 글자 짧게 기록했다. 파서는 이 값을 쓰지 않아 동작
  차이는 없었고, 토큰 원문을 잘라 쓰는 포매터에서 드러났다.
- `a + b * c * d`처럼 우선순위가 높은 연산자가 이어질 때 두 번째 이후 `binExpr`의 `op_pos`가 첫 연산자 위치였다.
- 같은 자리에서 이항 연산자의 우선순위가 틀리게 묶이던 것을 고쳤다. `parseRightExpr2`의 왼쪽 재귀가 두 번째 이후 연산자의 오른쪽
  항을 첫 연산자의 우선순위로 읽었다. `a == 2 * 3 + 4 * 5`의 오른쪽이 `((2 * 3) + 4) * 5 = 50`이 됐다. 낮은 연산자(`==` · `<` ·
  `and` 등) 뒤에 곱셈 항 둘을 `+` · `-`로 이은 식이 모두 해당한다. 낮은 연산자가 앞에 없는 `x := 2 * 3 + 4 * 5`는 원래 맞았다.
- 소스가 연산자 문자에서 끝나면(`x := a.`, `x <`, `1.`, 끝 개행 없는 편집 중 버퍼) tokenizer가 소스 밖을 읽었다. Debug · ReleaseSafe는
  `index out of bounds` panic, ReleaseFast는 검사 없는 읽기였다. 이제 구문 오류다.
- 지수가 `_`로 시작하는 `1e_5` · `1e-_5`가 float 토큰으로 읽혀 sema에서 `Parsed invalid character.`가 났다(지수 첫 글자 검사의
  `and`가 `or`여야 했다). `0o7_8`도 8진수로 읽혔다. 이제 구문 오류다.

## 언어와 표준 라이브러리

- `cyber fmt`가 동작한다(이전에는 `TODO` panic, F-33). 파일이나 디렉터리를 받아 제자리에서 다시 쓰고 바뀐 경로를 출력한다.
  `--check`는 쓰지 않고 바뀔 경로만 출력하며 있으면 종료 코드 1, `--stdout`은 결과를 표준 출력으로, 경로가 없거나 `-`면
  stdin → stdout이다. 공백만 바꾼다: 블록 4칸 들여쓰기, 이항 연산자 · `:=` · `->` 양쪽 한 칸, 괄호 안쪽 공백 제거, 줄 끝 공백 ·
  연속 빈 줄 정리. 줄을 합치거나 나누지 않고 옵션이 없다. 결과를 다시 파싱해 원본과 구문 트리 · 주석이 같을 때만 쓴다.
  디렉터리 탐색은 `.`으로 시작하는 디렉터리 · `zig-out` · `node_modules`에 들어가지 않고(명령줄에 직접 준 경로는 항상 처리),
  읽거나 쓸 수 없는 파일 · 디렉터리는 `path: error: Name`으로 세고 나머지를 계속 처리한다. 파일은 제자리에 쓴다: symlink는
  링크로 남고 대상이 바뀌며, hard link와 권한 비트가 유지되고, 읽기 전용 파일은 오류다. shebang 줄 뒤의 빈 줄은 유지된다.
  규칙은 `docs/docs.md`의 "Format source.", 설계는 `docs/decisions/project_fmt.md`.
- `examples/fmt.cy`: 같은 규칙을 Cyber로 구현한 예제.
- 숫자 리터럴의 자릿수 구분자 `_`: `100_000`, `0xff_ff`, `0b1111_0000`, `1_000u`, `1_000.000_5`. 선택 사항이고 값은 같다. 양쪽이
  숫자일 때만 구분자다(`1_`, `1__0`, `0x_ff`는 오류). tokenizer만 바뀌었고 값 변환은 원래 `_`를 건너뛰었다.

## 임베딩 API

- `cl_vm_format(vm, src, &out)`: `cyber fmt`와 같은 포매터. 파서만 돌고 VM 상태는 바뀌지 않는다. `CLFormatResult`를 돌려준다:
  `CL_FORMAT_OK`(`out`은 결과), `CL_FORMAT_SYNTAX_ERROR`(`out`은 `line:col: message`, 소스를 고쳐야 한다),
  `CL_FORMAT_INTERNAL_ERROR`(포매터가 자기 출력을 거부했다. 소스는 문제없으니 그대로 둔다), `CL_FORMAT_NO_MEMORY`(`out`은 null).
  `out`은 `cl_vm_freeb`로 해제한다.

## 에디터 지원

- `exts/tree-sitter`: `try … else |err|:` 캡처(이전 문법은 `else err:`로 되어 있어 오류 노드가 났다)와 숫자 구분자 `_`. 컴파일러가
  파싱하는 저장소 `.cy` 417개가 모두 오류 노드 없이 파싱된다. `exts/sublime`의 숫자 패턴도 `_`를 받는다.

## 알려진 문제

- `cyber fmt`는 손으로 맞춘 열 정렬을 한 칸으로 줄인다(줄 끝 주석 앞 간격은 유지). 구문 오류가 있는 파일은 포맷하지 않는다.
- Cyber에서 부르는 `cy.format`은 없다. 호스트는 `cl_vm_format`을 쓴다.
- 저장소의 기존 `.cy` 파일은 아직 `cyber fmt`로 다시 포맷하지 않았다.
- `zig build lib -Dtarget=wasm32-freestanding`이 `std.Io` 참조로 컴파일되지 않는다(0.4.5에서도 같다).
