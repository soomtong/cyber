# Cyber Zig 0.17 Upgrade — Design

접두사: ZU

Status: M1 · M2 · M3 커밋(`d64bcde` · `7e5db56` · `5735bed`), 0.4.1 릴리스(2026-10-29). 후속은 "남은 항목" 절.

참조: `/Users/dp/Repository/tars-linux`의 ZU 작업(`a4953c0` M0 · `8f0bcb7` M2 · `7204ebe` fmt · `41076fd` 닫기,
설계 `docs/specs/2026-10-03-tars-zig-upgrade-design.md`). 공식 릴리즈 노트
`https://ziglang.org/download/0.16.0/release-notes.html` · `https://ziglang.org/download/0.17.0/release-notes.html`.

## 한 줄 요약

Zig 0.15.2를 0.17.0으로 올린다. 참조 저장소는 0.16 → 0.17만 다뤘으므로, 0.15 → 0.16 구간(std.Io 전환)은
릴리즈 노트로 채운다. 0.16에서 한 번 멈춰 테스트를 초록으로 만든 뒤 0.17로 넘어간다.

## 착수 전에 아는 것

2026-10-25에 확인했다.

1. 저장소는 0.15.2 기준이다. `docs/build.md` · CI 세 workflow의 `ZIG_VERSION: 0.15.2`.
2. 호스트(macOS 27)에서 0.15.2는 build runner 자체가 링크되지 않는다(`_fork` · `_malloc` 등 undefined
   symbol). 0.16.0 · 0.17.0은 호스트에서 동작한다. 0.15.2 기준선은 Linux 컨테이너(debian, aarch64)에서 잰다.
3. 0.15.2 기준선(Linux 컨테이너, HEAD `c853fcc`)은 이미 빨갛다. `behavior_test`의 `Tests.`가
   `modules/os.cy:25`(`os.open_dir`)에서, `FFI.`가 `ffi/ffi.cy`에서 실패한다(`Tests passed: 164/269`).
   두 실패 모두 컨테이너 환경 탓으로 보고, 비교는 같은 환경의 0.16 결과와 한다.
4. 규모는 71k줄 · 90파일이다. 영향 패턴 수(착수 시점): `std.fs` 60 · `std.os`/`std.posix` 90 ·
   `std.io` 25 · `std.http` 20 · `.fields` 107 · `@bitCast` 194 · `builtin.os`/`cpu` 101.
5. cyberscript는 C API로 임베드되는 라이브러리이고, CLI도 VM을 별도 산출물(`cyber` lib)로 링크한다.
   `main`이 `Io` · 인자 · 환경 변수를 내려줄 경로가 없다.

## 결정

### 결정 1 — 0.16에서 한 번 멈춘다

0.15 → 0.17을 한 번에 넘지 않는다. 0.16에서 `zig build test`를 초록으로 만든 뒤 0.17로 간다. 0.17의
`@bitCast` 배열/벡터 의미 변화처럼 컴파일 오류 없이 깨지는 변경을 테스트 차이로 가르기 위해서다.

### 결정 2 — `Io`는 `stdx.io()` 하나에서 얻는다

`std.Io.Threaded.global_single_threaded.io()`를 돌려주는 프로세스 전역 접근자를 `src/stdx/stdx.zig`에
둔다. 0.15의 블로킹 syscall 동작과 같다. `Io.Mutex`/`Io.Condition`은 `builtin.single_threaded`가 아니면
실제 futex를 쓰므로 VM의 worker 스레드에서도 그대로 동작한다. 릴리즈 노트가 권하는 "Io를 인자로 받기"는
C API 경계 때문에 하지 않는다.

### 결정 3 — 환경 변수는 libc `getenv`로 읽는다

0.16은 환경 변수를 `main`에만 준다. Cyber는 임베드될 때도 HOME 등이 필요하다(cache 디렉터리). lib · cli
모두 libc를 링크하므로 `stdx.getEnvVarOwned`가 `std.c.getenv`를 감싼다. 오류 이름은
`std.process.getEnvVarOwned`와 같게 두어 호출부의 `catch`를 건드리지 않는다.

### 결정 4 — 인자는 `main`이 `os.process_args`에 넣는다

CLI `main`은 `std.process.Init.Minimal`을 받아 `src/std/os.zig`의 `process_args`에 넣는다. 테스트
러너는 이미 있던 `test_init` export 경로로 `Args` 포인터를 넘긴다. 임베더는 인자를 보지 못한다(null).

### 결정 5 — 사라진 std 타입은 같은 표면의 얇은 대체를 둔다

호출부가 많은 것만 대체를 둔다. `ArrayList.writer()`(18곳) → `stdx.ListWriter`, `std.time.Timer` →
`stdx.time.Timer`(`Io.Timestamp` 기반). 호출부가 적은 것(`fixedBufferStream` · `adaptToNewApi`)은
`std.Io.Writer.fixed` · `std.Io.Writer.Allocating`으로 바로 옮긴다.

### 결정 6 — `Value`는 `extern union`이 된다

NaN-tagging `Value`는 `packed union`이었고 포인터 필드와 크기가 다른 필드를 가졌다. 0.16은 둘 다
금지한다. `extern union`은 C union과 같은 배치(크기 8, 정렬 8, 모든 필드 offset 0)라 리틀 엔디언에서
기존 비트 배치가 같다. 0.17이 extern 타입의 `@bitCast`를 금지하므로 `Value`를 만드는 `@bitCast` 3곳은
`.val` 경유로 바꾼다.

### 결정 7 — 전체 `zig fmt`는 돌리지 않는다

참조는 0.17 `zig fmt`를 따로 commit했다(참조 M2-D). 이 저장소는 HEAD에서 이미 74파일이 `zig fmt`
기준과 다르다(zig fmt를 쓰지 않는 스타일). 전체 fmt는 업그레이드와 무관한 스타일 diff가 되므로,
fmt가 해 주는 의미 있는 업그레이드(`@intFromEnum` → `@backingInt`)만 골라 적용한다.

### 결정 8 — translate-c는 `b.addTranslateC`로 둔다

0.17은 `@cImport`를 없앴고 `b.addTranslateC`는 deprecated다. 참조는 translate-c 패키지로 갔지만,
이 저장소는 `build.zig.zon`이 없고 이미 `addTranslateC` 셋(`vm.h` · `libtcc.h` · `linenoise.h`)을 쓴다.
`@cImport` 셋(`cyber.h` · `mimalloc.h` · LLVM-C)도 같은 방식으로 옮긴다. 패키지 전환은 0.18 전에
따로 한다(남은 항목 1).

### 결정 9 — `DebugAllocator`는 `SafeAllocator`로 바꾸지 않는다

0.17에서 `DebugAllocator`는 deprecated다. 대체인 `SafeAllocator`는 메모리를 재사용하지 않으므로
(릴리즈 노트) Debug CLI에서 오래 도는 스크립트의 메모리 사용이 달라진다. 동작이 바뀌는 선택이라
이번에는 두고 남은 항목 2로 넘긴다.

## Milestone

- ZU-M1 — 0.15.2 → 0.16.0. 판정은 macOS `zig build test` · ReleaseSafe · `-Dffi=false`, CI 타깃 교차
  빌드, Linux 컨테이너 테스트(기준선과 비교).
- ZU-M2 — 0.16.0 → 0.17.0. 컴파일 오류와 런타임 실패를 고친다. CI `ZIG_VERSION` · `docs/build.md`.
- ZU-M3 — 0.17 deprecated 정리(결정 7의 fmt 업그레이드 포함). 0.18에서 사라질 이름을 지금 바꾼다.

## 실측 (M1)

### 실측 1 — 0.16이 드러낸 잠복 버그

0.16의 `ArrayList.pop`은 꺼낸 칸을 `undefined`(Debug에서 0xAA)로 덮는다. `bc_gen.genFuncBlock`은 함수의
proc를 push하기 전에 `enter_jit`를 내보내며 `pushOptionalDebugSym`으로 이미 pop된 `cur_proc`을 읽었다.
0.15에서는 옛 값이 남아 우연히 동작했다. `functions/jit_func.cy`가 `@intCast` 패닉으로 드러냈다.
`enter_jit`는 실패하지 않는 명령이라 바로 위 헤더 `nop32`처럼 디버그 심볼 없이 내보낸다.

### 실측 2 — `ZVM` padding의 macOS Debug 분기는 `Thread.Mutex` 크기 차이였다

0.15의 `std.Thread.Mutex`는 Debug에서 `DebugImpl`(`locking_thread: Thread.Id` + 락)이고, macOS의
`Thread.Id`는 u64라 16바이트였다. `vm.h`의 `padding[464]`(macOS + DEBUG)는 그 차이를 맞추던 분기다.
`std.Io.Mutex`는 모든 모드에서 4바이트라 non-wasm은 `padding[456]` 하나가 된다.

### 실측 3 — 0.16 판정

macOS `zig build test` · `-Doptimize=ReleaseSafe` 모두 `Tests passed: 269/269`. Linux 컨테이너는 0.15.2
기준선과 같은 결과다(같은 두 실패, `Build Summary` 같음). 교차 빌드는 x86_64-macos · x86_64-linux(cli · lib) ·
x86_64-windows-gnu(cli · lib · build-test) · wasm32-wasi(cli · build-test)가 선다.

`-Dffi=false`는 `modules/os.cy`에서 주소 0x0 세그폴트로 멈춘다. 0.15.2 기준선도 같은 자리에서 같은
세그폴트를 낸다(`os.get_env`가 libc를 FFI 바인딩으로 부르는데 ffi가 꺼져 null 함수 포인터가 된다).
업그레이드와 무관한 기존 문제다. CI의 `web-lib` step은 build.zig에 없다(기존부터 실패, `6db63e1`에서
matrix 항목을 뺐다).

### 실측 4 — 0.16에서 Windows는 kernel32 바인딩을 직접 선언한다

0.16은 `std.DynLib`의 Windows 지원을 없앴고, `std.os.windows.kernel32`에는 `CreateProcessW` 하나만
남았다(NtDll 이전 완료). Cyber가 쓰는 kernel32 함수(`LoadLibraryW` · `GetProcAddress` · `FreeLibrary` ·
`GetModuleHandleW` · `VirtualAlloc` · `VirtualFree` · 콘솔 코드 페이지)를 `src/win32.zig`에 선언하고,
`src/dynlib.zig`의 `DynLib`가 Windows에서 그것을 쓴다. 이 시점에는 교차 빌드만 확인했다. 실행은 뒤에 CI
`windows-2022` 러너에서 확인했다(남은 항목 6).

## 실측 (M2)

### 실측 5 — 0.17의 런타임 실패는 std 내부 배치에 기댄 코드였다

컴파일 오류를 다 고친 뒤 테스트가 둘 깨졌다.

1. `sym.zig`의 `ZArrayList`는 `std.ArrayListUnmanaged`의 배치(ptr · len · cap)를 extern struct로 흉내 내고
   포인터 캐스트로 바꿔 썼다. 0.17 `ArrayList`는 안전 모드에서 `pointer_stability: SafetyLock`(usize)을
   더 가져 구조체 밖 메모리를 락으로 읽었다(`assertUnlocked` 실패). extern struct 안에는 `ArrayList`
   크기 · 정렬의 바이트 저장소를 두고 `init()`에서 실제 `.empty`로 채운다. extern이 아닌 `TypeSym`은
   진짜 `ArrayList` 필드로 바꿨다.
2. 같은 필드 때문에 Zig `VM`(리스트 10개)과 `Heap`(1개)의 `c` offset이 커졌다(456 → 536, 112 → 120).
   `vm.h`가 `RT_SAFETY`에 따라 `ZIG_LIST_LOCK_SIZE`(= `sizeof(size_t)` 또는 0)를 padding에 더한다.

### 실측 6 — 0.17은 사용자 정의 build step과 테스트 러너 초기화를 바꿨다

- configurer/maker 분리로 `makeFn` 사용자 정의 step이 없어졌다. `zig build version`(CI가 버전 문자열을
  읽는다)은 버전을 출력하는 작은 host 프로그램을 Run step(`stdio = .inherit`)으로 돌린다.
- `std.testing.allocator`가 `SafeAllocator`가 되었고, 초기화는 테스트 러너의 몫이다. 사용자 정의
  `src/test_runner.zig`가 `allocator_instance` · `io_instance`를 직접 만든다.

### 실측 7 — 0.17 판정

macOS `zig build test` · ReleaseSafe 모두 `269/269`. Linux 컨테이너는 기준선과 같다. 매트릭스는 실측 3과
같은 타깃이 선다(release 빌드가 쓰는 mimalloc의 `@cImport`도 옮긴 뒤).

## 릴리즈 노트 항목별 적용 현황

참조(tars-linux)가 다루지 않은 0.15 → 0.16 구간과, 참조 저장소에 없던 0.17 항목을 포함한다.
"해당 없음"은 저장소에서 사용처를 검색해 0건인 항목이다.
